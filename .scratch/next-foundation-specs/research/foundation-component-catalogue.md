- **Forms' component-like parts** (Input Group, Help Text, Label, Fieldset) sit between "covered" and "not mentioned": Abide's spec *references* them as compatible markup (EFFORT/specs/abide.md:37,118,222,451) but no directive binds any of their classes. `EFFORT/issues/01-*.md` through `05-*.md` (the Foundation plugin inventories) never mention Input Group, Help Text, or Fieldset at all -- they inventory Abide's *validation* contract only, not the surrounding form-layout markup Abide's docs happen to reuse.
- **Checkbox/Radio**: the *validation-state* contract (aria-invalid, Space toggling, etc.) is thoroughly covered by Abide (EFFORT/specs/abide.md:98,207,291,307,320,336-337,441,453,460,469,490), but the *base* Foundation styling (spacing, label association, scss/forms/_checkbox.scss) is untouched by any spec -- one Sass file, two different coverage answers, split into separate rows above rather than decided one way.
- **Close Button** and **Title Bar/Menu Icon**: these are named by class in the docs but their *behaviour* is fully covered by existing shared utilities (Triggers for Close Button's `data-close`/`data-closable`; the `nfs-responsive-toggle` mixin's no-argument include for Title Bar/Menu Icon's hit-area fix, `EFFORT/building-blocks.md:135,251`). Only the bare *structural class* has no directive. None of the five Foundation inventories (`issues/01` to `05`) discusses either of these as a distinct entry -- they surface only inside the Reveal/Toggler/OffCanvas and ResponsiveToggle/OffCanvas inventories respectively, as markup the plugin's docs happen to show, never as their own catalogue rows. Flag this for the judge: is "the behaviour is covered by a shared utility" enough to call the component in scope, or does [Triage the out-of-scope Foundation components and variants](../issues/79-triage-out-of-scope-components-and-variants.md)'s ruling require a directive on the bare class too?
