# Spec: misuse warnings (later milestone)

Ticket: [Spec: misuse warnings (later milestone)](../issues/161-spec-misuse-warnings-later-milestone.md). Targets Angular 22.2, `@angular/cdk` 22.2, Storybook 10.6 with `@storybook/angular-vite`, Vitest 4.1.x, and Foundation for Sites 6.9.0. Planned and implemented in a later milestone of the implementing repository, by the user's ruling in [Decide: checks move to a later milestone](../issues/158-decide-checks-move-to-a-later-milestone.md). The design comes from the specs as committed at `53144f3` and from the `misuse` entries of the seven extraction manifests of [Task: extract the checks from the specs](../issues/159-task-extract-checks-from-specs.md) ([a](../research/checks-extraction-a.md), [b](../research/checks-extraction-b.md), [c](../research/checks-extraction-c.md), [d](../research/checks-extraction-d.md), [e](../research/checks-extraction-e.md), [f](../research/checks-extraction-f.md), [shared](../research/checks-extraction-shared.md)), which quote each check verbatim with its location, its tests, and its mentions. Decided upstream in building-blocks 1.4 (copied classes, insertion-timing attributes), 1.5 (ids), 1.6 (Motion values), 1.8 (Triggers), and 1.10 (the accessibility baseline, Names, Scroll regions); the architecture guide's P17 and P23; [ADR 0039](../adr/0039-directives-manage-every-foundation-class.md) (the class rule), [ADR 0022](../adr/0022-wcag-2-2-aa-enforcement.md) (WCAG 2.2 AA enforcement), and the ADRs that name one of these warnings: [ADR 0011](../adr/0011-button-listener-free-disabled-contract.md), [ADR 0013](../adr/0013-triggers-target-resolution.md), [ADR 0019](../adr/0019-sticky-native-range.md), [ADR 0038](../adr/0038-smooth-scroll-same-document-links.md), [ADR 0042](../adr/0042-menu-current-page-aria-current.md), and [ADR 0043](../adr/0043-menu-root-top-bar-right-section-token.md). The decision log, with every question this spec asked itself and its triage, is in the ticket answer.

Each component's checks keep the numbers their spec gave them, with gaps where a number belongs to another kind of check; "Accordion 7" is the Accordion spec's development check 7. Messages are quoted as the specs wrote them.

## Problem Statement

A developer copies Foundation's docs markup into an Angular template: `<li class="accordion-item is-active">`, `<button class="close-button">&times;</button>`, `<a class="button disabled" href="/checkout">`, `<a class="badge">`. Under the class rule (ADR 0039) the directives set every Foundation class themselves, so a copied class is stripped by a binding and the item renders closed, or it stays beside the typed input and styles the element until the two disagree. The close button has no accessible name, the disabled link still navigates, and the uncoloured badge on a link drops to 1.27:1 on hover and focus. The compiler sees none of it: every attribute is valid HTML, every class is a string, and axe reports only some of it, in the pages where axe runs.

The specs answered with each directive's own development warning about how the consumer used it: a copied Foundation class, a missing accessible name, a value the directive cannot use, a host element it does not work on, a missing Library mixin include that it can see in the computed style. The extraction manifests list 190 of them in 48 component specs (a few are one check that two specs quote), the Off-canvas and Orbit specs have one more each that they missed, and 23 passages of the shared documents state their rules.

The user then ruled that every check is specified but planned and implemented in a later milestone of the implementing repository. In the user's words, "all checks should be deferred to a later milestone because at the core of it, this is an issue Angular should correct, not 3rd-party Angular component libraries", and the first milestone should stay "simpler and smaller in scope". WCAG's conformance requirements bind the consumer's pages, not the library's diagnostics, and ATAG 2.0's checking criteria are for authoring tools, not component libraries; the library's own bar stays its components passing axe and WCAG 2.2 AA when used as documented, which its own stories prove. So in the first milestone every spec states each rule a warning enforced as documented usage ("give every close button an accessible name that says what it closes"), and a consumer who ignores it gets no warning and, where the rule is a WCAG one, fails WCAG on their own page.

The user also said why the specs hold so many kinds of check: "I want to analyze how each works in practice and evaluate trade-offs." The later milestone needs the misuse warnings exactly as the specs designed them, beside the forgotten-import checks, the family checks, the Runtime checks, and the build-time checks, so that it can build them, measure them, and weigh the kinds against each other; nothing of the design may be lost when the component specs are rewritten without checks.

## Solution

In the later milestone, each directive the specs gave misuse warnings gets them back, as this spec records them:

- A misuse warning is the directive's own development warning that reads only its host, its inputs, its content, or the page. It never reads another part of its family (a family check), the Selector manifest or a peer's missing instance (a forgotten-import check), or a Variant property (a Runtime check).
- Every warning runs in development builds only, behind an inline `ngDevMode` guard, in a client render callback or at the call it is about; it reports once through `console.warn`, has no switch, and leaves nothing in a production bundle. Two checks throw instead of warning, at construction, as their specs decided.
- The mechanisms several directives share are written once (Shared mechanisms S1 to S12): the copied-class read through `HostAttributeToken('class')`, the static insertion-timing attribute, names read as accessible-name computation reads them, the Scroll region check, the named navigation landmark, the Motion value that starts no animation, the missing include seen in the computed style, the Zero-breakpoint names, deep links with generated ids, link hosts, conflicting inputs, and the rule for staying silent where a forgotten import is the cause.
- Each component's checks follow, in the order of the component specs, each with its trigger, its message, where and how often it runs, what it reads, and its tests.
- The last section of Further Notes lists, per component spec, what the later milestone adds back to that spec when it lands: the checks, their tests, and the sentences that name them, beside the documented-usage rule the first-milestone spec already states.

## Implementation Decisions

### What a misuse warning is

The ruling's definition: a directive's own development warning that reads only its host, its inputs, its content, or the page, for example a copied Foundation class, a missing accessible name, or a value it cannot use. "The page" includes an ancestor's element name, classes, attributes, and computed style, `location.hash`, the document's `scroll-padding`, the elements an id names, and the computed style that shows whether Foundation's CSS or a Library mixin is in the stylesheet. A check that throws a development error for such a misuse (the Interchange's `<img>` host, the Breakpoint service's invalid map) is a misuse warning too.

The five kinds, by what each check reads (the manifests classified each check once, in the order forgotten-import, family, misuse, Runtime, build-time):

| Kind | Reads | Spec |
| --- | --- | --- |
| Forgotten-import checks | An element that carries a library directive's attribute with no instance of it, through the Selector manifest and the host record | [Re-run: forgotten-import checks spec for the later milestone](../issues/164-rerun-forgotten-import-checks-later-milestone.md) |
| Family checks | Another part of the directive's family: its parent, a child, or a peer, found by registration, by DI, or by a DOM-only placement or order check | [Spec: family checks (later milestone)](../issues/160-spec-family-checks-later-milestone.md) |
| Misuse warnings | Only the directive's host, its inputs, its content, or the page | This spec |
| Runtime checks | The Variant properties and Breakpoint properties of the compiled CSS (ADR 0040) | [Spec: Runtime checks (later milestone)](../issues/162-spec-runtime-checks-later-milestone.md) |
| Build-time checks | The consumer's Sass settings at compile time, and the Variant declaration tooling's check mode | [Spec: build-time checks (later milestone)](../issues/163-spec-build-time-checks-later-milestone.md) |

A check that one spec quotes and another spec owns is held here once, from its owner: the Positioner's three warnings (the Anchored pane spec, quoted by the Dropdown and Tooltip specs), the Nested menu's checks (quoted by the Accordion Menu, Drilldown, and Dropdown Menu specs), the Menu's copied-class check (applied to the three menu roots it is hosted on), the Breakpoint service's unknown-name warning (quoted by the Equalizer's `equalizeOn`, the Responsive Toggle's `hideFor`, and the Sticky's `stickyOn`), and the others D7 under Further Notes lists. The boundary cases this spec decided are D2 to D7.

### The first milestone and this spec

Nothing in the first milestone depends on a misuse warning. The re-runs of the component specs ([Re-run: specs without checks, group a](../issues/165-rerun-specs-without-checks-group-a.md) to [group f](../issues/170-rerun-specs-without-checks-group-f.md)) remove every check, its messages, and its tests, and state the rule it enforced as documented usage in the spec's API text, its usage section, and the JSDoc it asks for. A copied class there is stripped or keeps styling exactly as with the warning; the element simply gets no report. What the specs keep is the behaviour the warnings describe: the stripping bindings, the `false` answers for unknown names, the clamped `headingLevel`, the phase that completes at once when no animation starts.

When a warning lands, it comes back beside its documented-usage sentence, which stays: the sentence is the rule, the warning reports its breach. The closing section of Further Notes lists what comes back to each spec.

### The common contract

These rules hold for every warning unless its entry below says otherwise.

1. Development only, with an inline guard. Every check, and every field initialiser that reads for one, sits behind `typeof ngDevMode === 'undefined' || ngDevMode` written at its own site. A guard hoisted into a module constant (`const dev = typeof ngDevMode === 'undefined' || !!ngDevMode`) kept 4336 B of check code and every message in a production bundle, measured for the in-family checks by [Prototype: detecting a forgotten attribute directive import](../issues/145-prototype-missing-directive-import-checks.md) ([research/missing-directive-import-peer.md](../research/missing-directive-import-peer.md)), so no check hoists it. A production build carries none of the checks' code or messages.
2. When it runs. A check that reads the DOM runs in a client render callback, `afterNextRender`, an `afterRenderEffect` read phase, or a self-destroying `afterEveryRender`, which Angular skips on the server; a read that must happen before a binding strips a class (`HostAttributeToken`) is a DI read at construction, safe on the server, whose warning waits for the client callback. A check about a call or an event reports at that call or event (a method called with the wrong option, a write of an unknown id, a click on a link, a `focusin`), and the two throws happen at construction, on the server too.
3. Once. Each warning fires once per instance, unless its entry names another unit: once per offending class (the Tooltip's checks 6 and 7), per element (the Orbit's check 7), per link (the Smooth Scroll's checks), per distinct string (the Breakpoint service's unknown names, the Interchange's unknown queries), per value (the Media Object's check 2), or per realm (the Float Grid's check 3). A check marked "on every run" re-evaluates on every run of its read phase and still reports once.
4. Output. A warning is one `console.warn` with its entry's message. Most messages start with the directive's attribute name (`nfsBadge: ...`); each keeps the text its spec gave it.
5. No switch. Misuse warnings are development warnings in the P23 sense: every report is a real misuse, so they have no opt-out and no production form. With `provideNfsProductionRuntimeChecks` a production build runs the Runtime checks the consumer opted in to and none of these.
6. One read phase with the Runtime checks. A directive with a Variant check handle (ADR 0040) runs its warnings in the same `afterRenderEffect` read phase as its Runtime check, which it creates when `ngDevMode` is on or the handle is not `null`; the warnings run only while `ngDevMode` is on (the Badge, Flex Grid, Flexbox Utilities, Float Grid, Label, Progress Bar, Prototyping Utilities, Typography Helpers, Visibility Classes, and XY Grid entries). Until the Runtime checks land, the phase exists under `ngDevMode` alone; the Runtime checks spec owns the handle.
7. The checks write nothing. No check writes the DOM, a class, an attribute, or a signal that rendering reads; the stripping and the removals the entries mention (a copied class stripped by a binding, Magellan's marker write, the Off-canvas Scroll lock's removal of a stray `body` class) are the directives' own behaviour, which the first milestone keeps.
8. Independent of the other kinds, with one exception. The misuse warnings can land before or after any other kind. Where a warning stays silent because a forgotten import is the cause (S12), it reads only the attribute and the Structural class its entry names, except the Triggers' check 1, which reads the forgotten-import checks' shared verdict and so lands with those checks or after them.

### Shared mechanisms

Each mechanism is said once here; each component entry that uses it names it (S1 to S12) and gives only what its own spec adds.

#### S1. A copied Foundation or library class

The rule (building-blocks 1.4, the initial-state rule; P23; ADR 0039): initial state and Variants are bound, never read from a class, and a Foundation class copied from Foundation's markup is reported in development, naming what to bind. The directive reads its host's static `class` with `inject(new HostAttributeToken('class'), {optional: true})` in a field initialiser that runs only when `ngDevMode` is on, because after the first render a stripped token no longer shows; the warning waits for the first client render callback. The value read is the template's static classes merged with the static host classes of the element's directives (the Tooltip entry). Tokens are split on whitespace and compared whole, so `is-activated`, `my-is-active`, `top-bar`, and `righty` match nothing; a templated name (`medium-6`, `<word>-order-<n>`, `stack-for-<zero>`) is built from the Breakpoint map's names (`nfsBreakpointsToken`) where the family is responsive. The message names each class with the input to bind, in the form `class="small alert" is set by nfsButton: bind size="small" and color="alert" instead`, or with the directive to write instead, or says to remove it.

Five forms, by what the copy does:

1. A class the directive binds from state or an input: its binding strips the copy on server and client, because Angular's styling resolution consults a static class only when every binding for it is `undefined`; reported (`is-active`, `is-open`, `disabled`, `vertical`, a position class).
2. A Variant class of an open family set through a `[class]` list: the list sets only its own classes, so the copy is not stripped and keeps styling until removed; reported. A name the consumer declared (a custom palette entry) is not known without the Variant properties and is left to the Runtime checks' Variant check (the Button spec's D22 rule).
3. A Foundation class that no directive binds but that Foundation's CSS or JavaScript reads on that element: reported, naming what replaces it (the Tooltip's legacy position classes, the Slider Handle's `slider-handle`, the Pagination's and Breadcrumbs' `current` and `disabled`, the Menu's leaf `is-active`, the Dropdown pane's `is-opening`, the Responsive Embed's `flex-video`, the Visibility Classes' `show-for-ie`).
4. A class on a component whose host binds no class: not stripped, it styles the host itself; reported (the Responsive Accordion Tabs' check 7).
5. A State class the directive writes with `Renderer2` on an element no library directive hosts: the check reads the element's class before the write that removes the copy (Magellan's marker, D18; the Off-canvas Scroll lock's `body` class, check 10).

Not reported: a redundant copy of the directive's own static host class, which merges (`class="accordion"`, `class="badge"`); the consumer's own classes; a plugin root's class that its directive binds `true` whenever the root stands alone and that a Responsive Menu binds per Menu mode, whose copy changes nothing (the Responsive Menu's D22, the Accordion Menu's D24, the Dropdown Menu's D22); a State class that comes only from a measurement, stripped and not reported (the Sticky's D16); and any class on a directive that owns none (the Equalizer, the Card's D10).

Used by: Abide (D20), Accordion 7, Badge 2, Breadcrumbs 2 and 9, Button (d), Button Group 5, Callout, Drilldown 7, Dropdown 7, Flex Grid 1, Flexbox Utilities 1, Float Classes 1, Float Grid 1, Label 2, Magellan (D18), Media Object 1, Menu 1 and 2, Nested menu 1, Off-canvas 1 and 10, Orbit 7, Pagination 2, Progress Bar 2 and `NfsProgressElement`, Prototyping Utilities 1, Responsive Accordion Tabs 7, Responsive Embed 3, Responsive Toggle 1, Reveal 8, Slider 5, Switch (`NfsSwitch`), Table 4, Tabs (copied-class check), Toggler 1, Tooltip 6, Top Bar 5, Typography Helpers 1, Visibility Classes 1, XY Grid 1. The Toggler's check 3 and the Tooltip's check 7 read a class name given as an input value (ADR 0039's rule for class names in values), not the host's static class.

Shared code: the token splitter and whole-token matcher, one library-internal helper; each directive keeps its own table of names and inputs.

#### S2. A static insertion-timing attribute

The rule (building-blocks 1.4, input kind 3, `insertion`): the browser acts on `autofocus` when the element is parsed or inserted, and HTML attribute names are case-insensitive, so a static `autoFocus` attribute is HTML's global `autofocus`. Every such input binds `'[attr.autofocus]': 'null'`, which keeps it out of the server HTML, but in client rendering Angular sets static attributes before it inserts the element, and the browser takes the element as an autofocus candidate however soon the binding removes the attribute (measured in three engines). Where the host can take focus when it is inserted, the directive reads the static attribute with `inject(new HostAttributeToken('autoFocus'), {optional: true})` in a development-only field initialiser and warns, naming the bound form (`[autoFocus]="true"`) and the Defaults token.

Used by: Dropdown 6, Reveal 9, Tabs (static `autoFocus` on the strip).

#### S3. Names and text read as accessible-name computation reads them

The rule (building-blocks 1.10, Names): a check that reads a name or text from content (the host's, a referenced element's, a `label`'s, a `legend`'s, a `caption`'s) reads it as accessible-name computation does: text outside `aria-hidden="true"` subtrees, visually hidden text included, and an embedded image's text alternative, the non-blank `alt` of an `img` or the non-blank `aria-label` of an element with `role="img"`, so it never reports a name or text that assistive technology has. Each entry gives its sources in accessible-name order, typically the text of the elements `aria-labelledby` references (an id that names no element gives nothing), a non-blank `aria-label` (a blank one counts as none), the content, the element's `labels`, or its `caption` where the role takes its name from them, then a non-blank `title`. A role named by its author only (`progressbar`, `region`) does not count its content. A check whose name must be in the server HTML reads at the first render; a name bound only after it warns (documented in the Close Button entry). A symbol-only name is a name with no letter and no digit.

Used by: Badge 1, Close Button 1 and 2, Dropdown 1, Forms (`NfsInputGroupField`), Label 1, Nested menu 2, Off-canvas 4 (the modal panel's name), Orbit 4 and 5, Progress Bar 1 and `NfsProgressElement`, Prototyping Utilities 2 and Typography Helpers 2 (a focusable region's name), Responsive Accordion Tabs 1, Responsive Embed 1, Reveal 1, Slider 2, Switch 1 and 2, Table 1 and `NfsTableScroll`, Tabs (the strip's name), Thumbnail 1 and 2, Tooltip 4, Top Bar 1 and 2, XY Grid 3. The Drilldown's check 3 (a back item's button name) is the family-checks spec's.

Shared code: one library-internal name reader; each entry keeps its own sources and message.

#### S4. A Scroll region that a keyboard cannot reach, or that has no name

The rule (building-blocks 1.10, Scroll regions and the `.code-block` line): a region that scrolls holds focusable content or carries `tabindex="0"`, `role="region"`, and a name (2.1.1, 4.1.2). Reachability: for each axis whose computed `overflow-x` or `overflow-y` is `auto` or `scroll` (the Prototyping Utilities read `scroll` or `auto`) and whose scroll size exceeds its client size, the host has no `tabindex` attribute and no focusable descendant (`a[href]`, `button`, `input`, `select`, `textarea`, `[tabindex]` other than `-1`, `[contenteditable]`, none disabled). A host with `tabindex` of 0 or more and no non-blank `aria-label` or `aria-labelledby` gets the name message instead. A component's own Scroll region (the XY Grid's cell blocks, the Table's wrapper) binds `tabindex="0"` and `role="region"` itself, so only its name is checked.

Used by: Prototyping Utilities 2 (`NfsPrototypeOverflow`), Typography Helpers 2 (`nfsCodeBlock`, which "may share one library-internal helper with `NfsPrototypeOverflow`"), XY Grid 3 (a cell block's name), Table (`NfsTableScroll`'s name).

#### S5. A named navigation landmark

The Pagination's check 1 and the Breadcrumbs' check 1 share one condition and one wording: the host has no `nav` or `[role=navigation]` ancestor, or that ancestor has neither `aria-label` nor `aria-labelledby`; each runs in its component's self-destroying `afterEveryRender` (the Breadcrumbs' D10, the Pagination's D11). Magellan's landmark check asks only that the host be inside, or itself be, a `nav` or `role="navigation"` element; the name its ARIA table asks for when the page has another `nav` is left to axe's `landmark-unique`.

Used by: Pagination 1, Breadcrumbs 1, Magellan (landmark).

#### S6. A Motion value that starts no animation

The rule (building-blocks 1.6, rule 4): a Motion input takes a Motion name or the consumer's own keyframe class in the dot form, and must start a keyframe animation. The check runs in the render phase that measures a phase's animation (a `read` or `earlyRead` phase, after the Motion class is bound), not in the first render callback, and reads the host's computed `animation-name`. Three cases, each once per instance: a non-empty value, or a half of a pair, whose classes start no CSS animation when their phase begins (a Motion name without the `nfs-motion` include, a consumer class without `@keyframes`, a Motion UI transition class given in the dot form): `<input>="<value>" started no animation: include nfs-motion, or give your own class @keyframes` (the Reveal's reads "animationIn="spin-in" started no animation: include nfs-motion, or give your own class @keyframes"), the phase completing at once as before; a dot-form class that starts with `nfs-`: `write the library's Motion name without its prefix: <input>="fade-in"`; and, for the `NfsMotionPair` inputs, a value that does not split into one entering and one leaving value (three or more tokens, or a leaving value before an entering one), which the type admits only through a value that starts with a dot (`'.a .b .c'`, `'.a fade-in'`): "animate takes one entering and one leaving value". The mapping itself (`nfsMotionClasses`, `nfsMotionPairClasses`) is first-milestone code; the check adds only the computed-style read and the messages.

Used by: Reveal 3 (`animationIn`, `animationOut`), Dropdown 5, Toggler 4, Responsive Toggle 4 (each `animate`).

#### S7. A missing include or stylesheet, seen in the computed style

P23 lists "a missing Library mixin include" among the misuses a directive reports. Where a family has no Variant property, or its Variant properties prove nothing about the CSS it needs, the directive reads one computed value of its own host or content in a client render callback and warns naming the include or the setting; none of these reads a Variant property, so none is a Runtime check.

Used by: Accordion 6 (an expanded content with computed `display: none`), Breadcrumbs 6 (the first link computes `display: inline`; "check 6 covers the missing include instead"), Pagination 5 (the current link's background is fully transparent; the same), Flex Grid 2 (a row that is not a flex row), Float Grid 3 (a row's `::after` `content` is `none`, once per realm; the Float Grid's D10 rejects a `strictVariantProperties` report), Responsive Toggle 5 (a bar or menu whose computed `display` is not `none` where its Visibility class should hide it; "No Runtime check is requested"), Table 2 (a stacked table's `thead` or `tfoot` computes `display: none`), Top Bar 4 (a menu icon box under 24 by 24 CSS px), and the Positioner's check (c) (a placed element whose computed `position` is not `absolute`).

#### S8. A breakpoint name Foundation generates no class for

Foundation generates no class for the Zero breakpoint in several families, so a value naming it sets nothing. The directive reads the Zero breakpoint from `nfsBreakpointsToken` (`nfsBreakpointForWidth(map, 0)`), which it injects already, and warns. Rule strings with no mode at the Zero breakpoint warn the same way, beside the shared parser's own warnings for invalid tokens (the Breakpoint service's check (b)). A Class breakpoint that the compiled CSS lacks is the Runtime checks' report, so one mistake makes one report.

Used by: Media Object 2 (`stackFor` naming any breakpoint but the Zero breakpoint), Off-canvas 7 (`revealOn` or `inCanvasOn` naming the Zero breakpoint), Responsive Toggle 2 (`hideFor` is the Zero breakpoint), Top Bar 6 (`stackedFor` naming the Zero breakpoint), Responsive Accordion Tabs 6 and Responsive Menu 1 and 2 (rules).

#### S9. A deep link on a generated id

The rule (building-blocks 1.5, Ids): anything addressed from outside the application needs a consumer-supplied id, and the deep-linking inputs warn in development when the id was generated.

Used by: Reveal 4, Tabs (a generated panel id, recognised by Aria's `ng-tabpanel-` prefix), Responsive Accordion Tabs 5 (a section without `id`). The Accordion's check 2, which reads the content part's id, is the family-checks spec's.

#### S10. Links and link hosts

Three rules, no shared code:

- The disabled contract of ADR 0011 (a disabled link has no target; a placeholder link carries `role="link"` and `aria-disabled="true"`; a link without `href` is not focusable): Button (a) and (b), Pagination 4, Breadcrumbs 5 and 8, Thumbnail 2, Triggers 3.
- A look that fails on a link: Badge 3 and Label 3 (the host is an `a`, where Foundation's `a:hover, a:focus` colour outranks the one-class component colour, 1.27:1 on Foundation's defaults), Thumbnail 3 (a thumbnail inside a plain link loses Foundation's hover and focus shadow).
- In-page link targets: the Smooth Scroll's checks and Magellan's no in-page links, which reuses the Smooth Scroll's in-page rule (ADR 0038).

#### S11. Inputs that do nothing, or that cannot apply together

Each reads only its own inputs, with no shared code: Button (c), Button Group 4, Drilldown 4, Dropdown 2, Flexbox Utilities 3, Magellan (`updateHistory` without `deepLinking`), Off-canvas 2 and 5, Progress Bar 3, Responsive Accordion Tabs 4, Table 3, Toggler 2, Visibility Classes 2 and 5, XY Grid 4.

#### S12. Silent where a forgotten import is the cause

A misuse warning whose element may carry a peer's attribute without its directive stays silent there, or counts the attribute as well as the class, so that the defect is reported once and the message never names the wrong fix:

- The Close Button's check 3 and the Top Bar's check 3 count the `nfsButton` or `nfsCloseButton` attribute as well as `.button` or `.close-button`, because the misuse stays once a forgotten import is added.
- The Off-canvas' check 3 is silent for a panel with an ancestor that carries `nfsOffCanvasContent` without its class.
- The Off-canvas' check 4, in its clause on a registered Trigger inside a modal panel, is silent when the panel holds an element carrying `nfsClose` or `nfsToggle` that registered nothing.
- The Orbit's checks 1 and 3 are silent when the root holds an element carrying `nfsOrbitRotation`, or `nfsOrbitBullets` or `nfsOrbitBullet`, that registered nothing.
- The Triggers' check 1 is silent for a bare Trigger inside an element that carries an Openable's attribute where the forgotten-import checks' shared verdict finds no instance of its directive.

Each reads only the attribute and the Structural class its entry names, except the Triggers' check 1 (common contract 8). The Off-canvas' checks 3 and 4, the Orbit's checks 1 and 3, and the Triggers' check 1 are five of the registration checks that [Decide: family checks report a forgotten peer themselves](../issues/157-decide-family-checks-report-forgotten-peers.md) names in its decision 3, which the user approved, the fifth by its wording, as [Re-run: forgotten-import checks spec for the later milestone](../issues/164-rerun-forgotten-import-checks-later-milestone.md) applied decision 2. Built without the forgotten-import checks, each keeps the silent form above. Built with them, each calls `nfsReportForgottenPeer(element, directive, foundBy)` for every element it would be silent for (the ancestor that carries `nfsOffCanvasContent`, found by the panel's class; the element inside a modal panel that carries `nfsClose` or `nfsToggle`, found by the panel's class; the element that carries `nfsOrbitRotation`, `nfsOrbitBullets`, or `nfsOrbitBullet`, found by `NfsOrbit`; the element that carries the Openable's attribute, found by the Trigger's class) and gives its own message only when every call returns `false`, so the forgotten import is reported once, whether or not `strictDirectiveImports` is on. The rule and its tests are the forgotten-import checks spec's ([Spec: forgotten-import checks (shared utility)](../issues/150-spec-forgotten-import-checks.md), In-family checks and Testing Decisions), as F5 of [Spec: family checks (later milestone)](../issues/160-spec-family-checks-later-milestone.md) applies it to the family checks.

### Rendered output

None. No check writes a DOM node, an attribute, a class, a style, or a listener that production has; its only output is a console message or, for two checks, a thrown development error.

### Rendering modes

- Server rendering and prerendering: the checks that read the DOM run in render callbacks, which Angular skips on the server, so nothing reports there; the `HostAttributeToken` reads are DI and safe on the server. The call-time warnings of the Breakpoint service and the Interchange's parser run where the call runs, on the server too, and the Interchange's `<img>` error and the Breakpoint service's invalid-map error throw at construction there as in the browser.
- Before hydration: nothing runs; server HTML is judged at the application's first client render, which is why the name and text checks read at the first render.
- Hydration: the checks write nothing, so hydration is unaffected.
- Incremental hydration and `@defer`: a block's checks run when it hydrates or renders; the Responsive Embed's check 2 skips a box with no embedded child at its first render, because a `@defer` placeholder's content is still to come; the Pagination and Breadcrumbs checks wait, in their self-destroying `afterEveryRender`, for the first render at which the host holds an item.
- Event replay: the checks declare no listener that replays; the Sticky's `focusin` listener is added in code, only while stuck, and never replays.

## Testing Decisions

A good test asserts what a developer observes: the console message (its text, its count, and when it appears), a thrown error, and silence for correct markup; never a check's internal state. The seam is the one every spec already used: the browser-level test renders a test host in Vitest browser mode with a `console.warn` spy, which is the highest seam at which the warnings exist. Prior art: each component spec's development-check cases, kept in its entry above; the Breakpoint service spec's one-test-file-per-case rule for anything reported once per realm; the forgotten-import checks' report tests and production-bundle assertion.

1. Story play function (`@storybook/angular-vite` with `@storybook/addon-vitest`, `npx nx test-storybook <lib>`). The stories write no Foundation or library class and no misuse, so each is a negative control; the stories that the specs gave a `console.warn` spy that records nothing keep it (Float Grid `float-grid--source-ordering`, Flex Grid `flex-grid--nesting`, and the family checks' stories). A story shows the correct form beside each rule (the Orbit's `orbit--autoplay`, the Sticky's `sticky--overflow-hidden-ancestor`, the Tooltip's `tooltip--defined-term`); layer 1 runs in Angular development mode, so the warnings run in it.
2. Browser-level test (Vitest browser mode, `npx nx test <lib>`). Per check: it fires once for its case and not for correct markup, with the message its entry gives; a check reported once per realm has a test file per case (the Float Grid's check 3); a production-mode fixture, or `ngDevMode` false, logs nothing (the Abide's "a production-mode fixture logs nothing", and the "nothing is checked when `ngDevMode` is false" case of most entries); a test host that writes a Foundation class on purpose says so (the Accordion's check 7, Magellan's D18, the Tooltip's checks 6 and 7). A case that also involves a forgotten import (S12) sits in the forgotten-import checks' tests when those land; until then it asserts silence.
3. Node-level Vitest. The pure matchers, table-driven: the copied-class token tests (the Accordion's check 7, the Tabs' per-directive test, the Tooltip's check 6), the heading check and the hash lookup (Accordion), the known-class check (Toggler 3), the `templateClasses` filter's dropped tokens (Tooltip 7), the interactive-host classifier (Tooltip 1), the rule parsers' warnings (the Breakpoint service's (b), the Interchange's query classifier). The SSR smoke asserts that no warning is logged during a server render (the Accordion Menu, Media Object, Menu, Nested menu, Responsive Menu, Slider, Switch, Table, and Top Bar entries).
4. Playwright e2e. The Sticky's "Focus not obscured (2.4.11)" case asserts "no development warning is logged" and the Table's check 2 fires only below the stack breakpoint, which "the e2e layer covers". The static Storybook build runs in production mode (ADR 0018), where these warnings do not exist, so both run against the Fixture app built in the development configuration, as the forgotten-import checks' e2e does (D13 under Further Notes).

A test statement the spec wrote for a list that also holds another kind's checks ("each of the seven warnings fires once") keeps its wording in both deferred specs, each naming its own numbers, so the later milestone writes it once when both kinds have landed.

## Out of Scope

- The other four kinds: forgotten-import checks, family checks, Runtime checks, and build-time checks, each in its own spec (the table under What a misuse warning is). Category: `scope-boundary`.
- A switch, an opt-out, or a production form of any misuse warning: every report is a real misuse, and production must carry none of the code (P23; common contract 5). Category: `other`.
- Reporting on the server: the checks that read the DOM run in render callbacks only. Category: `other`.
- A lint rule or a compile-time form of these checks: a template's classes and attributes are strings the compiler accepts, and the forgotten-import checks already measured that syntax alone misreads scope. Category: `other`.
- Angular Aria's own development warnings: Aria's, in every milestone. Category: `scope-boundary`.
- The checks the specs considered and rejected, which the later milestone does not add: runtime contrast checks in the directives (ADR 0022, rejected for the compile-time checks); a copied-class check on the Card (D10) and on the Equalizer, whose directives own no class; a copied `accordion-menu` or `dropdown` on a root (the Accordion Menu's D24, the Dropdown Menu's D22, the Responsive Menu's D22); a report of a copied Sticky State class (D16); a check for an unhidden icon-font glyph and a re-check on every render (the Label's and Badge's D5); a check for digit-only badge text (the Badge's D6) and a badge on a button; a naming check for the Button Group (D4); checks on captions, autoplay, and fallback length (the Responsive Embed); checks on truncated text, table display, and positioned content (the Prototyping Utilities' D18); checks on a clipping ancestor, an NG02952 predictor, and a 2.5.8 size check (the Thumbnail's Out of Scope, D5, D7); the Float Classes' width check and missing-include detection, and the Float Grid's rejected alternatives (group c's re-run, decision 9); other Foundation class names in the Tooltip's `templateClasses`; a quiet guard for the Triggers' check 2 case (D12). Category: `other`.
- Changing any first-milestone behaviour: the stripping bindings, the `false` answers, the clamping, and the phases that complete at once stay as the component specs give them. Category: `scope-boundary`.

### Usage examples

```html
<ul nfsAccordion>
  <li nfsAccordionItem class="is-active">

```
the class is set by `nfsAccordionItem`; bind `[expanded]="true"` on the title instead
