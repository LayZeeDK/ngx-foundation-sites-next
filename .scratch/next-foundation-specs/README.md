# next-foundation-specs: bundle index

The planning bundle for the next, from-scratch ngx-foundation-sites: an Angular 22.2 directive library that keeps Foundation for Sites 6.9's Sass and CSS class contract and gives every Foundation UI component, layout system, and utility family Angular directives, which set every Foundation and library class so the consumer writes none (the class rule, [ADR 0039](adr/0039-directives-manage-every-foundation-class.md)); the layout systems and utility families are a later milestone's, and until then the consumer writes their Foundation classes (Later-milestone families, below). This file is the index the [Consistency review and bundle index](issues/36-consistency-review.md) wrote on 2026-09-26, after checking the whole bundle against itself, brought up to date on 2026-09-27 with the ruling of [Triage the out-of-scope Foundation components and variants](issues/79-triage-out-of-scope-components-and-variants.md); [Consistency review: the class-rule wave](issues/133-consistency-review-class-rule-wave.md) checked it again and brought it up to date on 2026-09-29, and [Consistency review: the later-milestone waves](issues/180-consistency-review-later-milestone-waves.md) did so again on 2026-09-30. The map is [map.md](map.md); every decision lives in one ticket under `issues/`, and this index only points at them. `issues/` holds 191 tickets, all resolved but the open ones of the lazy family styles question (185, 186, 190, and 192); the Open list gives the later waves in the order they ran.

## Destination

One published spec per Foundation docs page for every UI component, layout system, and utility family in Foundation for Sites 6.9, JavaScript plugin or CSS-only, plus the shared-utility specs and five specs of checks for a later milestone: 57 specs, all published under [specs/](specs/): the 21 JavaScript plugins, Button, the five shared utilities of the first milestone (the four the building-blocks decision added, and [Spec: Variant declaration tooling](issues/136-spec-variant-declaration-tooling.md), which [Decide: typed Variant inputs over open Sass maps](issues/81-decide-typed-variant-inputs-open-sass-maps.md) added), the 25 docs-page specs the 2026-09-27 ruling added (17 in the first milestone and the eight layout and utility family specs that [Decide: grids, typography, and utilities move to a later milestone](issues/174-decide-grids-typography-utilities-later-milestone.md) moved to a later milestone), and the five later-milestone check specs ([Spec: forgotten-import checks (shared utility)](issues/150-spec-forgotten-import-checks.md), which [ADR 0046](adr/0046-forgotten-imports-caught-by-checks.md) added, and the four that [Decide: checks move to a later milestone](issues/158-decide-checks-move-to-a-later-milestone.md) added); each of the 26 specs published before that ruling was re-run under the class rule by a ticket of its own (Open list). Each spec describes the Angular directives (preferred) or component that give the component to the next repository, and [building-blocks.md](building-blocks.md) records the Angular, Aria, CDK, or native platform primitive each one is built on. The map also required a working Playwright component test solution (found: [Prototype: Playwright component tests mounting CSF stories from @storybook/angular-vite](issues/40-playwright-component-testing-prototype.md)), a decided browser testing stack ([ADR 0018](adr/0018-browser-testing-stack.md)), and a passed consistency review: the [Consistency review and bundle index](issues/36-consistency-review.md) passed the 26 published specs, and [Consistency review: the class-rule wave](issues/133-consistency-review-class-rule-wave.md) passed all 53 on 2026-09-29, and [Consistency review: the later-milestone waves](issues/180-consistency-review-later-milestone-waves.md) passed all 57 on 2026-09-30. Since 2026-10-01 the Float Grid and Flex Grid are out of scope ([Task: remove the Float Grid and Flex Grid from the bundle](issues/187-task-remove-float-and-flex-grids.md)): 55 specs remain, six of them later-milestone family specs, and the two grid specs stay under `specs/` as history with an out-of-scope banner. The full statement is the map's Destination section.

Target platform: Angular 22.2 (core, forms, cdk, aria, material), Nx 23.2, Storybook 10.6 with `@storybook/angular-vite`, Vitest 4.1 browser mode, TypeScript 6.0, Foundation for Sites 6.9.0; browsers are the Baseline widely available set of 2026-05-07 (Chrome, Edge, and Firefox 119, Safari 17). Moving the bundle into the new repository is that repository's first task and is out of scope here.

## How to read the bundle

Read in this order. Each step assumes the ones before it.

1. [map.md](map.md): the Destination, the standing preferences every spec follows (directive first, implementation order, Foundation Sass reused and never re-implemented, WCAG 2.2 AA as requirements, animation through `animate.enter`/`animate.leave` or State classes, every rendering mode, the Browser target, the four test layers), the orchestration and triage rules, and Decisions so far (one line per resolved ticket).
2. [building-blocks.md](building-blocks.md): Part 1 holds the cross-cutting rules every spec inherits (1.1 directive or component to 1.14 spec shape); Part 2 is the matrix (Table A structure, Table B mechanics) with one row per plugin, and Table D, one row per spec the 2026-09-27 ruling added, filled by its spec ticket; Part 3 the five shared utilities (Table C); Part 4 the graduated tickets and the items once OPEN FOR HUMAN, none of which is open (Open list).
3. [architecture-guide.md](architecture-guide.md): the directive and component architecture principles: 26 testable rules over eight kinds of building block, an 11-question decision framework, an idioms table for authors who know React's headless libraries, and the conflicts the research raised, each principle restating a map ruling, an ADR, or building-blocks (which outrank it) or marked New; [Audit: the specs against the architecture guide](issues/142-audit-specs-against-architecture-guide.md) audits every spec against it, and the user decided both parts it had left provisional on 2026-09-28: the release policy ([ADR 0045](adr/0045-release-policy-devkit-version-scheme.md)), which stays out of the audit, and the import array, which the library does not have ([ADR 0046](adr/0046-forgotten-imports-caught-by-checks.md)).
4. [CONTEXT.md](CONTEXT.md): the glossary. Specs use its terms as written (Trigger, Openable, Light dismiss, Anchored pane, Nested menu, Mode swap, Server breakpoint, Library mixin, and so on) and avoid the words it lists under `_Avoid_`.
5. [adr/](adr/): 46 decision records, indexed below (44 accepted, two superseded). 6. ### `@angular/aria` building blocks not used (decided 2026-09-27)

The repository's `AGENTS.md` asks for confirmation before falling back from an `@angular/aria` building block. The user ruled that this pass decides the list from evidence (map, Open-decision pass); the [Decide the `@angular/aria` fallback confirmation](issues/75-evidence-aria-fallback-confirmation.md) did, from the dossier `research/aria-fallback-evidence.md` and two adversarial reviews. One fallback was overruled; eight stand, with corrected reasons where the original overstated.

1. Overruled: Orbit slides host Aria's `TabPanel` again and override only `inert`, with a binding derived from `TabPanel.visible()` that changes in every pass in which Aria's does and so keeps `inert` out of server HTML (measured in the server renderer and in three engines); the Orbit writes Aria's selection synchronously. [ADR 0037](adr/0037-orbit-slide-hosts-tab-panel.md) supersedes ADR 0034; [Spec: Orbit](issues/33-spec-orbit.md).
2. Orbit offers no Aria `TabContent` for lazy slides: Aria's lazy content renders only for the selected slide, and in a scroll-snap carousel a slide is on screen before it is selected, so a lazy slide would be blank while scrolled in and the container's height would jump when it fills; empty in server HTML too. `@defer (on viewport)` inside a slide is the supported form. [Spec: Orbit](issues/33-spec-orbit.md).
3. Accordion does not use Aria's `AccordionContent`, even for Lazy content: Aria creates the view in a render callback, so an open panel would be empty in server HTML (ADR 0008); it removes content at the start of the close transition unless preserved; and its `preserveContent` cannot be exposed through the wrapper's own `hostDirectives` inputs (a consumer can still bind it on the content element, in bound form only, through `AccordionPanel`'s own exposure, and library code reading it would depend on Aria's private-prefixed re-export). [Spec: Accordion](issues/15-spec-accordion.md).
4. Tabs uses Aria's `TabContent` only behind the opt-in lazy template; by default panel content is projected, for the same server-HTML reason. [Spec: Tabs](issues/16-spec-tabs.md).
5. Responsive Accordion Tabs exposes neither lazy form (additive scope, not a misfit): sections are created again on every Mode swap, including the first-render swap on a client whose breakpoint differs from the server's, so `preserveContent` cannot hold; and the tabs-mode lazy form is empty in server HTML while the accordion-mode form is not, so one lazy input would be server-rendered in one mode only. [Spec: Responsive Accordion Tabs](issues/19-spec-responsive-accordion-tabs.md).
6. The menus (the Nested menu family behind AccordionMenu, Drilldown, DropdownMenu, and ResponsiveMenu) use neither `ngMenuBar`/`ngMenu` nor `ngTree`: they apply the `menubar`, `menu`, `menuitem`, and `tree` roles that the APG advises against for site navigation (the Angular Aria guide agrees for `ngMenu` and lists navigation as a use for `ngTree`), set no tab stop in server HTML, cancel Enter on a link item (the menu), keep tree child levels out of server HTML and force multi-expansion (the tree), need `[submenu]` references or `ng-template` groups with `[parent]` inputs on Foundation's nested `ul`, fit Drilldown not at all, and the menubar is horizontal only ([ADR 0004](adr/0004-menus-use-disclosure-navigation.md)). [Spec: Nested menu (shared utility)](issues/56-spec-nested-menu.md), [Spec: Accordion Menu](issues/20-spec-accordion-menu.md), [Spec: Dropdown Menu](issues/21-spec-dropdown-menu.md), [Spec: Drilldown Menu](issues/22-spec-drilldown-menu.md), [Spec: Responsive Menu](issues/23-spec-responsive-menu.md).
7. Accordion Menu does not use Aria's accordion: every enabled trigger is a tab stop (not one roving stop), but its group listener handles keys from inside open sections without checking the target (arrows move among triggers only; Enter and Space toggle a section), so a menu would guard Aria's keys off and re-add Foundation's cross-link arrows; the `region` per panel is removable; each trigger needs a required `[panel]` binding; and ResponsiveMenu needs one directive family across modes. [Spec: Accordion Menu](issues/20-spec-accordion-menu.md).
8. The Dropdown pane does not use Aria's menu: a pane holds arbitrary content, so `role="menu"` would promise menu keys it does not have and fail axe's required-children rule; it is a disclosure or a non-modal dialog. [Spec: Dropdown](issues/26-spec-dropdown.md).
9. Triggers do not use Aria's `MenuTrigger`: it renders `aria-haspopup="true"`, which WAI-ARIA treats as `menu`, targets `ngMenu` only, and keeps the open state in the trigger, wrong for every Openable. [Spec: Triggers (shared utility)](issues/54-spec-triggers.md).

The specs of the class-rule wave decline three more Aria patterns, each a different pattern from the component's own and not a fallback from a building block that fits it, so none needs the confirmation `AGENTS.md` asks for: Aria's `Toolbar` for the [Spec: Button Group](issues/82-spec-button-group.md) (D10: a composite with one tab stop and arrow keys, which Foundation's Button Group does not have; the APG keeps toolbars for three or more controls, and a split button has two; `nfsButton` on an `ngToolbarWidget` host fights its `disabled` and `aria-disabled` bindings), and for the [Spec: Top Bar](issues/86-spec-top-bar.md) (D14) and the [Spec: Pagination](issues/87-spec-pagination.md) (D14), because a toolbar's roving tab stop does not suit site navigation ([ADR 0004](adr/0004-menus-use-disclosure-navigation.md)); `ngMenuBar`, `ngMenu`, and `ngToolbar` for the [Spec: Menu](issues/85-spec-menu.md) (Implementation level, ADR 0004, as item 6); and Aria's `Grid` for the [Spec: Table](issues/92-spec-table.md) (D14: an interactive composite, which a static table is not) and the [Spec: XY Grid](issues/99-spec-xy-grid.md) (D13: a CSS layout grid is not the APG Grid composite). No other available Aria pattern was declined: `@angular/aria` 22.2 ships accordion, combobox, grid, listbox, menu, tabs, toolbar, and tree, and has nothing for Button, Close Button, Switch, Callout, Progress Bar, the other CSS-only components, layout systems, and utility families, the Breakpoint service, the Anchored pane, Reveal, Off-canvas, Tooltip, Toggler, Responsive Toggle, Slider, Abide, Interchange, Equalizer, Sticky, Smooth Scroll, or Magellan.
