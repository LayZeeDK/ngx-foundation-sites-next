# next-foundation-specs: bundle index

The planning bundle for the next, from-scratch ngx-foundation-sites: an Angular 22.2 directive library that keeps Foundation for Sites 6.9's Sass and CSS class contract and replaces every Foundation JavaScript plugin. This file is the index the [Consistency review and bundle index](issues/36-consistency-review.md) wrote on 2026-09-26, after checking the whole bundle against itself. The map is [map.md](map.md); every decision lives in one ticket under `issues/`, and this index only points at them.

## Destination

One published spec for every JavaScript plugin in Foundation for Sites 6.9 (21 plugins), plus Button and the four shared utilities the building-blocks decision added: 26 specs under [specs/](specs/). Each spec describes the Angular directive (preferred) or component that replaces the plugin, and [building-blocks.md](building-blocks.md) records the Angular, Aria, CDK, or native platform primitive each one is built on. The map also required a working Playwright component test solution (found: [Prototype: Playwright component tests mounting CSF stories from @storybook/angular-vite](issues/40-playwright-component-testing-prototype.md)), a decided browser testing stack ([ADR 0018](adr/0018-browser-testing-stack.md)), and a passed consistency review (this index). The full statement is the map's Destination section.

Target platform: Angular 22.2 (core, forms, cdk, aria, material), Nx 23.2, Storybook 10.6 with `@storybook/angular-vite`, Vitest 4.1 browser mode, TypeScript 6.0, Foundation for Sites 6.9.0; browsers are the Baseline widely available set of 2026-05-07 (Chrome, Edge, and Firefox 119, Safari 17). Moving the bundle into the new repository is that repository's first task and is out of scope here.

## How to read the bundle

Read in this order. Each step assumes the ones before it.

1. [map.md](map.md): the Destination, the standing preferences every spec follows (directive first, implementation order, Foundation Sass reused and never re-implemented, WCAG 2.2 AA as requirements, animation through `animate.enter`/`animate.leave` or State classes, every rendering mode, the Browser target, the four test layers), the orchestration and triage rules, and Decisions so far (one line per resolved ticket).
2. [building-blocks.md](building-blocks.md): Part 1 holds the cross-cutting rules every spec inherits (1.1 directive or component to 1.14 spec shape); Part 2 is the matrix (Table A structure, Table B mechanics) with one row per plugin; Part 3 the four shared utilities (Table C); Part 4 the graduated tickets and the one open item of that ticket.
3. [CONTEXT.md](CONTEXT.md): the glossary. Specs use its terms as written (Trigger, Openable, Light dismiss, Anchored pane, Nested menu, Mode swap, Server breakpoint, Library mixin, and so on) and avoid the words it lists under `_Avoid_`.
4. [adr/](adr/): 35 accepted decision records, indexed below. Later findings are dated bullets beside the part they qualify, and a changed decision gets a new record; audit 0004's fixes corrected the wording of ADRs 0008, 0017, 0022, 0024, and 0025 in place (its Resolution log).
5. [specs/](specs/): the 26 specs, in the plugin and utility tables below. Every spec has the seven `/to-spec` sections in order (Problem Statement, Solution, User Stories, Implementation Decisions, Testing Decisions, Out of Scope, Further Notes), with the API-design material placed as building-blocks 1.14 says, a WCAG 2.2 AA criteria subsection (ADR 0022), and a Sass subsection in the form of [Sass packaging for the new library](issues/57-sass-packaging.md). Each spec's ticket under `issues/` holds its decision log, triage, and amendments.
6. [storybook-conventions.md](storybook-conventions.md): how every spec's stories are written, named, styled, and gated, including the full `_settings-overrides.scss` list the specs require.
7. [research/](research/): the fifteen research files the specs cite by title and section: the four Foundation plugin inventories ([disclosure](research/foundation-inventory-disclosure.md), [menus](research/foundation-inventory-menus.md), [positioned](research/foundation-inventory-positioned.md), [forms and media](research/foundation-inventory-forms-media.md)), [Foundation core conventions and utilities](research/foundation-utilities-conventions.md), the [Angular 22.2 API survey](research/angular-22-api-survey.md), the [Aria inventory](research/angular-aria-inventory.md), the [CDK inventory](research/angular-cdk-inventory.md), the [Material reference](research/angular-material-reference.md), the [APG patterns](research/aria-apg-patterns.md), the [web platform features](research/web-platform-features.md), the [tooling baseline](research/tooling-baseline.md), the [DI and composition patterns](research/di-and-composition-patterns.md), the [rendering modes](research/angular-rendering-modes.md), and [Playwright component testing](research/playwright-component-testing.md).
8. [prototypes/](prototypes/): the captured decisive files of 23 prototypes and re-runs, each with a README that states the question, how to run it, and the verdict; the matching ticket holds the results table and triage. The runnable workspaces stayed under `D:/tmp/`.
9. [audits/](audits/): five compliance audits (research wave, building blocks, prototypes and first specs, second spec wave, final bundle), each ending with a resolution log.

## Open list

Everything below is left OPEN FOR HUMAN after the triage rule in the map's Orchestration rules: only an item of HIGH impact with NOT-HIGH confidence stays open, plus outward-facing actions under the user's identity (upstream filings), checks that need assistive technology, and the fallbacks from `@angular/aria` building blocks that `AGENTS.md` asks the user to confirm, a kind the triage rule also names human-only. Each item runs on its applied default until the user decides; its ticket holds the options and the evidence. ### Upstream filings (10; filing needs the user's confirmation)

1. angular/components (Aria): let `ngAccordionPanel` and `ngTabPanel` take projected content without `ngAccordionContent`/`ngTabContent`, so the development warning per projected panel stops. 2. angular/components (Aria): skip `preventDefault()` during event replay in Aria's keyboard event manager, which logs one error per replayed Aria key (the library accepts the log: building-blocks Part 4, Decided item 3). [Prototype: `@angular/aria` Accordion and Tabs under Foundation markup](issues/43-prototype-aria-accordion-tabs.md), [Spec: Accordion](issues/15-spec-accordion.md), [Spec: Tabs](issues/16-spec-tabs.md).

4. angular/components (Aria): a public way to move `TabList`'s active item, so the roving tab stop can follow a selection change from outside Aria (accepted and documented as a known deviation in Orbit, Tabs, and Responsive Accordion Tabs). 6. angular/angular (compiler): a `#ref="exportAs"` reference to a directive applied through `hostDirectives` gives an unlocated internal error instead of a diagnostic. [Prototype: Abide control kinds, value adoption, and the ready gate](issues/66-prototype-abide-controls-and-ready.md).

### Confirmation: `@angular/aria` building blocks not used (1 item)

The repository's `AGENTS.md` asks for confirmation before falling back from an `@angular/aria` building block, and the map's triage rule names such a fallback human-only by kind: the spec applies its choice as the default, its ADR may be accepted, and the consistency review lists every such fallback once. The user confirms or overrules the list as one item.

1. Orbit slides do not host Aria's `TabPanel`: its own `inert` binding turns on in a later server pass, so no binding of the slide can keep `inert` out of server HTML, which ADR 0025 requires (measured in three engines); the slide binds the tab panel contract itself, and the bullets keep Aria `Tabs`, `TabList`, `Tab`. [ADR 0034](adr/0034-orbit-slide-contract.md); [Re-run: Orbit spec, the slide's ARIA contract and the focus handoff](issues/70-rerun-orbit-slide-contract-and-focus-handoff.md), [Spec: Orbit](issues/33-spec-orbit.md).
2. Orbit offers no Aria `TabContent` for lazy slides: slide content is projected so every slide is in server HTML and reachable without JavaScript. [Spec: Orbit](issues/33-spec-orbit.md).
3. Accordion does not use Aria's `AccordionContent`, even for Lazy content: Aria creates the view in a render callback, so an open panel would be empty in server HTML (ADR 0008), it removes content before the close animation, and its `preserveContent` cannot be forwarded through a second host-directive level. [Spec: Accordion](issues/15-spec-accordion.md).
4. Tabs uses Aria's `TabContent` only behind the opt-in lazy template; by default panel content is projected, for the same server-HTML reason. [Spec: Tabs](issues/16-spec-tabs.md).
5. Responsive Accordion Tabs exposes neither lazy form: sections are created again on every Mode swap and must be in server HTML. [Spec: Responsive Accordion Tabs](issues/19-spec-responsive-accordion-tabs.md).
6. The menus (the Nested menu family behind AccordionMenu, Drilldown, DropdownMenu, and ResponsiveMenu) use neither `ngMenuBar`/`ngMenu` nor `ngTree`: they apply the `menubar`, `menu`, `menuitem`, and `tree` roles that the APG and the Angular Aria guide advise against for site navigation, with a roving tab stop, and their `ng-template` groups and `[parent]` inputs break Foundation's nested `ul`; Drilldown fits neither; Aria's menubar is also horizontal only and renders submenus outside server HTML ([ADR 0004](adr/0004-menus-use-disclosure-navigation.md)). [Spec: Nested menu (shared utility)](issues/56-spec-nested-menu.md), [Spec: Accordion Menu](issues/20-spec-accordion-menu.md), [Spec: Dropdown Menu](issues/21-spec-dropdown-menu.md), [Spec: Drilldown Menu](issues/22-spec-drilldown-menu.md), [Spec: Responsive Menu](issues/23-spec-responsive-menu.md).
7. Accordion Menu does not use Aria's accordion: it is the APG Accordion pattern for page sections (a `region` per panel, one roving tab stop over the triggers), where disclosure navigation keeps every button and link in the tab sequence; each trigger would also need a required `[panel]` binding. [Spec: Accordion Menu](issues/20-spec-accordion-menu.md).
8. The Dropdown pane does not use Aria's menu: a pane holds arbitrary content, so `role="menu"` would promise menu keys it does not have; it is a disclosure or a non-modal dialog. [Spec: Dropdown](issues/26-spec-dropdown.md).
9. Triggers do not use Aria's `MenuTrigger`: it renders `aria-haspopup="menu"` and menu semantics, wrong for every Openable. [Spec: Triggers (shared utility)](issues/54-spec-triggers.md).

No available Aria pattern was declined elsewhere: `@angular/aria` 22.2 ships accordion, combobox, grid, listbox, menu, tabs, toolbar, and tree, and has nothing for Button, the Breakpoint service, the Anchored pane, Reveal, Off-canvas, Tooltip, Toggler, Responsive Toggle, Slider, Abide, Interchange, Equalizer, Sticky, Smooth Scroll, or Magellan.
