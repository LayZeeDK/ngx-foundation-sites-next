# Prototype: Variant declaration tooling in real Nx and Angular CLI workspaces

Ticket: [Prototype: Variant declaration tooling in real Nx and Angular CLI workspaces](../../issues/137-prototype-variant-declaration-tooling.md). The full answer, per-question evidence, triage, and the exact spec changes are in the ticket's `## Answer`. Everything here is throwaway prototype code.

## Question

Build the shared core, the setup generator and schematic, the Nx task sync generator, and the Architect builder of the [Spec: Variant declaration tooling](../../issues/136-spec-variant-declaration-tooling.md) over a stand-in `ngx-foundation-sites` package (the primary-entry-point types, five registries, their Library mixins, one directive per shape), pack it, and measure in scratch workspaces (Nx 23.2.1 with `@nx/angular` 23.2.1; Angular CLI 22.2.0):

1. Which rewrites of the declaration file the dev server re-checks, why only the first, and whether anything makes every rewrite reach the template diagnostics.
2. Whether the unit-test builders (Vitest, jsdom and browser mode) and `@storybook/angular-vite` (dev, build, the `@storybook/addon-vitest` run, docgen controls) see the file, and fail closed without it.
3. Whether the core's Sass compile reads the same Variant properties as the application builder's built `styles.css` across resolution and configuration cases.
4. The `CI=true` e2e of the typing decision's residual risk (b).
5. Whether per-project `syncGenerators` with the `"..."` spread keeps `targetDefaults`, and what an executor-keyed entry would drop.
6. `convertNxGenerator` in a plain Angular CLI workspace, the check builder without `nx`, and Nx running the same builder.

## Verdict

| # | Verdict | Spec |
| --- | --- | --- |
| 1 | The restart note does not stand; a fix exists. `@angular/build` 22.2.0 computes template diagnostics only for files TypeScript's builder reports as affected, and a module-augmentation file that nothing imports affects only itself (with `isolatedModules`, always only itself). The first rewrite is re-checked only because the dev server's first incremental rebuild replaces the 46-character placeholder type-check shim with the full one, which marks every component affected; after a component edit even the first rewrite stays stale (control run). `/// <reference path>` from `main.ts` and a `files` entry change nothing. An empty `declare global {}` in the file makes TypeScript treat each change as affecting every file: all five alternating rewrites were re-checked correctly under `ng serve` and `nx serve`, including the real flow (Sass edit, then `ng run cli-ws:nfs-variants` or `nx sync`) and an upgrade from a file without the line. | text correction |
| 2 | Pass for the unit-test builders: `@angular/build:unit-test` (CLI: Vitest 5.0.2, jsdom 30.1.1; Nx: Vitest 4.1.11, jsdom 27.4.0) and `@nx/angular:unit-test`, each in jsdom and in Chromium 153 browser mode, compile a declared name and fail with TS2322 without the file. Storybook type-checks nothing: `storybook dev`, `storybook build` (default `jit: true`, and `jit: false`), and the addon-vitest run pass with or without the file; only `tsc -p .storybook/tsconfig.json` checks story args (TS2322 without the setup's include). Docgen gives a Variant input typed by the package's alias no options (a JSON editor), because the docgen worker skips type aliases declared in declaration files; an alias declared in source gets its names, and a source `.d.ts` augmentation reaches them. Side finding: ng-packagr ignores `include`, so a library build needs the file in `compilerOptions.types`. | text correction |
| 3 | Pass for the cases the builder supports, with three rule corrections: the builder compiles with `sass-embedded` (pure-JS `sass` async took about 8.5 s per compile here, `sass-embedded` 0.7 s); every bare and `pkg:` specifier goes through esbuild's resolver with the builder's stylesheet options (so `style` wins over `sass` in a package without `exports`, where Sass's `NodePackageImporter` picks `sass`); and the builder does not strip `~` (both compilers failed on it). Equal properties in all eight cases; M12 and M11 fire where designed. | text correction |
| 4 | Pass: `CI=true nx build shop` passed against the stale file and shipped no `.button.warning` rule while `main.js` carried `"warning"`; `nx sync:check` exited 1 with the spec's detail line; `nx sync` rewrote the file (`warning: false`); the next build failed with TS2322 on `color="warning"`. | none |
| 5 | Pass: the per-project spread keeps the preset's executor-keyed defaults and name-keyed defaults (`dependsOn`, `cache`, `inputs`), another tool's executor-keyed `syncGenerators`, and inferred Storybook targets; executor-keyed entries for the sync generator dropped `dependsOn` and `inputs` of the name-keyed defaults, and Nx 23.2.1 warns about exactly that. | none |
| 6 | Pass, with two text corrections: the schematic wrote `angular.json`, the file, and the npm scripts, but the generator must edit `angular.json` itself (`updateProjectConfiguration` writes an `nx` field into `package.json` there); the check builder runs without `nx` (2.4 s wall) and the schematic ends with M9; Nx runs the builder as an Angular-compatible builder (exit 0 in step, 1 on drift under `CI=true`). | text correction |

## How to run

Scratch root `D:/tmp/nfs-proto-137/` (not committed). Node 24.18.0, npm 11.16.0, Windows 11 on arm64.

1. Package: `pkg-build/` holds `ng-packagr` 22.2.0, `@angular/*` 22.2.0, TypeScript 6.0.3 (`package/build-workspace.package.json`); the package source is `pkg-build/lib/` (this folder's `package/`). `npx ng-packagr -p lib/ng-package.json -c lib/tsconfig.lib.json`, then `npm pack` in `pkg-dist/`.
2. Nx workspace: `env -u CLAUDECODE npx create-nx-workspace@23.2.1 nx-ws --preset=angular-monorepo --appName=shop --style=scss --bundler=esbuild --ssr=false --e2eTestRunner=none --unitTestRunner=vitest --nxCloud=skip --workspaces=false --useProjectJson=true --formatter=prettier --linter=none --aiAgents=none`; the preset pinned `@angular/*` `~22.1.0`, so `measure/pin-nx.cjs` sets 22.2.0 and a fresh `npm install` follows. `shop` and `admin` were regenerated with `@nx/angular:application` (`--unitTestRunner=vitest-angular`), `ui` with `@nx/angular:library --buildable`; then `measure/add-include-paths.cjs shop admin`, the tarball, `foundation-sites` 6.9.0, and for question 2 `@vitest/browser-playwright` 4.1.11, `playwright` 1.63.0, `storybook`, `@storybook/angular-vite`, `@storybook/addon-vitest` 10.6.0, `@analogjs/vite-plugin-angular` 2.7.5, `@nx/storybook` 23.2.1, `@types/node` 24. Setup: `npx nx g ngx-foundation-sites:variant-types`, then `npx nx g ngx-foundation-sites:variant-types --projects=ui --buildTarget=shop:build`.
3. Angular CLI workspace: `npx @angular/cli@22.2.0 new cli-ws --defaults --style=scss --ssr=false --skip-git`, then the tarball, `foundation-sites`, `nx` and `@nx/devkit` 23.2.1, `@vitest/browser-playwright` 5.0.2, `playwright`; `npx ng g ngx-foundation-sites:variant-types --npm-scripts`; later `npm uninstall nx @nx/devkit`.
4. Measurements (each restores what it edits): `measure/q1-instrument.cjs <ws>` adds `NFS_TRACE` logging to the scratch workspace's own `@angular/build` (`--restore` removes it); `measure/q1-dev-server.cjs <cli|nx> <baseline|reference|files|global|tool|upgrade> <port>` (ports 5080, 5081; `SPEND_FIRST=1` for the control); `measure/q2-unit-tests.cjs <cli|nx>`; `measure/q2-dev-controls.cjs 5082 <label>`; `measure/q3-resolution.cjs` and `measure/q3-probe-fields.cjs` from `cli-ws`; `measure/q4-e2e.sh`; `measure/q5-target-defaults.cjs` from `nx-ws`; `measure/q6-update-project-config.cjs`. Every run used `NX_DAEMON=false`; no server or daemon was left running.

## What is here

- `package/` -- the stand-in package: `src/public-api.ts` (the spec's helper types, five registries, the Class breakpoint types, `nfsVariantBoolean`), `button/` (name and query shapes), `xy-grid/` (count and rules), `callout/` (the base palette), `_index.scss` (the Library mixins in the Variant property format), and `tooling/`: `core.cjs` (sources, compile, read, expected model, parse, compare, render, format), `setup.cjs` (generator and schematic), `sync.cjs`, `builder.cjs`, `manifest.json`, `collection.json`, `builders.json`, and the schemas. `emitted/` holds the packed `package.json` and the button entry point's typings.
- `fixtures/` -- the workspace files the measurements depend on, and the generated declaration files (`generated/*.d.ts.txt`).
- `measure/` -- the measurement scripts.
- `results/` -- per-question results, ASCII, with no personal paths: `q1-*.json` (per rewrite: rebuilt, TS2322 present, correct, the builder trace), `q2-*`, `q3-*`, `q4-*`, `q5-target-defaults.json`, `q6-*.log`.
