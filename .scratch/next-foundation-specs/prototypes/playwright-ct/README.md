# Prototype: Playwright component tests mounting CSF stories

Ticket: [Prototype: Playwright component tests mounting CSF stories from @storybook/angular-vite](../../issues/40-playwright-component-testing-prototype.md).

## Question

Does a working Playwright component test setup exist for an Angular 22.2 library on Nx 23.2, and can it
mount the same CSF stories that `@storybook/angular-vite` 10.6 renders and that `@storybook/addon-vitest`
runs as interaction tests? Compare the same story through Playwright component tests, `nx test-storybook`
(addon-vitest), and a Vitest Browser unit test.

This is a tooling feasibility prototype. Neither branch of the prototype skill (logic demo or UI variants)
fits the question, so the prototype is a runnable Nx workspace, as the ticket asks.

## Verdict

**Yes.** Playwright 1.63's built-in `mount(storyId, props)` fixture, pointed at the static Storybook build
(`iframe.html?embed=true`) as its gallery page, mounts the same CSF stories that addon-vitest runs. No
adapter package is needed: about 150 lines of project-owned gallery code (comments included) in `.storybook/` answer
`window.mount` / `window.unmount` by driving Storybook's own preview. Interaction, `update(props)` with
Angular state kept, function props, unknown-id rejection, the addon-a11y result, and `@axe-core/playwright`
all work in Chromium, Firefox, and WebKit. Without `embed=true` the story's own play function runs inside
Playwright and a failing play function or axe violation rejects `mount()` (that project ran in Chromium only).

None of the three Angular community packages is a working solution next to `@playwright/test` 1.63.0.
The full results table, the exact errors, timings, and the "what this does not prove" list are in the
ticket's `## Answer`.

`node_modules`, the Storybook build, and the spikes' own installs) stays at `D:/tmp/nfs-ct-prototype/`
and is not committed.

## How to run

Windows 11 arm64, Node 24.18.0, npm 11.16.0. From `D:/tmp/nfs-ct-prototype`:

```
npx nx test-storybook ui                                   # path 1: addon-vitest, play + addon-a11y
npx nx test ui --browsers=chromiumHeadless                 # path 2: Vitest Browser, portable stories
npx nx e2e ui-ct                                           # path 3: candidate 1, all four projects
npx nx e2e ui-ct -- --project=components --project=stories-play   # candidate 1, Chromium only
npx nx e2e ui-ct-gallery                                   # candidates 2 and 3
node tools/time-runs.mjs                                   # timings for all of the above

cd spikes/sand4rt && npx playwright test -c playwright-ct.config.mts
cd spikes/jscutlery && npx playwright test -c playwright-ct.config.ts
cd spikes/selectors-angular && npx playwright test         # needs Storybook dev on 4415 and static on 4410
```

`nx e2e ui-ct` builds Storybook and serves it on port 4410 as inferred task dependencies
(`ui:static-storybook`, `e2e--wait-for-webserver`). The Vite gallery listens on 4411; the spikes use
ports 4412 to 4415.

To rebuild the workspace from nothing, the ticket's `## Answer` lists every command, including the
`create-nx-workspace` pitfall (run it with `CLAUDECODE` unset, or it swaps the Angular preset for a demo
shop template pinned to Nx 23.2.0 and Angular 22.1.4).
