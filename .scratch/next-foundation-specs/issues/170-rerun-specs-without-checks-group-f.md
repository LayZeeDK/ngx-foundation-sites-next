# 170. Re-run: specs without checks, group f

Type: grilling
Status: resolved
Blocked by: 159
Labels: wayfinder:grilling
Map: ../map.md

## Question

The ruling [Decide: checks move to a later milestone](158-decide-checks-move-to-a-later-milestone.md) has every spec describe, and accept, a library with no checks. What do `specs/toggler.md`, `specs/tooltip.md`, `specs/top-bar.md`, `specs/triggers.md`, `specs/typography-helpers.md`, `specs/variant-declaration-tooling.md`, `specs/visibility-classes.md`, `specs/xy-grid.md` say without them?

## How to work it

Opus 5.5, AFK under the map's triage rule. For each spec, from its extraction manifest in [Task: extract the checks from the specs](159-task-extract-checks-from-specs.md) and a full read: remove every check of the five kinds, its messages, its tests and stories, and every sentence that relies on one (a parent check, a probe, `strictParents`, `nfsDirectiveCheck`, a Runtime check, a Library mixin's `@error`); state each rule a check enforced as documented usage, in the spec's API text, usage section, and the JSDoc it asks for; give each injection token its plain name as its description; keep the Library mixins' CSS rules and Variant properties, the required injections, ARIA, typed inputs, and the library's own tests of its components. No spec names a deferred check or links to a deferred spec; a forgotten import, a part outside its parent, or a misuse simply gets no warning. The Variant declaration tooling spec keeps its generate mode and loses its check mode (the build-time checks spec takes it) and the `missing-imports` builder (the forgotten-import checks spec takes it). Each changed spec gets a dated `### Amendment, 2026-09-29 (checks move to a later milestone)` in the ticket that holds its `### Amendment, 2026-09-29 (consistency review)`.

## Answer

Worked AFK on Opus 5.5 under the map's triage rule, from the group f manifest ([research/checks-extraction-f.md](../research/checks-extraction-f.md)) and a full read of each spec at 53144f3, following the conventions the group a and group e re-runs set (a Library mixin with only checks disappears; a read or property only a check used goes with it; each In-family bullet becomes an "Imports (documented usage)" bullet; a former compile stop becomes a required setting). The eight specs were revised in place; each governing ticket has a dated `### Amendment, 2026-09-29 (checks move to a later milestone)` that lists, per check, what left: [Re-run: Toggler spec under the class rule](109-rerun-toggler-class-rule.md), [Re-run: Tooltip spec under the class rule](119-rerun-tooltip-class-rule.md), [Re-run: Top Bar spec, out-of-scope survivors](148-rerun-top-bar-out-of-scope-survivors.md), [Re-run: Triggers (shared utility) spec under the class rule](130-rerun-triggers-class-rule.md), [Re-run: Typography Helpers spec, out-of-scope survivors](146-rerun-typography-helpers-out-of-scope-survivors.md), [Spec: Variant declaration tooling](136-spec-variant-declaration-tooling.md), [Re-run: Visibility Classes spec for the print classes](143-rerun-visibility-classes-print.md), and [Spec: XY Grid](99-spec-xy-grid.md).

### Decisions

1. Every check of the manifest left its spec, with its messages, tests, and the development-only reads it needed (`HostAttributeToken('class')`, `ElementRef`, CDK's `InteractivityChecker`, the XY Grid frame's `ResizeObserver`, the `nfsVariantCheck` handles). Each rule a check enforced is documented usage in the API text, a numbered "Documented usage" list stated in the JSDoc, the WCAG rows, or the Sass subsection. Bindings that strip a copied Foundation class stay, with their tests.
2. Every In-family line became an "Imports (documented usage)" bullet (Toggler, Top Bar, Triggers, Typography Helpers, Visibility Classes, XY Grid): NG8002 or NG8003 where a template binds or references the directive, otherwise nothing. `nfsOpenableToken` and `nfsTopBarRightToken` are described by their plain names.
3. Top Bar: `nfs-title-bar` and `nfs-top-bar` held only checks, so the first milestone has no such mixin; `nfs-menu-icon` keeps its 24 px box and forced-colours rules and loses its `@warn`. The group e re-run already removed the Responsive Toggle's includes of the two. The colour pairs the bars and the icon draw are required settings, listed in the Sass subsection and the 1.4.1, 1.4.3, 1.4.10, and 1.4.11 rows (D7, D8 rewritten).
4. Typography Helpers: `nfs-typography-base` held only checks and goes; `nfs-typography-helpers` keeps its grid margin rules and loses its `@error`. The four greys at `#666666` and `$code-color` at 4.5:1 on `$code-background` are required settings (D9, D23 rewritten).
5. Variant declaration tooling: generate mode stays (setup generator, sync generator writes with M1 and M2's thrown error, the builder's write mode, M8 to M13 without the CI step); check mode goes (the builder's `check` option and configuration, the CI steps, the check of hand-written files, M3 to M7, the "Check mode" comparison row, D24's old form). The spec now decides that the generated file is committed with the Sass change that changed it and CI builds against it, that a hand-written file follows the generated form's rules and is kept in step by hand, and that a stylesheet with no Variant property leaves every registry at its defaults. The Selector manifest and the `missing-imports` pieces left. The Variant typings check stays, as the library's own test of its published types (orchestrator's reading).
6. The flag-gated Variant properties the Variant declaration tooling spec described (read only by the Runtime check, not by the generator) left that spec's text with the Runtime checks; the tooling reads only the manifest's registry properties.
7. Tooltip: the Positioner's three warnings are the Anchored pane spec's; the quote left, and the offset and same-axis alignment rules are documented usage in the `alignment` and `vOffset`/`hOffset` rows. The `templateClasses` filter stays (it changes what the tip binds in every build); only its report left.
8. Design decisions: every row whose decision was a check now states the documented usage it decides (Toggler D19, D20; Tooltip D5, D7, D9; Top Bar D2, D5, D7, D8, D9, D13; Triggers D13; Typography Helpers D9, D10, D12, D14, D15, D21, D22, D23; Variant declaration tooling D8, D24, D29; Visibility Classes D4 to D11, D17, D20, D21; XY Grid D3, D7, D9, D10, D12, D16). Numbering is kept, so cross-references still resolve; rejected alternatives that were checks were removed.

### Triage

- Decision 3 and 4 (dropping `nfs-title-bar`, `nfs-top-bar`, and `nfs-typography-base` from the first milestone). Impact not HIGH: the first release carries fewer mixin names, and adding one later breaks no consumer (ADR 0045). Confidence HIGH: ADR 0012's 2026-09-27 note says a component that needs neither custom CSS nor checks "has none", and the group a re-run removed `nfs-abide` the same way. Decided.
- Decision 5 (which messages are check mode). M8, M10, M11, and M12 stay as the generator's own errors and warning (a compile failure, an unwritable count, a configuration it did not follow, two sources it cannot choose between); M3 to M7 read the consumer's setup or hand-written file and left. Impact LOW (tooling messages, additive), confidence HIGH (ticket 158 names M3 as check mode). Decided.
- Decision 6 (flag properties). Impact LOW for this spec; confidence HIGH (the orchestrator's convention 2 names `--nfs-button-responsive-expanded`). Decided here; the owning specs are other groups' (Finds, item 4).
- Nothing is OPEN FOR HUMAN.

### Finds for the deferred specs (not in the group f manifest, or worth their authors' attention)

1. [Spec: build-time checks (later milestone)](163-spec-build-time-checks-later-milestone.md): the Typography Helpers spec at 53144f3 argued in D9 that "a new compile stop after the first release waits for an Angular major (ADR 0045), so it lands now". Adding the `@error` checks in a later milestone stops compiles that passed before, which ADR 0045 treats as breaking outside an Angular major; the spec should say whether each check lands as an `@warn` first, as an opt-in, or only with an Angular major.
2. Same spec: `nfs-title-bar`, `nfs-top-bar`, and `nfs-typography-base` return there as checks-only mixins (the consumer then adds their includes); the exact-formula Sass helper (`math.pow`) that every contrast check used, and the Top Bar's false-pass test of Foundation's `color-luminance()` (2.94:1 for `#116666` on `#0a0a0a`), also live only there now.
3. Same spec: the Variant declaration tooling's check mode takes M3 to M7, the builder's `check` option and configuration, the CI steps, and the hand-written-file check; the setup summary M13 kept the hint to add `declare global {}` to a kept hand-written file, which reads that file (a boundary call: kept as part of the setup summary).
4. [Spec: Runtime checks (later milestone)](162-spec-runtime-checks-later-milestone.md) and the specs of other groups: the flag-gated Variant properties that only the Runtime check reads (`--nfs-flexbox-responsive-breakpoints` of the Flexbox Utilities, `--nfs-media-object-section` of the Media Object, one per `$prototype-*-breakpoints` flag in the Prototyping Utilities, `--nfs-button-responsive-expanded`) go with the Runtime checks; the Storybook conventions' include comments for `nfs-media-object` and `nfs-flexbox-utilities` name them.
5. [Spec: misuse warnings (later milestone)](161-spec-misuse-warnings-later-milestone.md): the Triggers' check 2 (a target without an `open` method) was the only guard for non-strict templates; without it, such a click throws a `TypeError` in the handler. Strict templates (the Angular default) reject the binding, so the first milestone accepts it; the later spec may add a quiet guard beside the warning.
6. Same spec: the Positioner's three warnings (same-axis alignment, negative offsets, a placed element that is not `position: absolute`) are the Anchored pane spec's own entry, which the group owning `specs/anchored-pane.md` extracts; the Tooltip quote is gone.
7. [Spec: family checks (later milestone)](160-spec-family-checks-later-milestone.md): the Nested menu root's DOM-fallback warning for a menu projected into the Top Bar's right-hand section (D9) is the Nested menu spec's check; the Top Bar spec now documents only `alignment="right"`.
8. The map (orchestrator's): the Out of scope line on base element styles says "the Library mixin of the export mixin that prints it checks it (`nfs-typography-base` ...)"; in the first milestone that colour is a required setting in the Typography Helpers spec and `nfs-typography-base` does not exist.
