# 182. Research: loading and unloading component styles from directives in Angular 22.2

Type: research
Status: open
Blocked by:

## Question

Under the user's ruling of 2026-10-01 (recorded in [Decide: how first-milestone directives load and unload their family styles](185-decide-lazy-family-styles.md)), first-milestone directives manage their family's styles lazily. A directive cannot declare `styles`. Which Angular 22.2, CDK, Angular CLI, and web platform mechanisms let a directive (or the component it sits beside) load its family's CSS when the first instance renders, and remove it when the last instance is destroyed? And what does each mechanism cost? The constraint from [ADR 0012](../adr/0012-sass-packaging.md) stands until the decision ticket says otherwise: Foundation's export mixins read the consumer's settings as Sass globals, so CSS compiled at library build time renders with Foundation's defaults, not the consumer's.

## How to work it

Resolve with a `/research` subagent, against the local clones first (`d:/projects/github/angular/angular` and `d:/projects/github/angular/components` at `22.2.x`). Cover, with `file:line` for each claim:

1. `SharedStylesHost` and `REMOVE_STYLES_ON_COMPONENT_DESTROY` (`packages/platform-browser/src/dom/`): how component styles are reference-counted, when they are removed, and what `ViewEncapsulation.None` changes. Also how styles rendered on the server are reused or removed at hydration (`ng-app-id`, `ng-transfer` and similar), and what happens to them inside `@defer` blocks, incremental hydration, and event replay.
2. CDK's `_CdkPrivateStyleLoader` (`src/cdk/private/style-loader.ts`) and every caller in CDK and Material: why it loads once per application and never unloads, and what a reference-counted variant would need, including removal timed after `animate.leave` finishes.
3. Where the CSS comes from, so the consumer's Foundation settings apply: a component in the consumer's own project whose `styleUrl` the consumer's build compiles (generated by an Nx generator or schematic, like the Variant declaration file of [ADR 0040](../adr/0040-variant-input-types.md)) and registered with the library through a provider; Angular CLI global `styles` entries with `inject: false` and `bundleName`, loaded through a `<link>` the library inserts and removes (SSR, hydration, and the `@angular/build` application builder's output naming); `stylePreprocessorOptions.includePaths` and how a component stylesheet `@import`s the consumer's settings; and anything else the sources show. For each source, say whether the CSS is in the server HTML at first paint, whether it is a separate chunk loaded on demand, and what a consumer writes.
4. Cascade order: CSS that is inserted lazily lands in runtime order, not in Foundation's source order. Does CSS `@layer` (Baseline status on the map's Browser support date, 2026-05-07, checked against its core browser table) let a stylesheet declared once fix the order regardless of insertion order? And how does a layered library rule rank against a consumer's unlayered rule?
5. Prior art outside this repo: how Angular Material, PrimeNG, Taiga UI, and Spartan load styles per component or directive, if they do.

Write `research/lazy-style-loading.md` with the options, the evidence, and the open unknowns. Decide nothing.
