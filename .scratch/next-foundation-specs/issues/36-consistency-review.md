### Audit 0004 items settled here

1. The 24 px `.title-bar .menu-icon` hit area stays in `nfs-responsive-toggle`; it does not move to a shared Library mixin. A title-bar menu icon that opens an Off-canvas panel without ResponsiveToggle meets WCAG 2.5.8 through `@include nfs-responsive-toggle;`, whose no-argument include emits only that hit-area rule plus compile-time title-bar contrast warnings; a `.menu-icon` outside `.title-bar` gets no library hit area, so no example shows one without saying how 2.5.8 is met. Reasons: the user's rule puts custom CSS in the plugin's `nfs-<plugin>` mixin, ADR 0012 names only plugin mixins, `nfs-motion`, and `nfs-breakpoint-properties`, and Title Bar and Menu Icon are CSS-only components outside the destination (map, Out of scope); a shared mixin would add a new kind of public Sass API for one rule. Recorded in building-blocks Table A ResponsiveToggle, Table B OffCanvas, and 1.10, and in the Responsive Toggle, Off-canvas, and Triggers specs (the Triggers and Off-canvas examples now sit the menu icon in a `.title-bar`).
2. Unrecorded departure 6 confirmed: the Off-canvas registration effects (panel to content, overlay to panel) write only the target's registry signal and no DOM, and the reference input can change at runtime, which `ngOnInit` cannot follow; the Triggers' `registerTrigger` and the Responsive Toggle bar do the same, and Aria's `MenuTrigger` runs `effect(() => this.menu()?.parent.set(this))` (checked in the components 22.2.x clone). Building-blocks 1.5 now names the reverse-link registration as the second exception to "no `effect` propagates state between signals", and 1.9 says the `ngOnInit` registration rule is for children found through DI.
3. Unrecorded departure 7 confirmed: Foundation 6.9.0's `tooltip` mixin sets no `display` (the `display: inline-block` is `.has-tip`'s, checked in the clone), so the tip's `hidden` needs no `.is-hidden`. Building-blocks 1.10 now binds `.is-hidden` only when a Foundation rule sets `display` on the hidden element.
4. Unrecorded departure 8 confirmed: Dropdown (D21) and Responsive Toggle bind no consumer Motion class while `reducedMotion()` is true, which also covers consumer keyframe classes without a reduced-motion rule; Reveal and Toggler rely on the `nfs-motion` override and the consumer's own rule. Both paths are allowed: the Breakpoint service spec's consumer rule 3 and building-blocks 1.6 rule 5 now name the exception, and the four specs point at it. Their behaviour is unchanged.

#### Confirmation: `@angular/aria` building blocks not used (1 item)

The repository's `AGENTS.md` asks for confirmation before falling back from an `@angular/aria` building block, and the map's triage rule names such a fallback human-only by kind: the spec applies its choice as the default, its ADR may be accepted, and the consistency review lists every such fallback once. The user confirms or overrules the list as one item.

1. Orbit slides do not host Aria's `TabPanel`: its own `inert` binding turns on in a later server pass, so no binding of the slide can keep `inert` out of server HTML, which ADR 0025 requires (measured in three engines); the slide binds the tab panel contract itself, and the bullets keep Aria `Tabs`, `TabList`, `Tab`. [ADR 0034](../adr/0034-orbit-slide-contract.md); [Re-run: Orbit spec, the slide's ARIA contract and the focus handoff](70-rerun-orbit-slide-contract-and-focus-handoff.md), [Spec: Orbit](33-spec-orbit.md).
2. Orbit offers no Aria `TabContent` for lazy slides: slide content is projected so every slide is in server HTML and reachable without JavaScript. [Spec: Orbit](33-spec-orbit.md).
3. Accordion does not use Aria's `AccordionContent`, even for Lazy content: Aria creates the view in a render callback, so an open panel would be empty in server HTML (ADR 0008), it removes content before the close animation, and its `preserveContent` cannot be forwarded through a second host-directive level. [Spec: Accordion](15-spec-accordion.md).
4. Tabs uses Aria's `TabContent` only behind the opt-in lazy template; by default panel content is projected, for the same server-HTML reason. [Spec: Tabs](16-spec-tabs.md).
5. Responsive Accordion Tabs exposes neither lazy form: sections are created again on every Mode swap and must be in server HTML. [Spec: Responsive Accordion Tabs](19-spec-responsive-accordion-tabs.md).
6. The menus (the Nested menu family behind AccordionMenu, Drilldown, DropdownMenu, and ResponsiveMenu) use neither `ngMenuBar`/`ngMenu` nor `ngTree`: they apply the `menubar`, `menu`, `menuitem`, and `tree` roles that the APG and the Angular Aria guide advise against for site navigation, with a roving tab stop, and their `ng-template` groups and `[parent]` inputs break Foundation's nested `ul`; Drilldown fits neither; Aria's menubar is also horizontal only and renders submenus outside server HTML ([ADR 0004](../adr/0004-menus-use-disclosure-navigation.md)). [Spec: Nested menu (shared utility)](56-spec-nested-menu.md), [Spec: Accordion Menu](20-spec-accordion-menu.md), [Spec: Dropdown Menu](21-spec-dropdown-menu.md), [Spec: Drilldown Menu](22-spec-drilldown-menu.md), [Spec: Responsive Menu](23-spec-responsive-menu.md).
7. Accordion Menu does not use Aria's accordion: it is the APG Accordion pattern for page sections (a `region` per panel, one roving tab stop over the triggers), where disclosure navigation keeps every button and link in the tab sequence; each trigger would also need a required `[panel]` binding. [Spec: Accordion Menu](20-spec-accordion-menu.md).
8. The Dropdown pane does not use Aria's menu: a pane holds arbitrary content, so `role="menu"` would promise menu keys it does not have; it is a disclosure or a non-modal dialog. [Spec: Dropdown](26-spec-dropdown.md).
9. Triggers do not use Aria's `MenuTrigger`: it renders `aria-haspopup="menu"` and menu semantics, wrong for every Openable. [Spec: Triggers (shared utility)](54-spec-triggers.md).

No available Aria pattern was declined elsewhere: `@angular/aria` 22.2 ships accordion, combobox, grid, listbox, menu, tabs, toolbar, and tree, and has nothing for Button, the Breakpoint service, the Anchored pane, Reveal, Off-canvas, Tooltip, Toggler, Responsive Toggle, Slider, Abide, Interchange, Equalizer, Sticky, Smooth Scroll, or Magellan.
