## Question

What is Yeti (`yeti-css`, version `7.0.0-alpha.0` on the upstream `develop` branch, 473 commits after v6.9.0), and what would it mean for this effort to wrap Yeti instead of Foundation for Sites 6.9?

The orchestrator found on 2026-10-01 that the repository's README calls Yeti "the successor to Foundation for Sites". Its stated traits:

- "CSS-first, native, zero-build", with "No Sass";
- one stylesheet, with runtime custom-property tokens;
- cascade layers, container queries, `light-dark()`, `dialog`, and `popover`;
- status `7.0.0-beta`, with class names, attributes, and token names frozen;
- not published to npm, where `foundation-sites` stays at 6.9.0 and keeps publishing 6.x from a `v6` branch.

## User question, 2026-10-01

Make a local clone and explore its readme, what is locked, what might change after v7.0.0-beta, and how that would affect us wrapping v7 instead of v6.9. Determine how much of Yeti is driven by JavaScript, what Angular would bring to the table other than replacing its JavaScript, and how it could better enable lazy-loading of component-specific styles.

## Answer

Resolved 2026-10-01 (Fable 5.1, high effort). Findings: [research/yeti-foundation-7.md](../research/yeti-foundation-7.md). Read from the clone `d:/projects/github/foundation/yeti` at `f52d1e8b9` (its `docs/` matched the docs site on every page compared), issue #15554 and repository metadata through `gh`, the npm registry, and web-features 3.40.1 under `D:/tmp/web-features`. Nothing is decided; whether to change the destination is the user's call.

- **Status (points 1, 6).** Yeti is a rewrite under a renamed repository, not a Foundation 7: `develop` was cleared on 2026-09-12 and refilled with 473 commits by one author over 13 days, the last on 2026-09-25. There is no prerelease to wrap: no `v7*` tag, no release after v6.9.0, `yeti-css` is not on npm, `package.json` says `7.0.0-alpha.0` while the README says `7.0.0-beta`, the install guide says "Yeti is not released yet", and #15554 says "Do not build on it yet". Publishing is a manual git-flow release with no publish workflow; the announcement's `docs/superpowers/` plans exist in no ref. Licence FSL-1.1-MIT (Aspect Services, LLC), MIT two years after each release; whether an Angular wrapper is a "Competing Use" is `OPEN FOR HUMAN`.
- **Locked and movable (point 6).** Frozen from beta: the 49 class names, attribute names and value lists, vocabularies, markers, public token names, the ten module file names and their optionality, event names, the two JSON schemas and `exports`. Not frozen: private `--_yeti-*` tokens (449 names), public token defaults, generated file layout, and "browser support minimums, which track Baseline". The freeze is enforced by `bin/frozen.js` on `develop` with no tagged baseline. A wrapper must bind only `data-*` attributes and public tokens, regenerate its types per release because values may be added, and expect Yeti's floor to move yearly while the map's target moves with the Angular major.
- **Browser support (points 2, 7).** Yeti's floor is "Baseline 2025", about two years above the map's target. Measured: 20 unguarded features are outside the target and six carry components with no fallback: `popover` (dropdown, nav; Firefox 125), invoker commands `commandfor`/`command` (the only way the dialog opens; Chrome 135, Firefox 144, Safari 26.2), `light-dark()` (all 47 colour tokens; Chrome 123, Firefox 120, Safari 17.5), `pow()` (the whole size scale; Chrome 120, widely available 2026-06-07), `:has()` (86 uses; Firefox 121, widely available 2026-06-19), `<details name>` (accordion exclusivity). Also outside, with graceful degrade: `@starting-style`, `transition-behavior`, `content-visibility` and `::details-content` transitions, generated-content alt text, relative colour (66 tone tokens nothing in Yeti reads), `lh`, `:dir()`, unprefixed `mask-image`, `text-wrap`, `scrollbar-width`. Guarded by `@supports` with stated fallbacks: anchor positioning (every Firefox user gets a viewport-centred dropdown), scroll-driven animations, masonry, `interpolate-size`, `field-sizing`. Container style queries and native nesting are not used (measured). Inside the target: container size queries, cascade layers, `<dialog>`, `::backdrop`, `inert`, scroll snap, `color-mix()`, `oklch()`, subgrid, `:user-invalid`, `tan()`/`atan2()`, and the observers.
- **Coverage (point 3).** Of 21 plugins, 9 have a counterpart (Accordion, Dropdown, DropdownMenu one level, Orbit, Reveal, Slider, Sticky, Tabs, Tooltip), 3 partial (OffCanvas as the nav drawer, ResponsiveToggle as the nav toggle, Magellan as `toc.js`), 9 dropped (Abide, AccordionMenu, Drilldown, Equalizer, Interchange, ResponsiveAccordionTabs, ResponsiveMenu, SmoothScroll, Toggler). Every CSS-only component has one (Label and Badge merge, Callout splits into `alert` and `box`). The XY Grid and the utility families are replaced by 17 layout primitives and 7 utilities; margin helpers and the 12-column grid are dropped on purpose; Float Classes and Typography Helpers' classes have none. 49 manifests, most new to Foundation.
- **JavaScript (points 3, 8).** 10 files, 760 lines (304 comments), 37.7 KB, against 69 CSS files, 5,276 lines, 265.6 KB: 12.6% by lines, all optional, no imports, no teardown, delegated on `document`; only tabs needs its module to work. The platform does opening, closing, Escape, light dismiss, focus trapping, exclusivity, snapping, and shape changes. Angular would add typed inputs from the frozen manifest, the class rule (Yeti still has the author write the class, `data-*`, `popovertarget`, `commandfor`, ids, and ARIA names), fallbacks for the six carrying features where a directive can supply one (not `light-dark()` or `pow()`, which need a transpiled sheet Yeti refuses to ship), SSR, hydration, event replay, `@defer`, per-instance signal state and teardown, dynamic content (`tabs.js` and `toc.js` miss elements added later), reactive forms in place of `validate.js`, typed outputs, and the dropped plugins.
- **Styling model (point 4).** 297 public runtime tokens in 39 groups, two themes that are `:root` token blocks, six fixed cascade layers declared first and wrapped around every rule, a 36 KB `attributes.css` mapping shared `data-*` values to private properties, a manifest with a11y, support, and event contracts, and no Sass. This is the "runtime theming through custom properties" the map's Out of scope rules out. Under it ADR 0012 and ADR 0005 are superseded; ADR 0040 keeps only closed types, generated once from `yeti-css/manifest` (vocabularies are closed and frozen, so registries, the declaration file, Variant properties, generator, and the Variant runtime checks lose their object); ADR 0039's Structural, Variant, and State kinds become one identity class, `data-*` attributes, and native or ARIA state.
- **Lazy loading (points 4, 9).** Yeti removes the two obstacles that drove 183, 184, 189, 191, and most of 192: settings (none reach the CSS; every component file is identical for every consumer, so the library can ship or import it with the public toolchain, no Sass plugin, no `buildApplication` extension) and cascade order (`layers.css` and per-file layer blocks; only within-layer ties depend on insertion order, fixable with sub-layers, untested). Companion files are optional by Yeti's design. It leaves the Angular half 182 and 188 measured (the `SharedStylesHost` count, the leave-animation leak, dehydrated instances, Beasties) and adds an always-loaded group (layers, tokens, base, `attributes.css`: 99 KB of 266 KB source) and a limit, no hashed class names.
- **Destination (point 5).** Wrapping Yeti rewrites the destination's object (51 Foundation pages become 49 manifests plus whatever is kept of the dropped plugins), the Domain note, the Sass preference, and the Out of scope line on runtime theming; it forces a decision on the browser target before anything else (keep it and carry fallbacks the map's one-code-path rule forbids, or move to Yeti's floor and leave Angular's); it supersedes ADR 0012 and 0005, reduces 0040, rewrites 0039's kinds, reopens 0002 (Yeti's dropdown, nav, and tooltip stand on `popover` and anchor positioning), and keeps 0003, 0004, 0007, 0045, 0046; every spec's class mapping, Sass subsection, and State bindings would be rewritten against a manifest; the Breakpoint service, Triggers, Anchored pane, Nested menu, Variant declaration tooling, and the Sass-reading check specs lose their basis. The precondition is the first bullet: today there is nothing to pin.
