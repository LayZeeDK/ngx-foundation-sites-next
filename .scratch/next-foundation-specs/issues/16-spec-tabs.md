## Answer

Spec: [specs/tabs.md](../specs/tabs.md).

Gist: Tabs land on `@angular/aria/tabs` through host directives, as the [Prototype: `@angular/aria` Accordion and Tabs under Foundation markup](43-prototype-aria-accordion-tabs.md) proved. The directive set is `[nfsTabsGroup]` (hosts `Tabs`, on any element enclosing strip and content, a Foundation grid row included), `ul[nfsTabs]` (hosts `TabList`: `selected` model by value, `selectionMode`, `wrapOnKeys`, `orientation`, plus the library-owned deep-linking options), `li[nfsTabsTitle]` (`role="presentation"`, `.is-active`), `a[nfsTab]` (hosts `Tab`, required `value`, no `href`), `[nfsTabsPanel]` (a directive hosting `TabPanel`, projected content), and the opt-in `ng-template[nfsTabsLazyContent]`. `.tabs-content` gets no directive. Outputs: `selectedChange` (the model's value), `selectionChange` and `deepLinked` (`{value, tab}`). The selected tab is a tab stop in server HTML because `NfsTab` overrides Aria's `tabindex` binding until Aria sets its first active tab, closing the prototype's pre-hydration keyboard gap. A `keydown` replay guard on the strip keeps replayed keys out of enclosing Aria widgets. `activeCollapse`, `matchHeight` (now a CSS grid recipe), the class-name options, and `deepLinkSmudgeDelay` are dropped. The tabs pattern needs no library CSS; the `nfs-tabs` mixin has one rule for the nav bar's `aria-current` link, and WCAG 2.2 AA contrast comes from two Foundation settings the spec makes required. Self-grilled against the primary sources below; no prototype is needed and, after triage, nothing is left OPEN FOR HUMAN except upstream filings and an assistive-technology check.

### Decision log

Sources are cited as: Aria prototype = [Prototype: `@angular/aria` Accordion and Tabs under Foundation markup](43-prototype-aria-accordion-tabs.md) and its README and source; seam prototype = [Prototype: Rendering-mode test seam](59-prototype-rendering-mode-test-seam.md); Aria source = `src/aria/tabs/*.ts` and `src/aria/private/tabs/tabs.ts`, `src/aria/private/behaviors/list-focus/list-focus.ts`, `event-manager/*.ts` in the 22.2.x components clone; Foundation = `js/foundation.tabs.js` and `scss/components/_tabs.scss` in the 6.9.0 clone; BB = `building-blocks.md`; R:x = the research files.

1. Q: Directive or component for each Foundation element? A: Directives only: `[nfsTabsGroup]`, `ul[nfsTabs]`, `li[nfsTabsTitle]`, `a[nfsTab]`, `[nfsTabsPanel]`, `ng-template[nfsTabsLazyContent]`. Source: ADR 0001; BB 1.1; Aria prototype verdict (`[nfsTabsPanel]` stays a directive: `TabPanel` works without `ngTabContent`, and the only effect is a dev warning a component could not silence either).
2. Q: Is the group wrapper still needed? A: Yes. `TabList` and `TabPanel` both `inject(TABS)` from a common `[ngTabs]` ancestor, and Foundation's `ul.tabs` and `.tabs-content` are siblings. The wrapper can be any consumer element enclosing both, including the `grid-x` row of Foundation's vertical tabs layout, so it costs no markup in that case. Named `NfsTabsGroup` because the element has no Structural class and `NfsTabs` names `.tabs` (BB 1.3). Source: Aria source `tab-list.ts`, `tab-panel.ts`; Foundation `docs/pages/tabs.md` vertical example.
3. Q: `[nfsTabsContent]` on `.tabs-content`? A: No directive. With the group wrapper replacing `data-tabs-content`, the class only styles; the Aria prototype needed none; the foundation-api-design skill lists `.tabs-content` as internal. Source: Aria prototype "Decisions handed to the specs"; foundation-api-design SKILL.md mapping table.
4. Q: `a[nfsTab]` or `button[nfsTab]`, and `href`? A: `a[nfsTab]` only, without `href`; dev warning on `href`. Foundation's `tabs-title` mixin styles only `> a` and keys the selected look on `a[aria-selected='true']`, so a button would need Foundation's declarations copied (user rule: reuse Foundation's Sass). Aria's `ClickEventManager` does not call `preventDefault()`, so an `href="#id"` would jump and rewrite the hash. Proposed ADR `adr/0023-tabs-anchor-tab-hosts.md`. Source: Foundation `_tabs.scss:79-109`; Aria `click-event-manager.ts` (`preventDefault: false`); Aria prototype "What the prototype does not prove" (href).
5. Q: How do tabs pair with panels? A: By equal `value` strings (Aria's pairing); ids only where the URL names a panel. Source: Aria `tabs.ts` `_panelMap`/`_tabMap`; R:di 3d; BB 1.9.
6. Q: How is the selection bound? A: Aria's `selectedTab` model exposed as `selected` (`model()`, string value), two-way through the aliased output `selectedChange`. When unbound, `NfsTabs` writes the first tab's value at content init and after each content check while the model is `undefined` and a tab exists, so server HTML shows a panel and `@for` tabs that arrive later still get a default. Source: Aria prototype case 6 (content-init write, no NG0100) and case 7 (blank without it); BB 1.4.
7. Q: Which outputs? A: `selectedChange` (model output, value, fires also for the first-tab default), `selectionChange` (`{value, tab}`, only on client-side changes after first paint, matching `change.zf.tabs`), `deepLinked` (`{value, tab}`, `deeplink.zf.tabs`). `collapse.zf.tabs` dropped with `activeCollapse`; `init`/`destroyed` have no counterpart. Source: BB 1.4 (model `xChange`; container outputs carry the item; event mapping); R:material 2 (two-tier outputs); Foundation `:278-282`, `:136-141`.
8. Q: Every `Tabs.defaults` option: map or drop? A: `deepLink`, `deepLinkSmudge`, `deepLinkSmudgeOffset`, `updateHistory`, `autoFocus` become library `input()`s with Foundation's defaults; `wrapOnKeys` is Aria's `wrap` aliased (same default `true`); `matchHeight` becomes a documented CSS grid recipe; `activeCollapse` dropped (Aria cannot collapse a selected tab: `ListExpansion.open` returns false when expanded and `multiExpandable` is forced false; the APG requires a rendered panel for the selected tab); `linkClass`, `linkActiveClass`, `panelClass`, `panelActiveClass` dropped (classes are the contract); `deepLinkSmudgeDelay` dropped (browser-owned timing). The option list comes from `Tabs.defaults`, not from the ticket (`activateOnFocus` does not exist). Source: Foundation `:443-549`; R:disclosure Tabs; audit 0001 H6; BB 1.4 dropped-options list; R:apg Tabs.
9. Q: Automatic versus manual activation, and `focusMode`? A: `selectionMode` exposed, default `'follow'` (APG-recommended automatic activation; Foundation was always automatic), `'explicit'` for manual. `focusMode` is not exposed: `activedescendant` keeps focus on the `ul`, so Foundation's `:focus` look on the anchor never applies and a focus indicator would need library CSS (WCAG 2.4.7). Source: Aria `tab-list.ts:99-106`; R:apg Tabs; Foundation `_tabs.scss:102-106`.
10. Q: Disabled tabs? A: Not exposed (`disabled`, `softDisabled`, list `disabled`): Foundation's Sass has no disabled-tab look, and leaving them out keeps the tab-stop rule (item 13) exactly equal to Aria's. Adding them later is not breaking. Source: Foundation `_tabs.scss`; Aria `list-focus.ts` `getItemTabIndex`.
11. Q: Vertical tabs? A: The consumer writes Foundation's `.vertical` on strip and content (Variant classes, ADR 0010) and `orientation="vertical"`; Aria then renders `aria-orientation` and uses Up and Down. The wrapper cannot derive `orientation` from the class, because it cannot set or re-default an Aria input (Aria prototype case 4); a dev warning reports a mismatch. Source: Aria `tabs.ts` pattern `prevKey`/`nextKey`; Aria prototype case 4.
12. Q: Keyboard table? A: Aria's: Left/Right (flipped in RTL through `Directionality`) or Up/Down by orientation, Home/End, Enter/Space, click; horizontal strips leave Up/Down to the page. Deltas from Foundation: Up/Down on horizontal strips dropped, Home/End and RTL added. Source: Aria private `tabs.ts` keydown manager; R:apg Tabs; Foundation `:28-37`.
13. Q: Pre-hydration keyboard gap (every tab `tabindex="-1"` in server HTML)? A: Fixed. `NfsTab` binds `[attr.tabindex]`, which overrides the host directive's binding (the host's bindings apply after its host directives'): Aria's value ("active ? 0 : -1") once the list has an active tab, and "selected ? 0 : -1" before that. Aria sets the active tab only in `setDefaultStateEffect` inside `afterRenderEffect`, and has no public API to set it; with `focusMode` and `disabled` unexposed the override equals Aria's value after hydration, so hydration changes nothing. Hydration does not compare attributes. Verified by the SSR smoke (selected tab `tabindex="0"`) and an e2e Tab-key test with JavaScript disabled. Source: Aria prototype case 10; Aria `tab-list.ts:133-137`, `list-focus.ts`; `directive-composition-api.md` "Directive execution order"; R:rendering 2.
14. Q: Replay behaviour and the replay guard? A: Aria's strip listeners (`click`, `keydown`, `focusin`) give the `ul` `jsaction`; a replayed click selects cleanly (no `preventDefault()` in Aria's click manager); a replayed key changes state, then Aria's trailing `preventDefault()` throws and logs once and skips `stopPropagation()`. `NfsTabs` adds a `keydown` host listener that calls `stopPropagation()` for the keys Aria handles on the current orientation, without modifiers, so tabs inside an Accordion panel do not hand the replayed key to the accordion group (Home, End, Enter, Space are accordion keys too). Source: Aria prototype cases 20-25; R:rendering 4; Aria `keyboard-event-manager.ts:33-35`.
15. Q: Deep links: History API or Router? A: History API, as Foundation: hash names the panel `id` (consumer-supplied, dev warning when generated); read in the first render callback and on `hashchange` (a `window` listener added in an `afterRenderEffect` keyed on `deepLink`); empty hash restores the initial tab; user-driven changes write `replaceState`/`pushState` with the current `history.state` passed through so the Router's bookkeeping survives; hash-driven changes and the first-tab default write nothing. Router consumers who want server-correct state bind `selected` from a query parameter and navigate on `selectedChange` (recipe in the spec). The library does not inject the Router. Source: Foundation `:104-147`, `:270-276`; BB 1.5 ids, 1.11 decision 9; R:rendering 7 rule 8.
16. Q: `deepLinkSmudge`, `deepLinkSmudgeOffset`, `autoFocus`? A: `scrollIntoView({block: 'start', behavior})` on the strip, `behavior` `'instant'` under the Breakpoint service's `reducedMotion()`, else `'smooth'`; the offset is bound as `scroll-margin-top` (null when 0), which also helps WCAG 2.4.11; `autoFocus` scrolls the same way in the first render callback, then `focus({preventScroll: true})` on the selected tab. Source: Foundation `:84-90`, `:131-134`; BB Table A Magellan and SmoothScroll (`scroll-margin-top` for offsets); smooth-scroll spec (`reducedMotion` behaviour).
17. Q: `matchHeight`? A: Dropped as code; the spec documents a consumer CSS grid recipe (all panels in one grid cell, hidden ones `visibility: hidden` and still `inert`). Source: BB Table A Tabs ("CSS grid advice, not code"); Foundation `:382-414` (measurement by forcing panels visible).
18. Q: Lazy content: template or consumer `@defer`? A: Both, documented: projected content by default (server-rendered); `ng-template[nfsTabsLazyContent]` hosting Aria's `TabContent`, with `preserveContent` exposed from `TabPanel`, for client-only content (empty in server HTML because `DeferredContent` creates views in a render callback); a consumer `@defer (when p.visible())` for code splitting, using the exported `visible()`. Queries match host directives, so `TabPanel`'s `contentChild(TabContent)` finds the library directive. Source: ADR 0008; R:rendering 5; R:aria 1.5; Angular `host_directives_spec.ts` "should be able to query for the host directives".
19. Q: `.tabs-content` transition and reduced motion? A: Kept as Foundation's; nothing is added or awaited, panel visibility is `display`, so switches are instant and no reduced-motion override exists; reduced motion only changes smudge and `autoFocus` scrolling. No `animate.enter` (persistent panels). Source: ADR 0003; Foundation `_tabs.scss:120`; BB Table B Tabs.
20. Q: Rendering modes? A: First-paint state is host bindings (including the first-tab default and the tab stop); nothing browser-only runs before the first render callback; clean hydration (prototype case 16); click and key replay as in item 14; one hydration boundary for group, strip, and panels; `hydrate never` keeps only the selected panel usable; prerendering equals SSR. Source: ADR 0008; R:rendering 7 rules 1-11 and the Tabs checklist row; Aria prototype cases 8, 9, 16.
21. Q: Defaults token? A: `nfsTabsDefaultsToken` (Shape B) with only the library-owned options; Aria-owned inputs cannot be re-defaulted by a wrapper. Source: BB 1.4; Aria prototype case 4.
22. Q: Nav-bar dual role with `aria-current`? A: No directive: links in Foundation's tabs markup with `aria-current="page"` (`RouterLinkActive` with `ariaCurrentWhenActive`, `routerLinkActive="is-active"` on the `li`), no tab roles. Foundation styles the selected look only through `aria-selected`, which a link must not carry, so the `nfs-tabs` Library mixin adds one rule, `.tabs-title > a[aria-current]:not([aria-current='false'])`, with `$tab-background-active` and `$tab-active-color`. Source: R:material 2 (nav bar switches roles by `tabPanel`); R:apg Tabs (`aria-current` not a substitute for `aria-selected`); Foundation `_tabs.scss:102-106`; BB 1.13.
23. Q: Selected-tab contrast (the prototype's 3.75:1 finding) and the other WCAG 2.2 AA criteria? A: Compiled Foundation 6.9's settings with Dart Sass and computed ratios: defaults give selected and focused text 3.76:1 (fails 1.4.3) and a selected background 1.24:1 against its unselected neighbours (fails the 1.4.11 state-indicator reading); the text-only fix `$tab-active-color: scale-color($primary-color, $lightness: -14%)` gives 4.78:1 text but leaves 1.24:1. Required settings: `$tab-background-active: $primary-color; $tab-active-color: $white;` give 4.65:1 for both; inactive text 4.65:1 and hover 5.92:1 under the defaults. (Foundation has no `$tab-item-color`; the text setting is `$tab-color`.) The library's Storybook compiles with them, axe `color-contrast` enforces 1.4.3, and a play function asserts 3:1 between selected and unselected tab backgrounds. `.tabs.primary` is documented as needing its own `$tab-background-active`. 2.5.8: default padding gives about 52 px; `.simple` relies on the spacing exception; axe `target-size` gates it. 2.4.7: Foundation's `:focus` background plus the untouched browser outline. 2.4.11: in-flow tabs, `scroll-margin-top` from the offset. 4.1.2: Aria roles and states, `role="presentation"` on titles, dev warning for an unnamed tab list. 2.1.1: item 13. Source: the coordinator's WCAG 2.2 AA instruction; Aria prototype case 18; WCAG 2.2 Understanding 1.4.11 ("any visual information necessary to indicate state, such as whether a component is selected ... 3:1"); Foundation `_tabs.scss` settings.
24. Q: Custom CSS list? A: None for the tabs pattern (Foundation's `.tabs-panel.is-active` and `a[aria-selected='true']` cover it, Aria prototype); one nav-bar rule in `nfs-tabs` (item 22). Source: Aria prototype "Custom CSS"; ADR 0012.
25. Q: Testing seams? A: The four layers with story ids `tabs--default`, `tabs--bound-selection`, `tabs--explicit-selection`, `tabs--vertical`, `tabs--no-wrap`, `tabs--rtl`, `tabs--dynamic-tabs`, `tabs--deep-link`, `tabs--lazy-content`, `tabs--equal-heights`, `tabs--nav-bar`; axe through addon-a11y with the six tags of the decision's `preview.ts` rule set (`wcag2a` to `wcag22aa` plus `best-practice`); browser-level tests on TestBed in Vitest browser mode under `@nx/angular:unit-test`, with the layer wording taken verbatim from the resolved browser testing stack decision; `tabs.ssr.spec.ts` through the shared `renderServer()` helper; Playwright e2e on the static Storybook build (real keys, deep links, reduced motion) and the prerendered fixture app (JavaScript disabled Tab key, hydration, held-back-bundle click and key replay, nested-in-accordion replay, Router history, `hydrate on interaction`, `hydrate never`). Source: BB 1.12; seam prototype "Decision handed on"; [Decide the browser testing stack: Playwright component tests, Vitest Browser, or both](41-browser-testing-stack-decision.md).
26. Q: Is `NfsTabsTitle` still needed? A: Yes: `role="presentation"` on the `li` (a `listitem` between `tablist` and `tab` breaks the required-children rule) and Foundation's `.is-active` State class, read from its child with `contentChild(NfsTab)`; `NfsTab` warns in dev mode when its parent lacks it. Source: R:apg hiding-semantics practice; Aria prototype case 9.
27. Q: Why a content query in `NfsTabs`? A: The first-tab default must run during the server render, where Aria's DOM-ordered collection (a `MutationObserver` started in `afterNextRender`) is idle; tabs inside one `ul` have template order equal to DOM order. BB 1.9 otherwise keeps queries for validation. Source: Aria `tabs.ts`, `tab-list.ts` `afterNextRender`; Aria prototype source.

## Prototype needed

None. Every mechanism the spec relies on was proven by the Aria prototype or the seam prototype, or follows from documented Angular behaviour (host-directive binding order, queries matching host directives); the remaining risks (the tab-stop override, the Router history case, the nested-in-accordion replay guard for tabs) are asserted by the SSR smoke and the e2e cases the spec lists.

### Proposed glossary terms

**Tab group**:
The element that encloses one tab list and all of its panels, which the library requires as their common ancestor because Foundation writes the tab strip and the content box as siblings.
_Avoid_: tabs container, tabs wrapper, tab set (for the element)

### Proposed ADR

- [`adr/0023-tabs-anchor-tab-hosts.md`](../adr/0023-tabs-anchor-tab-hosts.md): Tabs keep Foundation's `<a>` as the tab element, written without `href`. Hard to reverse (consumer markup), surprising against the native-elements-first rule and the APG's button examples, and the result of a trade-off against copying Foundation's Sass.
