## Answer

Spec: [specs/magellan.md](../specs/magellan.md). Resolved 2026-09-26 by self-grilling (AFK), both sides played against the sources below.

Gist: one attribute directive, `NfsMagellan` (`[nfsMagellan]`, `exportAs: 'nfsMagellan'`), on the link container where Foundation puts `data-magellan` (the `ul.menu` inside a `nav`, or the `nav`). It composes `NfsSmoothScroll` through `hostDirectives`, so link clicks scroll (instant under reduced motion), focus the section, keep the URL, and call `preventDefault()` last, as the Smooth Scroll spec defines. There is no target directive: the links' fragments name the sections, found by id (proposed ADR). Tracking is an `IntersectionObserver` with a 1 px band at the Activation line (`scroll-padding-top` of the scroll container + the section's `scroll-margin-top` + `threshold`, default 50), rooted on the sections' real scroll container (an element, or the `Document`), recomputing the Current section from live rectangles (last section past its line; the last one at the scroll end; `null` before the first), with a passive scroll listener whose 100 ms idle timer is the backstop and ends the click "transition". The `active` model (section id or `null`) replaces `update.zf.magellan` with `activeChange`; a consumer write scrolls there without focus; `scrollTo(id, {focus})` is the method. The marker is `.is-active` on the link and on its parent `li` (so Foundation's Menu paints it) plus `aria-current` (`ariaCurrentWhenActive`, default `true`), written with `Renderer2` after render. `deepLinking` writes `replaceState` (or `pushState` with `updateHistory`) with `history.state` passed through and scrolls to a load-time fragment without focus; no `hashchange` listener. Dropped: `animationDuration`, `animationEasing`, `activeClass`, `calcPoints`, `reflow`, the container id; `offset` becomes CSS. No library CSS. Implementation level: native platform, plus CDK `ViewportRuler` (and `InteractivityChecker` through Smooth Scroll).

### Decision log

Sources: FS = the Foundation 6.9.0 clone (`js/foundation.magellan.js`, `docs/pages/magellan.md`, `docs/pages/menu.md`, `scss/components/_menu.scss`, `test/visual/magellan/*.html`); NG = the Angular 22.2.x clone; NGC = the components 22.2.x clone; BCD = browser-compat-data `api/IntersectionObserver.json` (main, fetched 2026-09-26); R:x = research files by the short names `building-blocks.md` uses; BB = `building-blocks.md`; SS = the [Spec: Smooth Scroll](29-spec-smooth-scroll.md) and its spec; Tabs = the [Spec: Tabs](16-spec-tabs.md) spec; Sticky = the [Spec: Sticky](28-spec-sticky.md) and the [Prototype: CSS `position: sticky` with IntersectionObserver sentinels for Sticky](48-prototype-sticky-css.md); Stack = the [Decide the browser testing stack: Playwright component tests, Vitest Browser, or both](41-browser-testing-stack-decision.md) answer.

Round 1 (no prerequisites): what Foundation does.

1. **What are Magellan's options, events, and methods?** `Magellan.defaults` has seven options: `animationDuration: 500`, `animationEasing: 'linear'`, `threshold: 50`, `activeClass: 'is-active'`, `deepLinking: false`, `updateHistory: false`, `offset: 0`. The ticket's `barOffset` does not exist (audit H6); FS's own visual test `active-item.html` still carries a dead `data-bar-offset`. Events: `init`, `update.zf.magellan` `[$active]` (only when the active link changes), `destroyed`. Methods: `calcPoints`, `scrollToLoc`, `reflow`, `destroy`. Source: FS `js/foundation.magellan.js:24-286`; R:positioned Magellan 3-5; `foundation.d.ts:208-222`.
2. **How does Foundation choose the active link?** On debounced window scroll: none before `points[0] - offset - (up ? threshold : 0)`; the last point when `scrollY + winHeight === docHeight`; else the last point with `point - offset - (up ? threshold : 0) <= scrollY`, where `point = offset().top - threshold`. Targets are every `[data-magellan-target]` in the document; the link is matched by `href="#" + target value`. Source: FS `js/foundation.magellan.js:60-75, 152-212`.
3. **Where does the class land, and does Foundation's CSS style it?** On the `<a>` (`$active.addClass`). Foundation's Menu styles the active state on the list item: `.menu .is-active > a { @include menu-state-active; }`, and the Menu docs say "Add the class `.is-active` to any `<li>` to create an active state"; Dropdown Menu styles `li.is-active > a`. So Magellan's marker is invisible in a Menu without custom CSS, which FS's own Magellan visual tests add (`.is-active{background:#A1D4E9;...}`). Source: FS `scss/components/_menu.scss:382-385, 477-480`; `docs/pages/menu.md:235`; `test/visual/magellan/active-item.html`; R:positioned Magellan 2.
4. **What does Foundation do with the URL?** With `deepLinking`: `replaceState({}, '', url)` or `pushState` with `updateHistory`, `url` = `#id` or `pathname + search` above the first section; on `window.load` (bound with `one('load')`, which never fires when the plugin starts after load) and on `hashchange` it calls `scrollToLoc(location.hash)`; `destroy` calls `location.hash.replace(...)`, a no-op. The docs name the option `data-deep-link`, which jQuery maps to `deepLink`, not the `deepLinking` key. Source: FS `js/foundation.magellan.js:84-113, 191-203, 222-225`; `docs/pages/magellan.md` Browser History; R:positioned Magellan 3.
5. **What ARIA and focus does Foundation give?** None: no `aria-current`, no focus move after the animated scroll (the native jump that would move focus is prevented). Source: R:positioned Magellan 6; R:apg Magellan.

Round 2 (depends on 1-5): structure, targets, composition.

6. **Directive or component, and on which element?** One directive, `[nfsMagellan]`, on the link container, Foundation's placement. The BB sketch `nav[nfsMagellan]` is not the selector: Foundation puts `data-magellan` on the `ul.menu`, and a `nav`-only selector would silently not match; the `nav` landmark is required markup checked by a development warning instead. Source: FS docs; BB 1.1, 1.3, Table A; ADR 0001; R:apg Magellan (navigation landmark).
7. **How do targets register?** They do not: the links' fragments name the sections, resolved by id into an id-keyed map; missing or disconnected sections are re-resolved after each application render (`afterEveryRender`). Reasons: sections are siblings of the navigation, so DI cannot connect them; sections in dehydrated or `hydrate never` blocks never construct a directive, yet an observer can watch their server-rendered elements; Foundation's attribute only repeated the id; a root id registry is what ADR 0013 rejected. Proposed ADR. Source: BB 1.9, 1.11 decisions 6-7; ADR 0013; R:rendering 7; R:material 9 (id-keyed parent).
8. **Compose Smooth Scroll how?** `hostDirectives: [NfsSmoothScroll]`, no forwarded inputs or outputs (it has none). Host directives execute constructor, lifecycle hooks, and bindings before their host, so Smooth Scroll's click listener runs first; Angular runs each host listener with its own error handling (`executeListenerWithErrorHandling`), so Smooth Scroll's replay error does not skip Magellan's listener. Source: SS spec (API, Hierarchy), ADR 0017 Consequences; NG `adev/src/content/guide/directives/directive-composition-api.md:107-109`; NG `packages/core/src/render3/view/listeners.ts:46-93`.
9. **How does Magellan learn that a click started a scroll (Foundation's `_inTransition`)?** Its own `click` host listener: for a primary, unmodified click on a tracked link (no `download`, no foreign `target`), set `active` and start the transition; no `preventDefault()`, no `defaultPrevented` check. Every such click ends at that section (Smooth Scroll's scroll, or, when a `RouterLink` owned it, the Router's anchor scroll to the same fragment); if nothing scrolls, the idle end (decision 13) restores the truth. Rejected: a hook from `NfsSmoothScroll` reporting started scrolls (changes a published spec's API and is a start event, which BB 1.4 rules out); inferring from focus (indirect). Source: SS click order steps 1-6; BB 1.4, 1.11 decision 5.
10. **Which links count?** In-page `a[href]` descendants of the host, by Smooth Scroll's in-page rule and target resolution (one library-internal function), so Router-safe `/path#id` hrefs and `routerLink` + `fragment` links are tracked; links in any order and several links per section are fine (FS `test/visual/magellan/unordered-links.html`). Source: SS decisions 14-15; FS visual test.

Round 3 (depends on 6-10): tracking.

11. **IntersectionObserver or scroll-position maths?** Observer with a 1 px band at the Activation line (`rootMargin: -{line}px 0px -{rootHeight - line - 1}px 0px`, `threshold: [0]`), rebuilt when the root's height, `threshold`, or the target set changes; each callback recomputes from live `getBoundingClientRect()` reads. It reports top and bottom crossings, including layout-only shifts, with no per-frame work; per-frame maths would interleave layout reads with the library's own class writes and miss layout-only changes. A passive scroll listener with a 100 ms idle timer is the backstop for crossings the band cannot see (an instantaneous jump into a gap; a short last section at the scroll end), the pattern the Sticky prototype settled on. Source: R:platform 10 (Baseline 2019, widely 2021); R:positioned Magellan 9; Sticky prototype verdict (observer plus scroll backstop); BB Table A Magellan.
12. **Observer root?** The nearest scrolling ancestor of the first target, or the owning `Document`; never the implicit root, which inside an iframe (Storybook's canvas) is the top-level viewport. Document roots: Chromium 81, Gecko 76, Safari 14, inside the Browser target. Targets in another scroll container get a development warning. Source: BCD `options_root_parameter_Document`; IntersectionObserver spec (implicit root is the top-level browsing context's document); BB 1.2.
13. **The "in transition" flag without `scrollend`?** Started by a tracked-link click, `scrollTo`, a consumer write to `active`, and the first-render deep link; observer updates are ignored while it lasts; it ends at the first 100 ms without a `scroll` event counted from its start, then recomputes. This covers smooth, instant, unmoving, Router-owned, and user-interrupted scrolls. Rejected: ending when the target reaches its line (a short last section never does; a Router without anchor scrolling never scrolls). Source: R:platform 9 (`scrollend` Safari 26.2; "a debounced `scroll` listener" as the pre-`scrollend` route); FS `_inTransition`; SS Animation ("no completion signal").
14. **Activation line and `offset`?** A section is reached when its top is at most `scroll-padding-top` (resolved; percent against the scrollport; `auto` = 0) + its own `scroll-margin-top` + `threshold` below the scroll container's top: exactly `threshold` below where native and directive jumps land it. `offset` becomes that CSS (SS decision 17: the stopping point is CSS); the band uses the shared part, the recomputation the per-section value. Source: SS decisions 17, 28 (2.4.11); FS `threshold` meaning.
15. **Which section is current when several are visible?** The last in document order past its own line; at the scroll end (`scrollTop + clientHeight >= scrollHeight - 1`) the last target (Foundation's bottom rule); `null` before the first (FS `active-item.html`: "Navigation items should be inactive until first anchor point"). Foundation's direction-dependent threshold doubling is dropped: the same position should mean the same section. Source: FS `_updateActive`; FS visual test.
16. **Links and sections that appear later?** `afterEveryRender` (read phase) re-reads the host's links and re-resolves unresolved or disconnected fragments; changes re-observe and recompute. Ceiling: one query plus one lookup per unresolved fragment per application render. Source: NG `afterEveryRender`; BB 1.5.

Round 4 (depends on 11-16): state, API, marker.

17. **`active`: model or read-only?** `model<string | null>(null)`, as BB 1.4 names it. A consumer write requests that section: Magellan scrolls there with `focus: false` (a model write is not a link activation); unknown ids warn and mark nothing; tracking and click updates never scroll, detected by comparing with a private "last published" signal in an `afterRenderEffect` (browser-only). Makes `[(active)]` useful for a jump `<select>`. Source: BB 1.4; R:material 9 (`matSortActive`, "`active = model<string>()` on the container is the signal form").
18. **Outputs?** `activeChange` (the model's), the counterpart of `update.zf.magellan` (BB 1.4 mapping), with the id instead of the jQuery link. No Completion output (nothing animates). Source: BB 1.4.
19. **Methods?** `scrollTo(target: string, options?: {focus?: boolean}): boolean` (fragment with or without `#`; `false` for an untracked fragment; sets `active`, starts the transition, delegates to `NfsSmoothScroll.scrollTo`). `calcPoints` and `reflow` dropped (the observer sees layout). A host directive's methods are not reachable through the host's `exportAs`, so Magellan needs its own. Source: FS methods; SS D10.
20. **Where does `.is-active` go?** On every link of the Current section (Magellan's contract, for bare-link navigations and consumers' `a.is-active` CSS) and on each such link's parent when that parent is an `li` (Foundation Menu's documented active state, so the marker shows with no library CSS). Link only would need a library rule re-applying `menu-state-active`; list item only would break bare-link navigations and existing CSS. Source: decision 3; BB 1.13 (reuse Foundation's Sass); AGENTS.md Styling Guidelines.
21. **Host bindings or `Renderer2`?** `Renderer2` in an `afterRenderEffect` write phase: the links are consumer elements found by query (Smooth Scroll's delegation shape), and there is no first-paint value (the server cannot know the scroll position, R:rendering 7 checklist); `RouterLinkActive` writes classes and `aria-current` the same way. Removed on destroy. Source: BB 1.5; NG `packages/router/src/directives/router_link_active.ts:230-250`.
22. **`aria-current` token?** `ariaCurrentWhenActive` input, `true | 'location' | 'step'`, default `true` (the attribute string `"true"` maps to `true`), the name and meaning of `RouterLinkActive.ariaCurrentWhenActive`. `true` inherits the BB triage (DECIDED, `true`); the input lets a step list or map-like navigation pick a more specific token; `false` and `page` are excluded. Source: BB ticket triage item 1; R:apg Magellan; NG `router_link_active.ts:148`.
23. **Defaults token?** `nfsMagellanDefaultsToken` with optional `threshold`, `deepLinking`, `updateHistory`, `ariaCurrentWhenActive`, seeding input defaults (Material shape B). No Parent token: nothing injects one. Source: BB 1.4, 1.9.

Round 5 (depends on 17-23): URL and the Router.

24. **History API or the Router for `deepLinking`?** The History API directly, as the Tabs spec does: `replaceState(history.state, '', pathname + search + '#id')`, `pushState` with the same arguments for `updateHistory`, `pathname + search` for `null`; written in an `afterRenderEffect` when a tracking or click change differs from the URL's fragment, never at first render, during a transition, when off, or on destroy. Passing `history.state` through keeps the Router's navigation id and page id; `replaceState` fires no `popstate`. Rejected: Foundation's `{}` state (erases the Router's state); Angular's `Location` service (would diverge from Tabs for no gain in the supported strategy). Source: Tabs spec deep-link rule 3; SS decision 20; NG `statemanager/state_manager.ts`; BB 1.5, 1.11 decision 9.
25. **The URL-fragment question the Smooth Scroll spec handed over?** Answered by ownership: plain Smooth Scroll jumps never write the URL (SS triage: DECIDED), and Magellan writes it only through `deepLinking` (default off, Foundation parity), following the Current section after a click has settled rather than per click. Source: SS triage item 1; FS defaults.
26. **Fragment at load, and `hashchange`?** At first render with `deepLinking`, a fragment naming a tracked section is scrolled to with `focus: false` (a no-op in a server-rendered page, where the browser jumped while parsing; the jump itself in a client-rendered one). No focus because a programmatic focus of a whole section at load paints a ring the native jump does not. No `hashchange` listener: address-bar edits and Back/Forward over Magellan's entries are native fragment navigations or traversals that already scroll and restore; a listener would scroll twice. Source: WHATWG scroll to the fragment (via SS decision 2); FS `hashchange` handler.
27. **`updateHistory` with the Router?** Kept for Foundation parity. With the Router's scroll restoration on (which sets `history.scrollRestoration` to `manual`), a Back press over Magellan's pushed entries is a Router popstate navigation that restores the position stored for the copied navigation id, not the section's; documented as for pages without the Router's scroll restoration, guarded in e2e, and graduated as Prototype needed. Source reading: NG `router_scroller.ts:84-159`, `state_manager.ts:192-218`; SS decision 5.
28. **Restore the URL on destroy (BB 1.9)?** No, a recorded exception: rewriting history while a route is torn down would corrupt the Router's navigation, and Foundation's attempt was a no-op. Source: BB 1.9; FS `_destroy`.
29. **Router coexistence rules?** `routerLink` + `fragment` links tracked and marked, clicks the Router's; no `routerLinkActive` on Magellan links (both write `.is-active`); the Smooth Scroll rules for anchor scrolling, `setOffset`, and native jumps under scroll restoration apply; Magellan inherits the open [Prototype: Smooth Scroll under Router scroll restoration and replay](62-prototype-smooth-scroll-router-restoration.md) default (the Router undoes unhandled native jumps; the replayed handler runs last in a dehydrated block). Source: SS Comparison rules 1-4 and its Prototype needed.

Round 6 (depends on 11-29): rendering modes, CSS, tests.

30. **Server output and hydration?** No host bindings: server HTML is the markup plus `jsaction="click:;"` on the container; no marker; hydration changes nothing; the marker appears after the observer's first callback. Source: ADR 0008; R:rendering 7 rules 1, 10, checklist Magellan row.
31. **Replay and `preventDefault()` ordering?** Smooth Scroll's listener keeps its order (scroll, focus, `preventDefault()` last, only when not already prevented); on a replay after a native jump its scroll is a no-op and its error is logged (audit M12 wording, BB Part 4 item 3 DECIDED); Magellan's listener runs regardless and adds no error. Dehydrated navigation: the `jsaction` is on the container, so the dispatcher does not cancel the native jump. Source: `audits/0002-building-blocks.md` M12; BB triage item 3; NG `dispatcher.ts` (via SS decision 7).
32. **Targets and `@defer`?** Tracked anywhere, including dehydrated and `hydrate never` blocks (observed, never written); a plain `@defer` target is picked up when it renders; the container and links share one boundary; `hydrate never` around the navigation leaves native links and no marker. Timers and the scroll listener outside the zone. Source: BB 1.11 decisions 4, 6, 7; decision 7.
33. **Animation and reduced motion?** Browser-owned through `NfsSmoothScroll` (`'instant'` under `NfsMediaQuery.reducedMotion`); the marker switches with no transition; the idle timer is settle detection, not animation. Source: SS Animation; BP `reducedMotion`; map Animation rule.
34. **Custom CSS?** None: the list-item placement reaches Foundation's Menu style; the offset is the consumer's scroll padding. Sass subsection per the rule in [Sass packaging for the new library](57-sass-packaging.md) and ADR 0012 ("No library CSS; there is no `nfs-magellan` mixin"). Source: BB 1.13; ADR 0012.
35. **Material comparison?** `MatSort`: active id, id-keyed map, change output, defaults token; its `LiveAnnouncer` advice is not adopted (announcing reading position during scrolling would be noise). Source: R:material 9.
36. **Testing seams?** Story ids `magellan--menu`, `--sticky-top-bar`, `--table-of-contents`, `--scroll-container`, `--unordered-links`, `--custom-nav`, `--threshold`, `--jump-select`, `--programmatic`, `--deep-linking`, `--router-link-fragment`; the four layers with the Stack's verbatim wording (story play functions through `npx nx test-storybook <lib>`; Vitest browser mode through `npx nx test <lib>`; the SSR smoke in the same run through `renderServer()`; Playwright e2e on the static Storybook build and the prerendered fixture app, including hash and History cases and pre-hydration clicks). Source: Stack answer, wording section; BB 1.12; ADR 0018.

### OPEN FOR HUMAN

1. Assistive-technology check (human-only by kind): confirm with NVDA, JAWS, and VoiceOver that the Current section's link reads as current (with `true`, and with `location` for comparison) and that `aria-current` moving during scrolling produces no announcements while the user reads the content. ## Prototype needed

- Question: in a hydrated Angular 22.2 application with `provideRouter(routes, withInMemoryScrolling({scrollPositionRestoration: 'enabled'}))` (and again with `'top'` and `'disabled'`), on a route with an `nfsMagellan` navigation using `deepLinking` and `updateHistory`, what happens on Back and Forward after the reader has scrolled through two sections (two pushed same-document entries carrying a copy of the current `history.state`)? Where does the page end, which section is marked, does the Router log a navigation error or cancel, and does `canceledNavigationResolution: 'computed'` misbehave with the duplicated page id? And with `replaceState` only (no `updateHistory`), does a later Router navigation away and Back restore the route and scroll position without error? Measure in Chromium, Firefox, and WebKit.
- Why only running code settles it: the source reading (decision 27) predicts the Router's popstate scroll restores the position stored for the copied navigation id, but the order against the browser's own traversal and the Router's `setTimeout` plus frame scheduling differs per engine, and the page-id arithmetic is exercised only on cancellation.
- Default assumed in the spec: `replaceState` with `history.state` passed through is safe with every restoration mode; `updateHistory` restores wrong positions on Back when the Router's scroll restoration is on, so it is documented for pages without it, and the e2e suite records the outcome as a regression guard.

### Proposed glossary terms

- **Current section**:
  The section a Magellan navigation marks as the one the reader is in, at most one per navigation; its links carry `.is-active` and `aria-current`, and Magellan's `active` holds its id.
  _Avoid_: active target, active link (the link is marked; the section is current), scroll-spy item
- **Activation line**:
  The line, `threshold` pixels below where a section lands when scrolled to, that the section's top edge must pass for it to become the Current section; the replacement for Foundation's Magellan "points".
  _Avoid_: threshold (the Option), marker, point, trigger line

Both are specific to this library's Magellan and are used by the spec, its tests, and any later reader of the tracking rule; neither is a general web term.

### Proposed ADR

`adr/0029-magellan-targets-from-links.md`: "Magellan finds its sections from its links' fragments; there is no target directive". It meets the bar: hard to reverse (consumer markup and the public directive set), surprising (Foundation's `data-magellan-target`, the BB sketch of `[nfsMagellanTarget]`, and Material's registering sort headers all point the other way), and the result of a real trade-off (typed references, a registry, and a document-wide observer were each viable and rejected for stated reasons).
