## Question

What is the Angular design for Foundation's Dropdown plugin in the next library, and what does its spec say?

The result must be the best combination of: Foundation for Sites SCSS and the plugin's features; the ARIA APG pattern and WAI-ARIA; WHATWG HTML and HTML5+ platform features; Angular Aria; Angular CDK; Angular Material-equivalent accessibility and Material-equivalent component API (inputs, outputs, public properties and methods, content and view projection) for the similar Material component; and the modern DI patterns recorded in `research/di-and-composition-patterns.md` (lightweight injection tokens, host-scoped providers, host directives, parent tokens, default-options tokens). One plugin may yield several related directives or components (for example a container plus items plus a lazy-content directive); the spec covers the whole set.

## WCAG 2.2 AA guard (user decision, 2026-09-26)

Every directive and component complies with WCAG 2.2 AA; see the map's Accessibility preference and [ADR 0022](../adr/0022-wcag-2-2-aa-enforcement.md). The spec carries a criteria subsection under Implementation Decisions naming the 2.2 AA criteria this plugin touches (at least 1.4.3, 1.4.11, 2.4.7, 2.4.11, 2.5.8, 4.1.2, and, for overlays and hover content, 1.4.13) and how each is met, as requirements, never recommendations. Where a Foundation default fails a criterion, the spec states the Sass settings the consumer must set or the smallest custom rule the `nfs-<plugin>` mixin adds, with the reason. The story axe gate runs with the WCAG 2.2 AA tags, and the decision log records each criterion addressed.

## Note from the research repairs (2026-09-25)

Audit 0001 finding H5 corrected the Foundation facts in `research/angular-material-reference.md` that this ticket reads. Take these as given:

- `data-position` and `data-alignment` have no CSS side: the legacy `.top/.right/.bottom/.left` classes and the `has-position-*`/`has-alignment-*` classes carry no Sass rule on `.dropdown-pane` (`scss/components/_dropdown.scss`). ## Answer

Spec: [specs/dropdown.md](../specs/dropdown.md). Resolved 2026-09-26 by self-grilling (AFK), both sides played against the sources below, under the user's WCAG 2.2 AA rule and the triage rule for human-only items.

Gist: one attribute directive, `NfsDropdownPane` (`[nfsDropdownPane]`, `exportAs: 'nfsDropdownPane'`), on the consumer's `.dropdown-pane`, entry point `ngx-foundation-sites/dropdown-pane`. It is an Openable (`isOpen` model, `id`, `triggerRole` from a `role` input typed `'dialog' | null`, `open(trigger?)`, `close(result?)` with the result ignored, `toggle(trigger?)`, `registerTrigger`), provides only `nfsOpenableToken`, and binds `.dropdown-pane`, `.is-open`, and the `has-position-*`/`has-alignment-*` classes from the Positioner's Placement. Every positional Option maps unchanged onto `nfsPositioner()` (`parentClass` to its `boundary`), `closeOnClick` onto Light dismiss's pointer rule (group `'nfs-dropdown-pane'`), and `hover`/`hoverDelay` onto `nfsHoverIntent()` with the pane always in the Hover region, so `hoverPane` is dropped (its `false` default fails 1.4.13); `forceFollow` is dropped too. `autoFocus` uses CDK's first-tabbable rule and `trapFocus` uses CDK `FocusTrap`, valid only with `role="dialog"`; neither acts on hover opens or the first-paint state, and both CDK services are resolved from the `Injector` on first need. Outputs: `isOpenChange`, `opened`, and `closed` with the reason `'click' | 'keydown' | 'tab' | 'sibling' | undefined`, both Completion outputs after an optional `animate` keyframe phase on the kept `.is-open` State class with the measured completion timer; no Motion class under `reducedMotion()`. Plus `reposition()` and a read-only `placement` signal. No library CSS: WCAG 1.4.10 at 320 CSS px is met by required Foundation settings (`$dropdown-width: min(300px, 45vw)` and capped `$dropdown-sizes`), and the `nfs-dropdown-pane` mixin holds only a compile-time warning. No `injectAsync`, no `effect`, no `afterEveryRender`.

### Decision log

Sources: FS = the Foundation 6.9.0 clone (`js/foundation.dropdown.js`, `js/foundation.positionable.js`, `scss/components/_dropdown.scss`, `docs/pages/dropdown.md`); NGC = the components 22.2.x clone (`src/cdk/a11y`); APG = the aria-practices clone; R:x = the research files by the short names `building-blocks.md` uses; BB = `building-blocks.md`; AP = [Spec: Anchored pane (shared utility)](55-spec-anchored-pane.md) and `specs/anchored-pane.md`; TRG = [Spec: Triggers (shared utility)](54-spec-triggers.md) and `specs/triggers.md`; TOG = [Spec: Toggler](17-spec-toggler.md); RT = [Spec: Responsive Toggle](24-spec-responsive-toggle.md); BPS = [Spec: Breakpoint service (shared utility)](53-spec-breakpoint-service.md); P44 = [Prototype: Anchored pane positioning, measured Positionable port versus CDK Overlay](44-prototype-anchored-pane.md); P47 = [Prototype: `animate.enter` and `animate.leave` with Motion UI transition classes](47-prototype-motion-ui-animate-enter.md); WCAG = WCAG 2.2 AA as the user's rule names it.

Round 1: what Foundation does and what is settled.

1. **Which Options exist?** `Dropdown.defaults` has 14: `parentClass`, `hoverDelay` (250), `hover`, `hoverPane`, `vOffset`, `hOffset`, `position`, `alignment`, `allowOverlap`, `allowBottomOverlap` (true), `trapFocus`, `autoFocus`, `closeOnClick`, `forceFollow` (true). `allowGroupedOpen` does not exist (audit 0001 H6). Events `show.zf.dropdown`, `hide.zf.dropdown`, `closeme.zf.dropdown`; methods `open`, `close`, `toggle`. Source: FS `foundation.dropdown.js:332-433`; R:positioned Dropdown 3 to 5.
2. **What do BB, ADRs, AP, TRG settle?** Directive on the in-place pane (BB Table A, ADR 0001); custom Angular with platform measurement, no popover or anchor positioning, no CDK Overlay (ADR 0002 as amended by AP); Light dismiss model (ADR 0024); the Openable contract and Trigger roles (ADR 0013); State class animation (ADR 0003, BB 1.6 rule 1); rendering-modes contract (ADR 0008). The Positioner, Light dismiss, and hover intent are used exactly as AP defines them.
3. **Dead keyboard code?** Enter and Space are registered as `toggle`, which the handler never defines; only the button's native `click` works (FS `foundation.dropdown.js:37-41, 198-215`; R:positioned Dropdown 6). Not ported: native button activation through the Triggers covers it.

Round 2: shape, naming, DI.

4. **Directive or component, and where?** Attribute directive on `.dropdown-pane`, adding the Structural class on its host (as `nfsButton` adds `.button`), named `NfsDropdownPane` (BB 1.3: `.dropdown` alone is Button's Variant class). Source: ADR 0001; BB 1.1, 1.3.
5. **Plugin token?** None. BB Table B named `nfsDropdownPaneToken`, but no child directive injects the pane; the Triggers and the Nearest Openable need only `nfsOpenableToken` (TOG reached the same result for its own token).
6. **Defaults token?** `nfsDropdownPaneDefaultsToken`, Shape B, all-optional, covering every Option except `id`, `role`, `parentClass`, plus `animate` (BB 1.4, 1.9).
7. **Names of entry point, story ids, mixin?** `dropdown-pane` for all three, for the class name's reason; TRG already uses `dropdown-pane--` story ids. Rejected: `dropdown` (ambiguous with Button's Variant class and DropdownMenu).
8. **Openable members?** `isOpen` model (default `false`), `id` input defaulting to an `_IdGenerator` id (`nfs-dropdown-pane-`), `triggerRole` computed from `role`, `open(trigger?)`, `close(result?)`, `toggle(trigger?)`, `registerTrigger`. Source: TRG API; BB 1.4, 1.5.
9. **`role` input shape?** `'dialog' | null`, default `null`. A static `role="dialog"` sets it; the host binds `[attr.role]`. A free string would invite `menu`; a boolean loses the attribute idiom. Source: BB Table A ("non-modal `dialog` when the spec's `role` input is `dialog`"); TRG D6/D7; R:apg Dropdown.
10. **Output shape?** `opened: void`; `closed` with `NfsDismissReason | undefined` (Material `MenuCloseReason` plus `'sibling'`, ADR 0024); `undefined` for Triggers, methods, the model, and hover leave. A separate `'hover'` reason was weighed and not added (no consumer need). `close(result)` ignores its result, as TOG. Source: R:material 5; BB 1.4 event mapping.
11. **Extra public API?** `reposition()` (Material `updatePosition()`, AP user story 12) and a read-only `placement` signal (the Positioner's). `followScroll` is not an input: panes always follow (AP decision 21 allows either; nobody wants the detached behaviour).

Round 3: mapping every Option.

12. **`position`, `alignment`, `vOffset`, `hOffset`, `allowOverlap`, `allowBottomOverlap`?** Straight onto the Positioner with Foundation's defaults, `autoPosition` `bottom`, the RTL-aware base `auto` alignment, no pip. Source: AP "What each consumer maps"; P44 hand-off to this spec.
13. **Legacy `.top/.left/.right/.bottom` on the pane and `.float-*` on the anchor?** Not read. They have no CSS side (the research-repair note, audit 0001 H5), Foundation calls them legacy, and `_getDefaultPosition()`'s regular expression `/(top|left|right|bottom)/` matches any class name containing those words (FS `foundation.dropdown.js:89-107`). Listed as a delta.
14. **`parentClass`?** Kept as a class-name string (Foundation's name and docs), resolved to the host's nearest ancestor with that class inside the Positioner's measuring phase and passed as `boundary`. BB 1.4 drops class-name Options because the classes are the styling contract; this one is a lookup, so the rule does not apply. A `boundary` element input was weighed and left out (a second spelling; additive later).
15. **`hover`, `hoverDelay`?** `nfsHoverIntent` with `enabled` = `hover`, both delays = `hoverDelay` (the helper floors the close delay at 100 ms), the registered Triggers, and the pane. Source: AP consumer table.
16. **`hoverPane`?** Dropped: the pane is always in the Hover region. Its `false` default fails WCAG 1.4.13 hoverable (AP decision 37; FS `foundation.dropdown.js:185-196, 360`), and `false` has no compliant use left, so flipping the default would keep an Option whose only other value fails AA.
17. **Toggle while hover-opened?** Kept from Foundation: `toggle()` does nothing while the pane is hover-opened (FS `foundation.dropdown.js:311-318`, `data('hover')`), so a click right after a hover open does not close what just appeared. `close()` and `nfsClose` still close. Rejected: closing (surprising), pinning open (new state).
18. **Hover leave while focus is inside?** The pane's hover-intent `close` callback declines while focus is inside the pane: WCAG 1.4.13 persistent covers focus too. Focus leaving and Escape still close.
19. **`closeOnClick`?** Light dismiss `outsidePress`, default `false` as in Foundation: BB 1.4 keeps Foundation defaults unless the APG or Aria forces a change, and neither does (the APG disclosure pattern has no outside-click rule). Escape, the focus rule, and siblings apply regardless (ADR 0024). Consequence recorded in the spec (D11): with it off, an outside click on a control closes the pane only where the engine focuses on click; Safari does not focus buttons on click.
20. **`forceFollow`?** Dropped (already in BB 1.4's dropped list). Triggers never call `preventDefault()` (TRG D12), and hover never opens from touch, so the first-tap guard has nothing to guard (FS `foundation.dropdown.js:150-163`).
21. **`autoFocus`?** CDK's first-tabbable rule: the first element in DOM order for which `InteractivityChecker.isFocusable` (which includes `isVisible`) and `isTabbable` hold, the rule `FocusTrap.focusFirstTabbableElement()` uses (NGC `a11y/focus-trap/focus-trap.ts:264-297`, `a11y/interactivity-checker/interactivity-checker.ts:54-150`). This refines AP's "isFocusable and isVisible" by also excluding `tabindex="-1"`, which matches Foundation's `tabindex >= 0` filter while dropping its positive-`tabindex` sort. Not on hover opens (hover must not move focus) and not on the first-paint state (focus only on user action, R:rendering 7 checklist Dropdown row).
22. **The `autoFocus` attribute collision?** HTML attribute names are case-insensitive, so a static `autoFocus` attribute renders HTML's global `autofocus`, which the browser acts on at page load and when a containing `<dialog>` opens (autofocus delegate). The input keeps Foundation's name (BB 1.4) but is documented as set by binding or the Defaults token, and a dev check warns on a static attribute. Rejected: renaming the input.
23. **`trapFocus`?** CDK `FocusTrap` (BB 1.2), created on open with deferred anchors, anchors attached, destroyed on close. Requires `role="dialog"` (dev warning otherwise): a trapped disclosure breaks the APG disclosure's Tab-out behaviour (R:apg Dropdown keyboard table), while the APG describes non-modal dialogs as containing their tab sequence and Escape is their standard exit (WCAG 2.1.2). Moves focus in on open, because CDK inserts its start anchor before the pane and a Tab from the Trigger would land on it and jump to the last control (NGC `focus-trap.ts:43-49, 112-132`). Not on hover opens.
24. **Trap anchors and Light dismiss?** CDK's anchors are siblings outside the pane. A `focusin` on an anchor is redirected into the pane by the anchor's `focus` listener, but the anchor's own `focusin` can still reach the document afterwards (UI Events order: `focus` then `focusin`), and AP's focus rule would read it as focus leaving. Required: the registry ignores a `focusin` whose target is no longer `document.activeElement`. That guard never changes a normal `focusin` (its target is the active element at dispatch) and covers any focus trap; proposed as an AP amendment below, with browser-level and three-engine e2e cases. No prototype needed: the guard is correct whichever order an engine uses.
25. **Resolving the CDK services?** `Injector.get` inside the render callback of the first open that needs them, so the server and panes without `autoFocus`/`trapFocus` never construct them; `FocusTrapFactory`'s constructor loads CDK's visually-hidden style into the document (NGC `focus-trap.ts:382-395`).

Round 4: ARIA, focus, keyboard.

26. **Pattern?** Disclosure by default (no role on the pane, Trigger `aria-expanded` + `aria-controls`); non-modal dialog with `role="dialog"` (Trigger adds `aria-haspopup="dialog"`, pane named, no `aria-modal`). Never Menu Button, never `aria-haspopup="true"` (WAI-ARIA treats it as `menu`). Source: R:apg Dropdown; TRG ARIA table.
27. **`aria-hidden` on the pane?** Dropped: Foundation's `display: none; visibility: hidden` removes a closed pane from the accessibility tree (BB 1.10; FS `_dropdown.scss:41-67`).
28. **Naming a dialog pane?** Consumer-supplied `aria-labelledby` or `aria-label`, dev warning when missing, and axe's `aria-dialog-name` (in the `best-practice` tag of the ADR 0018 rule set). Foundation's automatic `aria-labelledby` needs an id written onto the Trigger, which a pane directive cannot do before hydration (ADR 0008, BB 1.11 decision 3); a disclosure pane needs no name. This departs from TRG's consumers table ("and its `aria-labelledby`"); proposed change below.
29. **Focus return?** On a close requested while focus is inside the pane, with reason `'keydown'` or `undefined` from a method, a Trigger, or hover leave: focus the Trigger passed to `open()`, else the element focused when `open()` ran, if connected and focusable, in the close's render callback, before any leave animation ends (focus must not stay in content that is going away, WCAG 2.4.3; the Trigger is visible throughout). No focus move for `'click'`, `'tab'`, `'sibling'` (AP focus return rule) or for model-driven closes (TOG's rule; a consumer closing from a submit handler calls `close()`). No `restoreFocus` input (Foundation has none). Source: APG disclosure and dialog (Escape returns focus to the trigger); TRG "Requirements every Openable spec inherits".
30. **Keyboard table?** Enter/Space toggle through the native button; Tab moves through and out (closing with `'tab'`), wraps with `trapFocus`; Escape closes the topmost pane from anywhere; no arrow keys. Source: R:apg Dropdown keyboard table; AP keyboard table.
31. **DOM order?** The pane must follow its Trigger, so Tab from the Trigger enters it and the focus rule does not close it on the way; a dev check warns when the pane precedes its first registered Trigger, or when `hover` is on and no Trigger is registered (a hover pane must also open by click and keyboard, 2.1.1).

Round 5: WCAG 2.2 AA (the ticket's guard).

32. **1.4.13?** Dismissible (Escape from anywhere), hoverable (pane always in the Hover region, 100 ms close floor), persistent (no timer; hover leave never closes a pane holding focus). Foundation's `hoverPane: false` default is the failing default, fixed by dropping the Option.
33. **1.4.10 at 320 CSS px?** Foundation's 300 px default and its 200 px and 400 px sizes overflow from Triggers away from the edges, because the Positioner never shifts or shrinks a pane (AP decision "pane is never moved or resized beyond Foundation's formulas"). Reasoning: with the bottom position, the search tries left and right alignment; left fits when the Trigger starts at most `page - W` from the left, right fits when it ends at least `W` from the left, so any `W` of at most half the page always fits one of them. Required consumer settings: `$dropdown-width: min(300px, 45vw)` and `$dropdown-sizes: (tiny: 100px, small: min(200px, 45vw), large: min(400px, 45vw))`; 45vw rather than 50vw leaves room for a desktop scrollbar (vw includes it, the body box does not); CSS `min()` is in target; Dart Sass passes `min()` with mixed units through as a CSS calculation. The `nfs-dropdown-pane` mixin warns at compile time for fixed widths over 160 px (half of 320), ADR 0022's "compile error or warning from the library's mixin". Rejected: a library `max-width` rule (a pane anchored mid-page still overflows), advice only (ADR 0022).
34. **2.4.11?** Every Placement sits beside its anchor for non-negative offsets (Positioner warns on negative); the focus rule closes a pane as focus moves on; one pane at a time; a hover pane over an already focused control is dismissed with Escape without moving focus.
35. **2.5.8?** The pane adds no target; `.button` Triggers pass (Button spec); axe `target-size` runs in every story.
36. **4.1.2, 1.3.1?** Trigger ARIA from host bindings, correct in server HTML (TRG); dialog panes named; `aria-controls` from the pane's `id`.
37. **1.4.3?** Passes with defaults: `$body-font-color` #0a0a0a on `$dropdown-background` (`$body-background`, white) is about 19.8:1; axe `color-contrast` checks open panes in stories.
38. **1.4.11?** `$dropdown-border` (1px `$medium-gray`, about 1.6:1 on white) is a container edge, not needed to identify a control or state, so the criterion does not apply; state is conveyed by `aria-expanded` and the pane appearing.
39. **2.4.7, 2.1.1, 2.1.2, 2.4.3, 1.3.2, 3.2.1, 2.2.2?** Foundation keeps focus outlines unless `what-input` is loaded, which the library never does (TOG 2.4.7 row); native button Triggers; trap only with `role="dialog"` and Escape always closes; in-place pane after its Trigger; nothing opens on focus; `animate` runs only on user action, and no Motion class under reduced motion.

Round 6: animation, rendering modes, hooks.

40. **Animation?** `.is-open` State class plus keyframe Motion classes from an `animate` input (`'in [out]'`, default `''`, Foundation has none), phases in a `linkedSignal` with `.is-open` kept during leaving (Foundation's `display: none` would cut the animation), the measured completion timer (TOG's refinement: longest computed animation, `animationend`/`animationcancel` filtered by target, fallback of measured length plus 100 ms outside the zone, zero measured completes at once). Motion UI transition classes warn once and apply unchanged (P47 orchestrator note). Source: ADR 0003; BB Table B Dropdown; P47; TOG Animation.
41. **Reduced motion?** No Motion class when `NfsMediaQuery.reducedMotion()` is `true` or `nfsAnimationsToken` disables animations, as RT does; `nfs-motion`'s 1 ms override stays the backstop. This covers consumer classes without a reduced-motion rule. BPS notes CSS motion is normally the mixins' job; binding nothing is the stricter of the two published choices.
42. **Server output?** `.dropdown-pane`, `.is-open`, `id`, `role` as host bindings; closed pane hidden by Foundation CSS so `aria-controls` is valid; no offsets, placement classes, Motion classes, trap anchors, or CDK style in server HTML. Source: ADR 0008; R:rendering 7 rules 1 to 3; AP rendering modes.
43. **Open at first paint?** `.is-open` at the static position, one settle in the first client render callback (AP decision 46); no `autoFocus`/`trapFocus`, no `opened`; not dismissible before hydration.
44. **Replay?** Trigger `click` replays through the Trigger's host listener and calls `toggle(trigger)`, the Positioner places after (R:rendering 4 worked case); hover before hydration does nothing (non-replayed `pointerenter`); Light dismiss is document-level and never replays, correctly. The pane's own listeners (`animationend`, `animationcancel`) are not replay types, so the pane carries no `jsaction`.
45. **`@defer` and hydrate triggers?** No `@defer` in library code; per-plugin entry point; `hydrate on hover` opens a hover pane on the second entry, `on viewport`/`on idle` avoid it; `hydrate never` keeps server state. Trigger, pane, and parent pane in one boundary. Source: ADR 0008 decisions 6 and 7; AP decision 48.
46. **Render hooks?** `afterRenderEffect` inside the three utility calls; the pane's own `afterRenderEffect` with `earlyRead` (computed animation), `mixedReadWrite` (finding the first tabbable element and `focus()`, after the Positioner's `write`), `read` (Completion outputs); `afterNextRender` only for dev checks under `ngDevMode`; no `effect` (no non-DOM side effect; the Triggers' registration effect is theirs); no `afterEveryRender` (per-change-detection cost). Source: BB 1.5; the angular-developer skill `effects.md`; AP decision 54.
47. **`injectAsync`?** Not used, and nothing lazy is added. AP decided eager loading for the utility (AP decision 53). The only code needed only after an interaction is `FocusTrapFactory` and `InteractivityChecker`; both are in `@angular/cdk/a11y`, which the pane already imports for `_IdGenerator`, so a separate chunk saves little, and the trap must attach in the same pass that shows the pane (an awaited load lets an early Tab escape and close the pane through the focus rule). Synchronous `Injector.get` on first need gives the server and unused-panes saving without the latency.
48. **Implementation level and fallback?** Custom Angular on the Anchored pane utility with platform measurement; `popover` and anchor positioning out of target (R:platform 2, 3: popover Firefox 125, iOS 18.3; anchor positioning Baseline 2026); `<details>` cannot host a free-standing Trigger; a non-modal `<dialog>` with `show()` was weighed for dialog panes and rejected (its UA `inset-inline: 0; margin: auto; width: fit-content` fights `.dropdown-pane`, and `show()` adds nothing Light dismiss lacks); Aria has no fitting pattern; CDK supplies `InteractivityChecker`, `FocusTrapFactory`, `_IdGenerator`. No fallback needed.
49. **Material comparison?** Borrowed: reason-carrying `closed`, the interface-typed template reference, `updatePosition()` as `reposition()`, a defaults token.
