## Answer

Spec: [specs/smooth-scroll.md](../specs/smooth-scroll.md). Resolved 2026-09-26 by self-grilling (AFK), both sides played against the sources below.

Gist: one attribute directive, `NfsSmoothScroll` (`[nfsSmoothScroll]`, `exportAs: 'nfsSmoothScroll'`), on a container of in-page links or on one link, as Foundation places `data-smooth-scroll`. No inputs, outputs, models, host bindings, or Defaults token. One `click` host listener: for an unmodified primary click on an in-page link whose target exists, it scrolls with `scrollIntoView({block: 'start', inline: 'nearest'})` (`'smooth'`, or `'instant'` while `NfsMediaQuery.reducedMotion()` is true), focuses the target (temporary `tabindex="-1"` when not focusable, removed on `blur`; `preventScroll`), leaves the URL unchanged, and calls `preventDefault()` last and only when the click is not already cancelled. A container host yields to clicks a link-level listener (such as `RouterLink`) already cancelled; a link host owns its click. Public `scrollTo(target: Element | string, options?: {focus?: boolean}): boolean` for code and for Magellan, which composes the directive through `hostDirectives`. Foundation's `offset` and `threshold` become CSS (`scroll-padding-top` on the scroller, `scroll-margin-top` on a target); `animationDuration` and `animationEasing` are Dropped options (browser-owned). Opt-in Library mixin `nfs-smooth-scroll($scroller: html)` emits `scroll-behavior: smooth` under `prefers-reduced-motion: no-preference` for native jumps. Implementation level: native platform, plus CDK `InteractivityChecker`. A listener-free recipe is documented for pages that do not need the directive.

### Decision log

Sources: FS = the Foundation 6.9.0 clone; NG = the Angular 22.2.x clone; NGC = the components 22.2.x clone; APG = the aria-practices clone; WHATWG = HTML Standard, "Navigation and session history" (fetched through markdown.new, Living Standard of 25 September 2026); BCD = browser-compat-data `api/Element.json` (main, 2026-09-26); R:x = research files by short name as `building-blocks.md` cites them; BB = `building-blocks.md`; BP = the [Spec: Breakpoint service (shared utility)](53-spec-breakpoint-service.md) and its spec; Button = the [Spec: Button](37-spec-button.md) and its spec.

Round 1 (no prerequisites): what Foundation does, and what the platform and Angular already do.

1. **What is Foundation's SmoothScroll contract?** `data-smooth-scroll` on a container (delegated to `a[href^="#"]`) or on one link; the handler starts `$('html, body').stop(true).animate({scrollTop: offset().top - threshold / 2 - offset}, animationDuration, animationEasing)` and then calls `preventDefault()`; no focus move, no URL change, no ARIA, no Sass; generated container id; static `scrollToLoc(loc, options, callback)` returning `false` on a miss; events only `init`/`destroyed`. `SmoothScroll.defaults` has exactly four options: `animationDuration: 500`, `animationEasing: 'linear'`, `threshold: 50`, `offset: 0` (audit H6 check: the ticket's four names match the source). Source: FS `js/foundation.smoothScroll.js:18-140`; `docs/pages/smooth-scroll.md`; R:positioned SmoothScroll 1-9.
2. **What does the platform do for an in-page link with no script?** "Navigate to a fragment" pushes a history entry, fires `popstate` (with null state) and `hashchange`, and runs "scroll to the fragment": sets `:target`, scrolls the target into view with behavior `auto`, block `start`, inline `nearest` (so CSS `scroll-behavior`, `scroll-margin`, and `scroll-padding` apply), runs the focusing steps for the target with the viewport as fallback, and moves the sequential focus navigation starting point to it. An empty fragment or `top` scrolls to the top with no focus move. Source: WHATWG "navigate to a fragment" steps 12-16, "scroll to the fragment" steps 1-3, and the note that "`popstate` events fire for fragment navigations"; R:platform 9.
3. **Which of those features are in the Browser target?** `scrollIntoView` with options (smooth: Chromium 61, Gecko 36, WebKit 15.4), `scroll-behavior` (widely available 2024-09-14), `scroll-margin`/`scroll-padding` (2021), `prefers-reduced-motion` (2020): yes. `scrollend` (Safari 26.2): no. BCD lists `behavior` values under one `options_behavior_parameter` entry (Safari 14) with no separate `instant` entry, and NG `packages/router/src/router_scroller.ts:109` passes `{behavior: 'instant'}` to the same browser set. Source: R:platform 9, 18; BCD; NG.
4. **What does the Router do with fragments?** `withInMemoryScrolling({anchorScrolling: 'enabled'})` makes `RouterScroller` call `ViewportScroller.scrollToAnchor(anchor)` after `NavigationEnd` plus a macrotask or frame, for imperative navigations only ("Anchor scrolling does not happen on 'popstate'"). `scrollToAnchor` computes a position from `getBoundingClientRect`, subtracts `setOffset`, calls `window.scrollTo` with no `behavior` (so the root's CSS `scroll-behavior` decides), then `focus({preventScroll: true})` ("to avoid extra scroll that breaks smooth scrolling"). `scrollOffset` exists only on `RouterModule.forRoot`'s `ExtraOptions`; with `provideRouter` the equivalent is `ViewportScroller.setOffset`. `window.scrollTo` ignores `scroll-margin`/`scroll-padding`. On the server `ViewportScroller` is a null implementation. Source: NG `packages/router/src/router_scroller.ts:84-159`, `router_config.ts:140-193, 300`, `router_module.ts:200-201`, `provide_router.ts:182-195`, `packages/common/src/viewport_scroller.ts`.
5. **How does the Router react to a native fragment jump?** `HistoryStateManager` forwards every `popstate` to `navigateToSyncWithBrowser` with trigger `popstate` and `replaceUrl`. `RouterScroller` then sets `lastSource = 'popstate'` and `restoredId = 0` (the new entry's state is null), and emits a `Scroll` whose position is `store[0]`, the scroll position recorded at the first `NavigationStart`. With `scrollPositionRestoration: 'enabled'` it scrolls there, with `'top'` to the top, with `'disabled'` (the default) nothing. While hydrating it schedules no scroll. So in a hydrated Router app with scroll restoration on, an unhandled native in-page jump is undone. Source reading: NG `statemanager/state_manager.ts:192-218`, `router_scroller.ts:84-121, 124-159`. Confirmation is the Prototype needed below.
6. **What does `RouterLink` do on an `<a>`?** A `click` host listener that ignores non-primary and modified clicks and non-`_self` targets, navigates through the Router, and returns `false`, which makes Angular call `preventDefault()`. Its server-rendered `href` includes the route path and the fragment. Source: NG `packages/router/src/directives/router_link.ts:471-522`.
7. **What does Angular's event dispatch do with anchor clicks?** The early contract (full-hydration window) queues events and never cancels, so native navigation happens and the handler replays later. For live events inside still-dehydrated blocks, `Dispatcher.dispatch` calls `preventDefault()` when the resolved action element (the nearest element with `jsaction` for the event) is an `A`. A replayed event's `preventDefault()` calls the original and throws; Angular reports it to `ErrorHandler`. Source: NG `packages/core/primitives/event-dispatch/src/dispatcher.ts:79-140`, `event_dispatcher.ts:121-138`; R:rendering 4.
8. **What does `<base href>` do to `href="#x"`?** A fragment-only URL resolves against the document's base URL, so with Angular CLI's default `<base href="/">` on a route other than `/` it is not the current document and the browser performs a cross-document navigation to `/#x`. Source: WHATWG (navigate to a fragment only for a URL equal to the document URL apart from the fragment); R:platform 9; the Angular CLI default `index.html`.

Round 2 (depends on 1-8): does this reduce to documentation plus Router configuration?

9. **Is a directive needed at all?** Partly no: for a page without the Router's scroll restoration, same-document `href`s plus `scroll-behavior` (gated) plus `scroll-padding-top` give smooth, offset, reduced-motion-aware jumps and platform focus handling with no script (APG research: "Native `scroll-behavior: smooth` plus fragment navigation gives both the focus move and the reduced-motion respect without script"). A Router-only answer (`routerLink` + `fragment` + `anchorScrolling` + `setOffset`) covers Router apps without the directive, with a separate JavaScript offset and focus only for focusable targets. What neither gives: keeping plain in-page links out of the Router's `popstate` handling (decision 5), focus on targets that are not focusable, Foundation's `href="#x"` markup working in place after hydration under `<base href>` (decision 8), and a shared programmatic scroll for Magellan (Foundation's Magellan depends on `SmoothScroll.scrollToLoc`, R:positioned Magellan 7). Answer: a small directive, plus the documented listener-free recipe and Router rule. Source: decisions 2-8; R:apg SmoothScroll; BB Table A SmoothScroll.
10. **Container, link, or both?** Both, as Foundation documents; one class, one selector, host kind decided from the host tag at construction; links found by delegation at click time (survives `@for`, `@if`, deferred content with no registration). Source: FS docs; BB 1.1, 1.3; BB 1.9 (registration is for ordered children, which this is not).
11. **Listener-free native navigation or a click handler?** A handler, with the native path kept as the pre-hydration behaviour and the documented recipe. The amended BB 1.11 decision 5 and ADR 0011 forbid host click listeners on link-hosted directives "when it can be avoided"; here it cannot, because only a cancelled click avoids the `popstate` and the history entry, and focus on non-focusable targets needs script. The container placement (Foundation's primary form) keeps `jsaction` off the `<a>`, so in dehydrated blocks the dispatcher does not cancel the native jump. Recorded as the proposed ADR. Source: decisions 5, 7; ADR 0011; BB 1.11 decision 5.
12. **Handler order and replay?** Filter (primary unmodified click, `a[href]` inside the host, no `download`, `target` empty or `_self`); container host only: ignore when `defaultPrevented`; in-page test; resolve target (miss: ignore, native default); `scrollTo`; last: `preventDefault()` unless already `defaultPrevented`. Full-hydration replay: native jump already happened; the handler's scroll is a no-op, focus moves, `preventDefault()` throws and is logged (BB Part 4 OPEN FOR HUMAN 3 default; audit M12's wording). Dehydrated block, link host: the dispatcher cancelled, the replayed handler scrolls and focuses and skips `preventDefault()`, so nothing is logged. Source: BB 1.5, 1.11 decision 5, Table B SmoothScroll (after M12); `audits/0002-building-blocks.md` M12; decision 7.
13. **Why does the container yield to cancelled clicks but the link host not?** `RouterLink` (and any consumer handler) on a link inside the container has already cancelled its click when it bubbles to the container; handling it too would double-scroll against the Router's anchor scrolling. On a link host, a cancelled click reaching the handler is the dispatcher's cancellation in a dehydrated block, and yielding would lose the scroll. Source: decisions 6, 7.
14. **Which links are in-page?** Raw `href` starting with `#` (Foundation's `a[href^="#"]`), or a resolved URL equal to the document URL apart from a non-empty fragment. A `#`-only `href` that `<base href>` resolves elsewhere is still handled after hydration, with a development-mode warning that it leaves the page before hydration, in `hydrate never`, and on middle-click. The alternative (handle only resolved same-document links, identical in every rendering mode) is OPEN FOR HUMAN 2. Source: decision 8; FS `js/foundation.smoothScroll.js:42-56`; ADR 0008 (server HTML is the first paint).
15. **Target resolution?** HTML's indicated part: element with `id` equal to the percent-decoded fragment, then the first `a[name]`; empty fragment or `top` with no match is the top of the document. `scrollTo` accepts a fragment with or without `#`, or an `Element`; returns `false` on a miss (Foundation parity). A click on a link with a missing target falls back to the native default. Source: WHATWG indicated part; FS `scrollToLoc` returns `false`; NG `viewport_scroller.ts` `findAnchorFromDocument`.

Round 3 (depends on 9-15): options, focus, history, CSS.

16. **`animationDuration`, `animationEasing`?** Dropped options: native smooth scrolling has no duration or easing control; a JavaScript scroll loop would be JavaScript-timed animation, which the user ruled out. Already listed in BB 1.4's dropped timing options. Source: map Standing preferences (Animation); BB 1.4; R:platform 9, Plugin table.
17. **`offset`, `threshold`?** Mapped to CSS, not inputs: `scroll-padding-top` on the scroll container (one rule for a sticky bar) or `scroll-margin-top` per target; SmoothScroll's `threshold` is only extra offset (`threshold / 2`). CSS applies to native fragment navigation and to `scrollIntoView` alike, so the landing point is the same before and after hydration and in nested scroll containers; a JavaScript offset would be browser-only and viewport-only. Library default 0 (Foundation's effective default is 25 px; documented). Magellan's second use of `threshold` stays with Magellan. Source: decision 2; R:platform 9 ("`scroll-margin` on the target offsets the final position"); FS `smoothScroll.js:82`.
18. **Reduced motion?** `behavior: reducedMotion() ? 'instant' : 'smooth'`, read at each scroll from `NfsMediaQuery.reducedMotion` exactly as BP defines it (live, `false` on the server and before the service goes live; the service goes live before any replay). `'instant'` rather than `'auto'` so a consumer's own ungated `scroll-behavior: smooth` cannot override the preference. The mixin gates its rule with `prefers-reduced-motion: no-preference`. Source: BP (API table, consumer table row "SmoothScroll, Magellan: `reducedMotion` (`behavior: 'auto'` instead of `'smooth'`)"); decision 3; BB 1.6 rule 5.
   Note: BP's consumer table says `'auto'` for SmoothScroll; this spec uses `'instant'` for the reason above. Proposed below as a one-word change to that row.
19. **Focus?** After starting the scroll, `focus({preventScroll: true})` on the target; if `InteractivityChecker.isFocusable` says no, set `tabindex="-1"` first and remove it on the target's next `blur`; no focus move for the top of the document or with `scrollTo(..., {focus: false})`. Source: R:apg SmoothScroll ("it must still move focus to the target"); WHATWG focusing steps; NG `viewport_scroller.ts` comment on `preventScroll`; BB 1.2 (`InteractivityChecker`).
20. **URL and history?** Unchanged: Foundation never changed the URL; no `pushState` or `replaceState` means no `popstate`, no extra entries, and no risk of erasing the Router's `history.state` (its navigation id and router page id), which a naive `replaceState(null, ...)` would; Magellan owns deep linking and history options. The BB Table A row's "History API `replaceState` for the hash" is withdrawn. Whether directive-handled jumps should write the fragment anyway is OPEN FOR HUMAN 1. Source: FS `smoothScroll.js`; decision 5; NG `state_manager.ts`; R:positioned Magellan 3 (`deepLinking`, `updateHistory`).
21. **Outputs, Defaults token, host bindings?** None. No Foundation event; a completion output needs `scrollend` (out of target); every Option is CSS or browser-owned. Source: decisions 1, 3; BB 1.4.
22. **Library CSS?** One opt-in rule: `nfs-smooth-scroll($scroller: html)` emits `#{$scroller} { scroll-behavior: smooth; }` inside `@media (prefers-reduced-motion: no-preference)`. Reason: Foundation ships no smooth-scroll CSS, and native jumps (pre-hydration, `hydrate never`, Router-owned fragment links) are instant without it. The parameter exists because Foundation has no setting naming the scroll container and because `scroll-behavior` on `html` also animates every programmatic root scroll, including the Router's forward-navigation `scrollToPosition([0, 0])` (no `behavior` passed; only restored positions pass `'instant'`) and CDK's scroll restore (CDK's block scroll strategy resets `scroll-behavior` to `auto` for that reason). Source: FS (no SmoothScroll Sass); `issues/57-sass-packaging.md` decision log 16-17 and the Sass subsection rule; ADR 0012; NG `router_scroller.ts:107-121`; NGC `src/cdk/overlay/scroll/block-scroll-strategy.ts:72-87`; R:platform 9 ("apply it to the specific container, and wrap in `@media (prefers-reduced-motion: no-preference)`").

Round 4 (depends on 11-22): Router interplay, rendering modes, testing.

23. **Rule for apps that use both the Router and the directive?** (a) One owner per link: `routerLink` + `fragment` links belong to the Router (the container yields), plain same-document links to the directive; never both on one element. (b) Router-owned fragments need `anchorScrolling: 'enabled'`, `ViewportScroller.setOffset` equal to the CSS offset, and `tabindex="-1"` on non-focusable targets. (c) With scroll restoration on, native in-page jumps the directive does not handle are undone by the Router (decision 5); keep such links inside the directive (as link hosts inside deferred regions) or keep restoration off on those pages. (d) The mixin on `html` animates the Router's forward scroll-to-top when restoration is on. Source: decisions 4-6, 22.
24. **Server output and hydration?** No host bindings: server HTML is the consumer's markup plus `jsaction="click:;"` on the host; hydration changes nothing; no `ngSkipHydration`; prerendering identical. Source: ADR 0008; R:rendering 4, 7 rules 1, 10, 11.
25. **Incremental hydration and `@defer`?** Container host in a dehydrated block: native jump at once, replay as in decision 12, and the jump's `popstate` reaches the (hydrated) Router. Link host: dispatcher cancels, the block hydrates, the replay scrolls, no error. `hydrate never`: native jumps with CSS offset and mixin smoothness (BB 1.11 decision 7 residue), which also reach the Router as `popstate`. A plain link with no directive that is a root node of `hydrate on interaction` is cancelled with nothing to replay it (Button's hazard). Targets may sit anywhere; ids consumer-supplied. Library templates have no `@defer`; own entry point. Source: decision 7; R:rendering 3, 4, 7; BB 1.5, 1.11 decisions 5-7; Button spec Rendering modes.
26. **Material and Aria?** No Material counterpart (BB Table B "Nothing"); no Aria pattern; the Router's in-memory scrolling is the comparison table instead. Source: BB Table B; R:aria; R:material.
27. **Testing seams?** Story ids `smooth-scroll--container`, `--single-link`, `--sticky-offset`, `--scroll-container`, `--focusable-target`, `--link-filters`, `--programmatic`, `--back-to-top`, `--router-link-fragment`; play functions assert position (polled, 1 px tolerance), focus, Tab continuation, and an unchanged hash; browser-level tests cover the link filter table, ownership, reduced motion through an `NfsMediaQuery` test double, temporary `tabindex`, replay (both `defaultPrevented` cases), `hostDirectives` composition, and the dev checks; node-level Vitest has the SSR smoke, the pure in-page decision, and the Sass compile; Playwright e2e covers real keys, the History API (`history.length`, no `hashchange`/`popstate`), `emulateMedia`, Router coexistence with scroll restoration on the static Storybook build, and on the prerendered fixture app (nested route, `<base href="/">`): no-JS jumps, hydration counters, a pre-hydration click, link and container hosts in a dehydrated block, and `hydrate never`. Source: BB 1.12; map Testing rule; R:rendering 6.

Round 5 (the user's standing rule, restated 2026-09-26: WCAG 2.2 AA as requirements).

28. **Which WCAG 2.2 AA criteria apply, and how does each hold?** Recorded per criterion; the spec's ARIA and keyboard section carries the table and the tests assert each.
    - 2.1.1 Keyboard: native link activation; Enter produces the `click` the directive handles.
    - 2.4.1 Bypass Blocks: a skip link with `nfsSmoothScroll` scrolls to and focuses the main content.
    - 2.4.3 Focus Order: focus moves with the scroll (decision 19); Foundation's Plugin left focus on the link and fails it. Native jumps focus a focusable target and otherwise move the starting point (WHATWG scroll to the fragment, steps 6-7).
    - 2.4.7 Focus Visible: Foundation removes outlines only under `[data-whatinput='mouse']` (FS `scss/util/_mixins.scss:205-210`, used in `_global.scss:224` and `components/_menu.scss:69`), which never matches without what-input, so the browser's `:focus-visible` ring shows on keyboard-initiated focus of the target; asserted in play functions and e2e.
    - 2.4.11 Focus Not Obscured (Minimum): with a sticky or fixed bar, `scroll-padding-top` of at least the bar height on the scroll container is required consumer CSS; it governs the directive's `scrollIntoView`, native jumps, and later focus-driven scrolling, whereas `scroll-margin-top` alone covers only the jump. Foundation's default (`offset: 0`, no CSS) fails it under a Sticky bar, and Foundation has no setting for the bar height, so the smallest rule is the consumer's one declaration, shown in the spec's examples; asserted in the `smooth-scroll--sticky-offset` story and in e2e in three engines.
    - 2.3.3 Animation from Interactions (AAA): honoured anyway (decision 18).
    - 2.2.2 Pause, Stop, Hide: not applicable (user-initiated, self-ending motion).
    - Story gate: axe via `@storybook/addon-a11y`, `parameters.a11y.test = 'error'`, `runOnly` tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa` (BB 1.10); axe does not test 2.4.3, 2.4.7, or 2.4.11, so play functions assert them.
    Source: the user's rule (coordinator message 2026-09-26); WCAG 2.2; FS Sass; WHATWG; BB 1.10; R:apg SmoothScroll.

### OPEN FOR HUMAN

1. Should a directive-handled jump write the fragment to the URL? Decided under the triage rule below.
2. DECIDED 2026-09-27 by [Decide: `#`-only links that `<base href>` resolves to another document](74-decide-base-href-hash-links.md): option (b), ADR 0038. Should `href="#x"` links that `<base href>` resolves to another document be handled after hydration? Default applied: yes, with a development-mode warning (Foundation's `a[href^="#"]` contract keeps working in client-rendered Router apps). Alternative: handle only links the browser itself treats as same-document, so behaviour is identical before and after hydration, at the cost of Foundation's markup leaving the page on every deep route.
3. Inherited, not new: building-blocks Part 4 item 3 (how a handler recognises a replayed event). Its default makes a pre-hydration click log one `preventDefault` error on replay; the spec's e2e assertion flips if the item is answered with a replay check.

## Prototype needed

- Question: in a hydrated Angular 22.2 application with `provideRouter(routes, withInMemoryScrolling({scrollPositionRestoration: 'enabled'}))` (and again with `'top'`), where does the page end after a native same-document fragment navigation (a plain `<a href="/current/path#target">` with no directive, clicked after hydration): at the target, or at the position the Router stored for navigation id 0 (or the top)? And inside a `@defer (hydrate on interaction)` block holding an `nfsSmoothScroll` container, which scroll lands last: the Router's `popstate`-driven `Scroll` or the replayed handler's `scrollIntoView`? Measure in Chromium, Firefox, and WebKit, with and without the `nfs-smooth-scroll` mixin.
- Why only running code settles it: the source reading (decision 5) predicts the Router's scroll, but its timing (after `NavigationEnd`, a `setTimeout`, and a frame) races the block's chunk download and replay, and smooth scrolling in progress may be interrupted differently per engine.
- Default assumed in the spec: the Router undoes unhandled native jumps when scroll restoration is on, and in a dehydrated block the replayed handler runs last so the page ends at the target after a visible jump; the spec therefore recommends link hosts for in-page links inside deferred regions of such apps and keeps an e2e regression guard.

   - Impact: HIGH. ### Amendment, 2026-09-26

Verdict of the [Prototype: Smooth Scroll under Router scroll restoration and replay](62-prototype-smooth-scroll-router-restoration.md), appended to this decision log: the spec's assumptions hold in Chromium, Firefox, and WebKit. ### Amendment, 2026-09-27 (Decide: `#`-only links that `<base href>` resolves to another document)

Triage item 2 above and item 2 of the consistency-review triage (OPEN FOR HUMAN 2, `#`-only `href`s that `<base href>` resolves to another document) are DECIDED by the [Decide: `#`-only links that `<base href>` resolves to another document](74-decide-base-href-hash-links.md) panel: option B, [ADR 0038](../adr/0038-smooth-scroll-same-document-links.md). A link is in-page exactly when a click on it would be a same-document fragment navigation for the browser, so a `#`-only `href` that `<base href>` resolves elsewhere is left to the browser, named by a development-mode warning at first render and at click time; the documented current-path `href` now follows `Location.onUrlChange`. Impact HIGH, confidence HIGH after the panel; the item leaves the trap-quadrant list. `specs/smooth-scroll.md` was edited as listed.

1. Solution: the directive earns its place with three things, not four (the "Foundation's `href="#id"` after hydration" item is gone), and a new sentence says it never changes where a link goes: in-page means a same-document fragment navigation for the browser, and on other routes under `<base href>` the consumer builds the `href` from the current path.
2. User stories 16, 17, and 25: the warning names a link the directive does not handle; story 17 becomes the keyboard and screen reader user's promise that a link goes to the same place in every state and is announced as same-page exactly when it stays on the page; story 25's "back to top" links apply when they resolve to the current document.
3. Foundation contract, Activation row: the same-document rule, with Foundation's `href="#id"` qualifying where the page URL is the base URL (D9).
4. Click handling step 3: HTML's fragment-navigation condition on the resolved `a.href` (document URL with fragments excluded, non-null fragment, possibly empty); the raw `href` attribute is not consulted.
5. Development-mode checks: the first-render read covers the container's `a[href]` descendants, the `<base href>` warning also fires at click time, and its text says the directive does not handle the link and where it navigates.
6. WCAG table, 2.4.1 row: the skip link needs an in-page `href`, built from the live current path in an application shell under `<base href>`; a bare `href="#main"` off the base URL, or a shell path read once, fails it.
7. Rendered HTML note: a bare `href="#first"` on a deep route is a link to the base URL for the browser, assistive technology, and the directive alike.
8. Rendering modes, link-host bullet: a link host whose `href` is not in-page inside a dehydrated block of a hydrated app is cancelled by the dispatcher and its replayed click is not handled, so the click does nothing; the click-time check names it.
