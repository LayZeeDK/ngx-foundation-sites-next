## Question

What is the Angular design for Foundation's Drilldown Menu plugin in the next library, and what does its spec say?

The result must be the best combination of: Foundation for Sites SCSS and the plugin's features; the ARIA APG pattern and WAI-ARIA; WHATWG HTML and HTML5+ platform features; Angular Aria; Angular CDK; Angular Material-equivalent accessibility and Material-equivalent component API (inputs, outputs, public properties and methods, content and view projection) for the similar Material component; and the modern DI patterns recorded in `research/di-and-composition-patterns.md` (lightweight injection tokens, host-scoped providers, host directives, parent tokens, default-options tokens). One plugin may yield several related directives or components (for example a container plus items plus a lazy-content directive); the spec covers the whole set.

## WCAG 2.2 AA guard (user decision, 2026-09-26)

Every directive and component complies with WCAG 2.2 AA; see the map's Accessibility preference and [ADR 0022](../adr/0022-wcag-2-2-aa-enforcement.md). The spec carries a criteria subsection under Implementation Decisions naming the 2.2 AA criteria this plugin touches (at least 1.4.3, 1.4.11, 2.4.7, 2.4.11, 2.5.8, 4.1.2, and, for overlays and hover content, 1.4.13) and how each is met, as requirements, never recommendations. Where a Foundation default fails a criterion, the spec states the Sass settings the consumer must set or the smallest custom rule the `nfs-<plugin>` mixin adds, with the reason. The story axe gate runs with the WCAG 2.2 AA tags, and the decision log records each criterion addressed.

## Answer

Spec: [specs/drilldown-menu.md](../specs/drilldown-menu.md). Resolved 2026-09-26 by self-grilling (AFK), both sides played against the sources below, under the user's WCAG 2.2 AA rule, the Foundation Sass reuse rule, the render-hook rule, the browser testing stack decision, and the triage rule for human-only items. The Nested menu spec is used as defined, including its 2026-09-26 amendment (`open()` does not open closed ancestors; `transition: none` on the drilldown submenu under `nfsAnimationsToken.disabled`; unrounded contrast checks from `color-luminance()`).

Gist: one secondary entry point, `ngx-foundation-sites/drilldown-menu`, with three directives over the Nested menu utility. `ul[nfsDrilldown]` (`exportAs: 'nfsDrilldown'`) provides `nfsMenuRootProviders('drilldown')`, binds `drilldown` and, while a level is open, `invisible` from the root handle, forwards `keydown`, and adds Foundation's `autoHeight`, `animateHeight`, `closeOnClick`, `scrollTop`, `scrollTopElement`, and `scrollTopOffset` (Foundation defaults, seeded from `nfsDrilldownDefaultsToken`), the aggregate `opened`/`closed` Completion outputs carrying the `NfsMenuItem`, a read-only `currentLevel`, `collapseAll()`, and `openPath(item, {focus})` for Foundation's `_showMenu()`. `[nfsDrilldownWrapper]` on the consumer's wrapper binds `is-drilldown`, `animate-height`, and the measured `min-height` (tallest level) or `height` (current level, `autoHeight`) from one ResizeObserver, only in drilldown mode. `li[nfsDrilldownBack]` on the consumer's `li.js-drilldown-back > button` closes its level (focus returns to the parent toggle through the utility's focus-loss guard) and is `hidden` plus `is-hidden` outside drilldown mode. Disclosure navigation per level; hidden ancestor levels use Foundation's `invisible`; the slide is Foundation's `$drilldown-transition`; after each slide the focused control is scrolled into view with `block: 'nearest'`. `closeOnClick` is the popover pointer rule on its own document listeners, never `preventDefault()`, not the Light dismiss registry. The `nfs-drilldown` mixin restates the Nested menu spec's drilldown rules and adds a reduced-motion override for `animate-height`, an inset focus ring, and compile checks for arrow contrast (unrounded), toggle size, and row height. Nothing is left open except a screen reader pass; no prototype is needed.

### Decision log

Sources: FS = the Foundation 6.9.0 clone (`js/foundation.drilldown.js`, `scss/components/_drilldown.scss`, `_visibility.scss`, `_accordion-menu.scss`, `_menu.scss`, `scss/_global.scss`, `scss/util/_color.scss`, `docs/pages/drilldown-menu.md`); NMS = [Spec: Nested menu (shared utility)](56-spec-nested-menu.md) (`specs/nested-menu.md`, with its 2026-09-26 amendment); P50 = the [Prototype: Nested menu directive family with breakpoint mode switching](50-prototype-nested-menu.md) answer and `prototypes/nested-menu/`; BB = `building-blocks.md`; R:menus, R:apg, R:rendering, R:platform, R:di = the research files by BB's short names; AP = `specs/anchored-pane.md`; SS = `specs/smooth-scroll.md`; OC = `specs/off-canvas.md`; BTN = `specs/button.md`; T41 = the [Decide the browser testing stack: Playwright component tests, Vitest Browser, or both](41-browser-testing-stack-decision.md) answer; SC = `storybook-conventions.md`; APG = the aria-practices clone; NG = the Angular 22.2.x clone; WCAG = the 2.2 AA criteria the user's rule names.

Round 1: the Foundation contract and the audit guards.

1. **Which Options, events, and methods does Drilldown have?** From `Drilldown.defaults` (FS `foundation.drilldown.js:560-655`): `autoApplyClass` (`true`), `backButton`, `backButtonPosition` (`'top'`), `wrapper`, `parentLink`, `closeOnClick`, `autoHeight`, `animateHeight`, `scrollTop`, `scrollTopElement` (`''`), `scrollTopOffset` (`0`), `animationDuration` (`500`), `animationEasing` (`'swing'`); `holdOpen` is commented out. Events `open`, `hide`, `close`, `closed`, `scrollme` `.zf.drilldown`; only `destroy()` is public, with `_show`, `_hide`, `_hideAll`, `_showMenu`, `_back`, `_resize`, `_getMaxDims` used as API. Source: FS lines cited; R:menus 2.3 to 2.5.
2. **Audit guard H6 (option names from the source, not the ticket).** The ticket's list omits `autoApplyClass`, `backButton`, `animationDuration`, and `animationEasing`; the brief described `animationDuration`/`animationEasing` as slide timing, but the source uses them only for `scrollTop`'s jQuery scroll (FS `:193`), so they are mapped as scroll timing and dropped (decision 17). `animateHeight` only adds the `animate-height` class whose CSS transitions `height` (FS `_drilldown.scss:82-84`, `foundation.drilldown.js:125`).
3. **Audit guard M12 (Browser target).** Everything used is Baseline widely available on 2026-05-07: `ResizeObserver` (widely 2023-01-28), `overflow: clip` (Chrome 90, Firefox 81, Safari 16), `inert` (in the core set), `scrollIntoView`/`scroll-behavior` options (widely 2024-09-14), Pointer Events, `transitionend`. View Transitions, `CloseWatcher`, `:has()`, `scrollend`, `overflow-clip-margin`, and `interpolate-size` appear only under "Platform features to adopt" with the current mechanism as the stated fallback. Source: R:platform feature summary, sections 9 and 10; BB 1.2.
4. **What does the Nested menu spec already settle?** The item, submenu, and toggle directives, all class emission including `invisible`/`visible`/`is-closing`/`drilldown-submenu-cover-previous`, the drilldown key table and focus handoff with `preventScroll`, completion (`transitionend` plus measured fallback), the focus-loss guard, the swap rule, and the Drilldown row of its consumer table: `ul[nfsDrilldown]`, `nfsMenuRootProviders('drilldown')`, `[class.drilldown]`, `[class.invisible]` from `hasOpenItem()`, `(keydown)`, `configure('drilldown', {autoHeight, opened, closed})`, and "own pieces": `nfsDrilldownDefaultsToken`, the wrapper, `li.js-drilldown-back`, `closeOnClick` calling `collapseAll()`, `scrollTop*`, the `nfs-drilldown` mixin. Source: NMS API, "What each consuming spec maps".

Round 2: shape, naming, DI.

5. **Directives or a component?** Three directives; the wrapper and the back item are one plain consumer-written element each. Source: ADR 0001 (names the drilldown back button); BB 1.1 case 3.
6. **Class and selector names.** `NfsDrilldown` on `ul[nfsDrilldown]` (BB 1.3: the Plugin name, not the docs title); `NfsDrilldownWrapper` on `[nfsDrilldownWrapper]`, after Foundation's `wrapper` Option, because `NfsIsDrilldown` would read as a State class (the prototype's and NMS's name); `NfsDrilldownBack` on `li[nfsDrilldownBack]` after the Structural class `js-drilldown-back` without its `js-` prefix. Source: BB 1.3; NMS rendered HTML; P50 files.
7. **Entry point and story ids.** `ngx-foundation-sites/drilldown-menu`, story ids `drilldown-menu--<story>`, since a story id's plugin part is the entry point folder (SC "Story ids"), the brief asks for `drilldown-menu--<story>`, and the menu family's folders are `accordion-menu`, `dropdown-menu`, `responsive-menu`. Foundation's hyphenated plugin name `drilldown` (R:menus 0.4) is the alternative not taken. Source: SC; BB 1.3; brief.
8. **How does the wrapper find its root?** The root injects `NfsDrilldownWrapper` (`optional`, `skipSelf`) and registers at construction; the wrapper accepts only its own child element (Foundation's rule, FS `:123`) and warns otherwise, which also keeps a nested root without a wrapper from taking the outer one. Registration at construction precedes host bindings, so `is-drilldown` is in server HTML. Source: BB 1.9 parent-owned registration; FS `:123-130`.
9. **Where does the back directive sit and what does it inject?** On the `li` (so it can bind `hidden` on the whole item, P50 decision to the Drilldown spec 1); it injects `NfsSubmenu` (BB Table B) and `NfsDrilldown` (present on a ResponsiveMenu root as a host directive), both optional, and registers with the root for development checks. Source: BB Table B; NMS consumer table.
10. **Defaults token.** `nfsDrilldownDefaultsToken`, Shape B, all-optional `NfsDrilldownDefaults` (`autoHeight`, `animateHeight`, `closeOnClick`, `scrollTop`, `scrollTopOffset`); `autoHeight` falls back to `nfsMenuBehaviourDefaults.drilldown.autoHeight`. No other token: nothing outside the entry point needs a lightweight handle. Source: BB 1.4, 1.9; R:di 5; ADR 0009.
11. **Openable?** No, as NMS D22. Source: NMS; Triggers spec Out of scope.

Round 3: each Option.

12. **`autoApplyClass`.** Dropped: `drilldown` is always bound in drilldown mode; Foundation's CSS needs it and a ResponsiveMenu must remove it in other modes. Source: FS `:49-51`; NMS consumer table.
13. **`backButton`, `wrapper`.** Dropped (HTML-string Options); consumer-written elements. Source: BB 1.4; ADR 0008 rule 4.
14. **`backButtonPosition`.** Dropped: the markup order is the switch; the utility's focus rule skips controls inside the back item wherever it is; an input that moved consumer DOM would break rule 4. Foundation's JSDoc "`'left'`" is a doc bug (R:menus 2.3). Source: FS `:99-115`.
15. **`parentLink`.** Dropped (BB 1.4, NMS): a Hybrid item keeps the link beside its toggle; a consumer who wants it inside the level writes an ordinary item (Foundation's `is-submenu-parent-item` has no CSS, FS scss search). Source: FS `:87-89`.
16. **`autoHeight` and `animateHeight`.** Kept with Foundation's defaults: `autoHeight` feeds the utility slot and switches the wrapper from `min-height` of the tallest level to `height` of the current level; `animateHeight` binds Foundation's `animate-height`, whose `transition: height 0.5s` animates it; `animateHeight` alone does nothing, as in Foundation, and warns. The current level is the innermost expanded submenu, so the height moves at the start of open and close, as Foundation's `_show`/`_hide` did. Source: FS `:118-130, 451-497, 505-527`; `_drilldown.scss:82-84`.
17. **`scrollTop`, `scrollTopElement`, `scrollTopOffset`, `animationDuration`, `animationEasing`.** The first three kept: `window.scrollTo({top: targetDocumentTop + scrollTopOffset, behavior})`, `'smooth'` or `'instant'` by `NfsMediaQuery.reducedMotion()` (SS's rule), once per `currentLevel` change after the first render (Foundation fired on up to four events per change); `scrollTopElement` takes an element reference or a CSS selector (typed references first, BB 1.8), `null`/`''` meaning the root. `window.scrollTo` rather than BB Table A's `scrollIntoView`, because `scrollIntoView` cannot add `scrollTopOffset` and scrolls every ancestor, while Foundation scrolled only `html, body`. The two timing Options are dropped (BB 1.4 lists both; the browser owns smooth scrolling). Source: FS `:177-200, 624-653`; SS decision on `'instant'`; R:platform 9.
18. **`closeOnClick`.** Kept, default `false`: while a level is open, a press whose `pointerdown` and `pointerup` both land outside the wrapper calls `collapseAll()`, with document listeners added in an `afterRenderEffect` only while needed; no `preventDefault()` (Foundation's swallowed the outside click, FS `:159-167`). Not the Light dismiss registry: ADR 0024's Escape and focus-out rules exist for content that overlays (1.4.13, 2.4.11), a drilldown level overlays nothing, and those rules would reset the menu whenever focus leaves it; the pointer rule itself is the registry's (AP rule 2), so touch scrolls and drags never reset. Under ResponsiveMenu one binding also reaches DropdownMenu with its own default (the brief's note, NMS). Source: FS; ADR 0024; AP Light dismiss rules.

Round 4: roles, keys, focus.

19. **ARIA model.** Disclosure navigation per level inside one named `nav`, with a back control and focus handoff (R:apg Drilldown option 1, corrected: hidden ancestor levels use `invisible`, not `hidden`, P50 row 9, NMS D9). Why not treeview: the tree keeps ancestors visible and moves focus across all visible levels, while a drilldown hides them, so the tree's Left, Home/End, and typeahead would target nodes the user cannot see; it needs roving `tabindex`, `treeitem`/`group` roles, and `aria-owns`; the APG cautions against it for navigation; and `ngTree` needs `ng-template` groups and `[parent]` inputs. The menu pattern is out of scope (map). Source: APG `treeview-navigation.html` caution; R:apg Drilldown; ADR 0004.
20. **Back button role and label.** Native `<button type="button">` (it does not navigate); visible "Back" (Foundation) plus a `show-for-sr` suffix naming the level it returns to, so the name describes its purpose (2.4.6) and starts with the visible label (2.5.3); no `aria-expanded`/`aria-controls` (it closes a level, it is not a disclosure; the toggle carries the state); a nameless back button warns. Source: R:apg names practice; FS `backButton` default; WCAG 2.4.6, 2.5.3.
21. **Keys.** The NMS drilldown table unchanged (Enter/Space/Right open with focus to the first non-back control; Left/Escape/back close with focus to the toggle; Down/Up within the level; Escape at the root propagates), plus the back button as a native click. Source: NMS drilldown table; FS `:31-39, 209-283`.
22. **Focus after a slide in a long page.** The utility focuses with `preventScroll: true` (P50 row 11), which can leave the focused control above the viewport after a user scrolled a long level. Decided: the completion callbacks run a reveal step, `scrollIntoView({block: 'nearest', inline: 'nearest'})` on the focused control inside the root, after the slide (nothing horizontal left) and with `overflow: clip` (the wrapper is no scroll container, so it cannot scroll sideways); it honours the consumer's `scroll-padding`. Source: P50 rows 11, 12; R:platform 9; WCAG 2.4.11; CSS Overflow 3 (`clip` forbids scrolling).
23. **Every submenu needs a back item.** Development warning: without it a pointer user cannot leave a level, because the parent toggle is `invisible`. Foundation generated one everywhere (FS `:99-115`).
24. **`openPath` and `collapseAll`.** `collapseAll()` keeps `_hideAll()` (NMS consumer table). `openPath(item, {focus})` keeps `_showMenu($ul, autoFocus)`: NMS's amended `open()` does not open closed ancestors, so showing a deep level from code needs the Open path opened top-down and the target's children closed; `null` collapses; a leaf shows the level it is in; a development warning for an item expanded under a closed level points at it. Name from the glossary's proposed "Open path" and BB 1.3's open/close verbs. Source: FS `:398-443`; NMS item API (amended).
25. **Outputs.** Aggregate `opened`/`closed` with the `NfsMenuItem`, after the slide, one `closed` per level on `collapseAll()` (Foundation's four events had mixed timing); `scrollme` dropped (no scroll timing; `scrollend` out of target). Source: BB 1.4 mapping row; NMS usage example (`output<NfsMenuItem>()`).

Round 5: height, animation, render hooks.

26. **Height contract under CSS reuse.** The wrapper binds `min-height` or `height` as host style bindings from a `#heights` signal fed by one ResizeObserver (`borderBoxSize`, created lazily outside the zone in an `afterRenderEffect` that observes the root list and every submenu while in drilldown mode). Inline styles are Foundation's own mechanism; no `--nfs-*` property (AP's reasoning for inline `top`/`left`); no `max-width` (Foundation froze it at init, FS `:524`, breaking fluid layouts; `overflow: clip` confines the levels). RO reports layout size, unaffected by `transform`; the wrapper is never observed, so no loop. BB 1.5's "Renderer2 for inline min-height" example is not followed because a host binding expresses it; the cost is at most one scheduled render after a measurement. Source: P50 row 8; R:platform 10; BB 1.5, 1.13; AP Sass.
27. **Submenu elements for the observer.** NMS exposes `NfsMenuRoot.element` but no `NfsSubmenu.element`; proposed as an additive read-only member (below); until then, a DOM read of the root's `ul[nfsSubmenu]` descendants outside nested roots. Source: NMS API tables.
28. **Slide animation per ADR 0003.** Foundation's `$drilldown-transition` on `is-active`/`is-closing` (State classes), completion by the utility; no Motion class, no `animate.enter`. Height: Foundation's `animate-height`, not awaited (Foundation did not wait for it). Reduced motion: `transition-duration: 1ms` for the slide (NMS rule 12) and for `.is-drilldown.animate-height` (added, ADR 0003's "every library animation"); scrolling `'instant'`. Disabled animations: the utility's `transition: none` on the submenu (NMS amendment) and no `animate-height` binding on the wrapper. Source: ADR 0003; BB 1.6 rules 1, 5; FS `_drilldown.scss:95-113`; NMS Animation (amended).
29. **Render hooks.** Host bindings for classes, `hidden`, heights; constructor for `configure`, registrations, seeding; `afterRenderEffect` for the observer set (`write`), the `closeOnClick` listeners (`write` with cleanup), and `scrollTop` (`earlyRead` measure, `write` scroll, first value skipped); the completion callback (client-only) for the reveal step; `afterNextRender` for `openPath(..., {focus: true})` and development checks; no `effect` (no non-DOM side effect), no `afterEveryRender` (per-render work would run on every change detection). `injectAsync` does not apply: nothing loads only after interaction, and replayed clicks need their handlers at once. Source: BB 1.5, 1.9 lazy services; NMS render-hook table; OC render-hook table.

Round 6: WCAG 2.2 AA, each criterion (the spec's criteria subsection holds the requirements).

30. **1.3.1, 1.3.2**: native nested lists, `aria-controls`; DOM order equals visual order in a level, hidden levels out. Source: R:apg disclosure navigation.
31. **1.4.3**: `$anchor-color` on `$drilldown-background`, 4.65:1 with defaults; no new text pair. Source: NMS 1.4.3 row; FS settings.
32. **1.4.4, 1.4.12**: the ResizeObserver re-measures on text zoom or spacing changes, so no stale height clips text. Source: R:platform 10.
33. **1.4.10**: at 320 px no horizontal scrolling; clipped off-screen levels add no scrollable overflow. Source: CSS Overflow 3; e2e case.
34. **1.4.11**: arrows 4.65:1 by default; compile checks for `$drilldown-arrow-color` against both drilldown backgrounds, `$dropdownmenu-arrow-color` (Foundation's aligned twins, FS `_drilldown.scss:59-71`), and `$accordionmenu-arrow-color` for the Hybrid toggle against `$accordionmenu-submenu-toggle-background` or else `$body-background` and `$drilldown-submenu-background`, whatever `$drilldown-arrows` says (FS `_accordion-menu.scss:137-160` draws it unconditionally); ratios from `color-luminance()` unrounded, because `color-contrast()` rounds to one decimal (NMS amendment; BTN). Source: ADR 0022; BB 1.10.
35. **1.4.13**: not applicable; nothing opens on hover or focus. Source: FS (click and key only).
36. **2.1.1, 2.1.2, 2.4.3**: keyboard for every open and close; Tab leaves after the level's last control; focus handoff. Source: NMS key table; P50 row 10.
37. **2.4.6, 2.5.3**: back button name (decision 20).
38. **2.4.7**: the wrapper must clip, which cuts ring edges (the NMS row accepted top and bottom only; with `autoHeight` the first and last controls would lose three edges); the mixin adds `outline-offset: -2px` on `:focus-visible` links and buttons inside `.is-drilldown`; e2e screenshots of the first and last controls. Source: P50 row 22 (rings per engine); NMS 2.4.7 row.
39. **2.4.11**: levels overlay nothing outside the wrapper; the reveal step and `scroll-padding` keep focus in view; `scrollTopOffset` for fixed headers. Source: decision 22; Sticky spec convention (BB 1.10).
40. **2.5.8**: rows 38 px, toggle 40 px; compile checks for the toggle settings and for rows (`1rem` plus twice the vertical padding, `rem-calc()`) below 24 px, because the story gate sees only the library's settings. Source: P50 row 20; BB 1.10 (Library mixin floors); FS `$global-menu-padding`.
41. **3.2.1, 4.1.2**: focus changes nothing; names from content, `aria-expanded` from state, no roles or `aria-hidden`. Source: NMS rows.
42. **Axe gate.** The six ADR 0018 tags on every story, root level and levels open, after slides settle; no Foundation default fails, so no settings override. Source: ADR 0018; T41 entry 20.

Round 7: rendering modes, Sass, tests.

43. **Server output and replay.** Root level first paint with every class and ARIA; wrapper `is-drilldown` without height (the settle is accepted, BB Table B); toggle and back `click` replay without `preventDefault()`; root `keydown` replays with the one accepted error log (BB Part 4, Decided 3); document listeners never replay; one hydration boundary for wrapper, root, items, and back items; `hydrate never` and no-JavaScript leave only the root level working, so the spec tells consumers to use Hybrid items for reachable landing pages. ResponsiveMenu: wrapper and back bindings follow `root.mode()` in the handoff tick. Source: ADR 0008; R:rendering 7 rules 1 to 11 and the Drilldown checklist row; ADR 0014.

## Prototype needed

None. Every mechanism the spec adds is either Foundation's CSS (`animate-height`, the slide), a platform call whose behaviour is specified (`ResizeObserver`, `window.scrollTo`, `scrollIntoView` with `nearest` under `overflow: clip`, the popover pointer rule already specified by the Anchored pane spec), or the Nested menu utility the prototype carried in three engines. The parts the prototype did not run (`autoHeight`, `animateHeight`, `scrollTop`, `closeOnClick`, a bottom back item, the inset focus ring, the reveal step in a long scrolled page) each have a Playwright e2e case in three engines, and none of their outcomes would change the API.

### Proposed glossary terms

**Drilldown level**:
One list of a Drilldown, the root list or a submenu, shown alone in the Drilldown wrapper while it is the innermost open list.
_Avoid_: panel, pane, screen, page, current menu

**Drilldown wrapper**:
The consumer-written element around a Drilldown's root list that clips the Drilldown levels and carries their measured height; the replacement for Foundation's generated `div.is-drilldown`.
_Avoid_: wrapper component (which adds an element inside a component), container, viewport

### Proposed ADR

None. The domain-modeling bar needs all three of hard to reverse, surprising, and a real trade-off. The public names (entry point, `openPath`) are hard to reverse but follow existing rules (SC, BB 1.3) rather than surprise; the `closeOnClick` pointer rule, the height bindings, the reveal step, and the inset ring are surprising or traded off but local to the plugin and reversible in one place. ADRs 0001, 0003, 0004, 0008, 0012, 0022, 0024, and 0033 already cover the architectural choices this spec relies on.
