## Question

Can host-directive wrappers satisfy Aria's required link inputs while panel content is projected (not Aria's `ng-template` content directives, which render empty in server HTML), keeping `.accordion-title` as a button inside a heading, `.tabs-title > a[aria-selected]`, `.is-active` on the list items, and the grid `0fr -> 1fr` height animation? Does Aria's tab panel need a template child (`ngTabContent`) that only a panel component can supply, or can `[nfsTabsPanel]` stay a directive? (This decides whether `.tabs-panel` is a wrapper component, `building-blocks.md` 1.1 case 2.) What does a replayed arrow key do, given Aria calls `preventDefault()` after its handler and `preventDefault()` throws during event replay? Only if composition fails, estimate the cost of the fallback (custom ARIA and keys over CDK accordion state) from sources; do not build it.

Read first: `building-blocks.md` (the matrix row and the open risk this prototype settles), `adr/*.md`, `research/angular-aria-inventory.md`, `research/foundation-inventory-disclosure.md`, `research/aria-apg-patterns.md`, `research/angular-rendering-modes.md`, `research/di-and-composition-patterns.md`.

### Verdict

Composition works, so no fallback was built or estimated. Host-directive wrappers on Foundation's markup (`ul.accordion > li.accordion-item > (h3 > button.accordion-title) + div.accordion-content`, and a wrapping element around `ul.tabs > li.tabs-title > a` plus `.tabs-content > .tabs-panel`) satisfy Aria's link inputs. For `AccordionTrigger.panel` there is one limit. It is `input.required`, and a wrapper can neither set it from code nor hide it: NG2019 forces the wrapper to expose it and NG8008 forces the consumer to bind it. The consumer therefore writes one template-reference binding per item. Two forms work: `#p="ngAccordionPanel"` (host-directive `exportAs` names can be referenced) and `#c="nfsAccordionContent"` with `[panel]="c.panel"`. The tab pairing is two static `value` attributes. With projected content the open accordion panel and the selected tab panel are in server HTML, and the collapsed and hidden panels carry `inert`. `.is-active` binds on `li.accordion-item`, `li.tabs-title` and `.tabs-panel`. Foundation's `.accordion-content { display: none }` is replaced, at equal specificity, by a documented grid rule, and the `0fr -> 1fr` row animation runs in all three engines. `[nfsTabsPanel]` stays a directive. Aria's `TabPanel` works without `ngTabContent`; leaving it out only produces a dev-mode `console.warn`, which a panel component could not silence either, because Aria's check reads the consumer's content children. A replayed arrow key, Enter or Space changes state exactly as a live key would. Then Aria's trailing `preventDefault()` throws, and Angular's `ErrorHandler` logs ``ERROR Error: `preventDefault` called during event replay.`` once per replayed key; nothing reaches `window.onerror`. Enter and Space toggle once, not twice, because Aria's `ClickEventManager` ignores the synthetic click. The throw also skips Aria's `stopPropagation()`, so a replayed key in a nested accordion is handled again by the outer group and focus lands on the wrong trigger. A `keydown` listener on the wrapper's own host that calls `stopPropagation()` again for Aria's keys fixes that in all three engines. Two further limits of composition: the wrapper cannot change the default of an Aria `input()` (Foundation `multiExpand=false` against Aria's `multiExpandable=true`), but it can write Aria `model()`s. Defaulting `TabList.selectedTab` to the first tab on the server gives unbound tab sets a panel at first paint, with no NG0100.

Exact error text:

- `NG2019: Required input 'panel' from host directive AccordionTrigger must be exposed.` (wrapper lists `AccordionTrigger` without `panel` in `inputs`). The consumer's `[panel]` bindings then also fail with `NG8002: Can't bind to 'panel' since it isn't a known property of 'button'.`
- `NG8008: Required input 'panel' from directive AccordionTrigger must be specified.` (consumer omits `[panel]`)
- Replay, Chromium and WebKit: ``ERROR Error: `preventDefault` called during event replay.`` (`console.error` from `ErrorHandler`). Firefox prints the same call as `ERROR Error`, because Playwright's console text for Firefox does not serialise the Error argument. The throw is the same code path (`event_dispatcher.ts`).

### What the prototype does not prove

- Incremental hydration (`@defer (hydrate on ...)`) and prerendering: only full hydration under `RenderMode.Server` was run. Prerendering produces the same server HTML at build time, but its replay was not exercised.
- Aria's opt-in lazy mode (`ng-template[ngAccordionContent]` / `[ngTabContent]` inside the wrappers), `preserveContent`, deep links, `allowAllClosed`, RTL, reduced motion, and the `@supports` fallback. The `@supports not (grid-template-rows: 0fr)` guard from building-blocks 1.6 rule 3 was left out: it tests parsing, not interpolation, so it cannot detect a browser that snaps, and every target browser interpolates `fr` tracks.
- Tabs on `<a href="#...">`: only anchors without `href` were tested. Aria's `ClickEventManager` does not call `preventDefault()` (`preventDefault: false`), so source reading says an `href` would also navigate the hash.
- Replay of a nested tab list (for example tabs inside an accordion panel) and of tab-list keys under the guard: the same `KeyboardEventManager` path is used, but only the nested accordion was run.
- A fix for tab sets being unreachable by the Tab key before hydration (case 10); an `extends AccordionPanel` wrapper (a third way to type the `panel` reference) was not tried.
- Screen-reader output, find-in-page on clipped `inert` content, touch devices; the development-build console was captured in Chromium only.

### Decisions handed to the specs

- [Spec: Accordion](15-spec-accordion.md): Aria composition is confirmed (`@angular/aria` level; the CDK fallback is not needed). `button[nfsAccordionTitle]` hosts `AccordionTrigger` and exposes `panel`. The consumer binds `panel` once per item, and the spec chooses between the two proven reference forms (cases 2 and 3). `[nfsAccordionContent]` is the attribute-selector wrapper component hosting `AccordionPanel` with a single wrapper `div`. `li[nfsAccordionItem]` binds `.is-active` from its title's `expanded`. Foundation's `multiExpand=false` default cannot be reached through composition (cases 4 and 5): the spec either records `multiExpand` defaulting to `true` as a delta from Foundation (1.4), or has the wrapper enforce single expand through the triggers' `expanded` models (untested). The group wrapper carries the replay guard from case 25. The spec also settles the accessible-name flaw from Foundation's `::before` icon (case 19); CSS alternative text for `content` is outside the browser target (Firefox 119).
- [Spec: Tabs](16-spec-tabs.md): `[nfsTabsPanel]` is a directive, not a component (building-blocks 1.1 case 2 does not apply), binding `.is-active` from `TabPanel.visible()`. `a[nfsTab]` hosts `Tab` and carries `aria-selected`; `li[nfsTabsTitle]` binds `role="presentation"` and `.is-active` from its child tab. `[nfsTabsGroup]` hosts `Tabs`, and nothing in the prototype needed a `[nfsTabsContent]` directive. When `selected` is unbound, `ul[nfsTabs]` writes the first tab into Aria's `selectedTab` model so server HTML shows a panel (case 6). The spec must also decide how a tab becomes reachable by the Tab key before hydration (case 10), and document Foundation's default tab contrast (case 18).
- [Spec: Responsive Accordion Tabs](19-spec-responsive-accordion-tabs.md) and [Prototype: ResponsiveAccordionTabs as one component](51-prototype-responsive-accordion-tabs.md): both directive sets compose and hydrate cleanly. The component owns its template, so it can write the `[panel]` references and the tab `value`s itself. It inherits the first-tab default, the replay guard, and the pre-hydration tab-stop question.
- [Spec: Orbit](33-spec-orbit.md): bullets on `Tab`/`TabList` and slides on `TabPanel` as directives with value pairing work without `ngTabContent`. Server HTML needs a selected bullet (bound, or the first-tab model write). Replayed arrow keys on bullets log the same error, and the bullets are not reachable by the Tab key before hydration.
- All Aria-hosted specs: panel content is projected by default, and the Aria dev-mode warnings in case 17 come with that choice (OPEN FOR HUMAN 1).

### Custom CSS (all in the `nfs-accordion` mixin, `src/_nfs-accordion.scss`, imported after Foundation per ADR 0012)

1. `.accordion-item > :is(h1, h2, h3, h4, h5, h6) { margin: 0; }`: the APG heading is only a semantic container, and Foundation's base typography gives headings a bottom margin.
2. `button.accordion-title { width: 100%; text-align: start; cursor: pointer; }`: Foundation assumes `<a class="accordion-title">`. A button neither stretches nor left-aligns, and Foundation's button reset sets `cursor: auto`.
3. `:is(h1, h2, h3, h4, h5, h6) > .accordion-title { @include accordion-title; }`: re-includes Foundation's own mixin so its two child-combinator rules (`:last-child:not(.is-active) > &` for the closed last item's border, `.is-active > &::before` for the minus icon) match again once a heading sits between the item and the title. It adds no values of its own; the output repeats Foundation's declarations from the consumer's settings.
4. `.accordion-content { display: grid; grid-template-rows: 1fr; transition: grid-template-rows, padding-block; }` and `.accordion-item:not(.is-active) > .accordion-content { grid-template-rows: 0fr; padding-block: 0; border-block-width: 0; }`: Foundation hides the content with `display: none` and shows it only through jQuery inline styles. These rules show it as a one-row grid and animate the row. Collapsed, the item looks like Foundation's `display: none` one; open, Foundation's own padding and border apply untouched.
5. `.nfs-accordion-content-body { min-height: 0; overflow: hidden; }`: the single wrapper child that the grid row clips.
6. `@media (prefers-reduced-motion: reduce) { .accordion-content { transition-duration: 1ms; } }`: a stand-in for the library-wide rule in `_nfs-motion.scss` (building-blocks 1.6 rule 5).

Tabs needed no custom CSS: Foundation's `.tabs-panel.is-active` and `.tabs-title > a[aria-selected='true']` cover it.

### OPEN FOR HUMAN

1. Aria's dev-mode check warns on every panel whose content is projected rather than placed in `ngAccordionContent`/`ngTabContent` (case 17: two `console.warn` lines per panel in development builds). The library cannot silence it; neither a directive nor a wrapper component can supply the content child Aria queries. Should the library accept and document the warnings, or should an issue be filed in angular/components asking that projected content be allowed without the template directive? Filing in that repository needs the user's confirmation.
2. Building-blocks Part 4 item 3 stands, now observed. Every replayed Aria-handled key logs ``ERROR Error: `preventDefault` called during event replay.`` from Aria's own `KeyboardEventManager`, not from a library handler, so "`preventDefault()` last" in library code does not prevent it. The choices are: (a) accept the log (state is correct, and nesting is fixed by the case 25 guard); (b) drop replayed keys by stopping propagation at the trigger when `event.eventPhase === 101`, which needs the internal constant and loses the user's key; (c) ask angular/components to skip `preventDefault()` during replay in its event manager (filing needs the user's confirmation).
