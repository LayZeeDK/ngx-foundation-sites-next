## Part 1. Cross-cutting decisions

### 1.1 Directive or component

Rule (ADR 0001): a plugin becomes attribute directives on the Foundation markup the consumer already writes. A component is allowed only where Foundation's JavaScript builds structure the consumer never writes and that structure cannot be expressed as a single consumer-written element. Three cases qualify:

1. `ResponsiveAccordionTabs` renders one of two markup trees from the same content and must swap heading-plus-button semantics for tab semantics (`R:apg` ResponsiveAccordionTabs; `R:disclosure` ResponsiveAccordionTabs "Behaviour that only jQuery makes easy"). It is the one element-selector component: `nfs-responsive-accordion-tabs`.
2. Content wrappers that need one extra element for a CSS-only height animation: `.accordion-content` and `.tabs-panel` become attribute-selector components (`[nfsAccordionContent]`, `[nfsTabsPanel]`) whose template is a single wrapper around `<ng-content>` (the grid-row trick in 1.6 needs the wrapper; Material does the same, `R:material` 1 Animation). The Foundation class stays on the host element the consumer wrote.
3. Elements Foundation generates that the consumer should not author: the Tooltip tip (`.tooltip`, created by the plugin and never written by hand, `R:positioned` Tooltip 2). The Tooltip *directive* sits on the trigger and creates an internal `NfsTooltipTip` component on first show. Everything else Foundation generates (Reveal overlay, off-canvas overlay, drilldown wrapper and back buttons, sticky container, accordion-menu toggle button, parent-link clones) is either replaced by a platform feature (`::backdrop` for the Reveal overlay), authored by the consumer as one plain element with a directive on it (off-canvas overlay, drilldown back button, sticky container, submenu toggle), or dropped (parent-link clones, `wrapper`/`backButton`/`container`/`template` HTML-string options).

Why this and not the repo skill's "container = component" table: the skill's table predates the user's directive-over-component preference and Aria's all-directive shape (`R:aria` 1.4, `R:material` 1 "Directive or component"). The skill's rule that survives is "one directive or component per structural Foundation CSS class" (foundation-api-design SKILL.md, Naming Conventions); Part 2 applies it row by row, and state classes (`.is-active`, `.is-open`, `.is-stuck`) are host class bindings, never directives.

Consequence: every directive works on server-rendered markup with no DOM creation before hydration (1.11), and the consumer keeps Foundation's docs markup almost verbatim; the deltas (`<a href="#">` becomes `<button>`, `<div class="reveal">` becomes `<dialog class="reveal">`) are listed per spec.

### 1.2 Implementation level and the browser target

Order per plugin: native platform feature, then `@angular/aria`, then `@angular/cdk`, then custom Angular. A spec stops at the first level that covers the behaviour with the browser target applied, and states the fallback if a prototype fails that level.

Browser target (user decision): Baseline widely available on 2026-05-07, Chrome/Edge/Firefox 119 and Safari 17 (map, Notes). Applied from `R:platform` Feature summary:

| Usable without fallback | Not usable (needs fallback or is out) |
| --- | --- |
| `<dialog>`, `showModal()`, top layer, `::backdrop`, `:modal`; `<details>`/`<summary>` and `toggle`; `position: sticky`; scroll snap, `scrollIntoView()` with options, `scroll-behavior`, `scroll-margin`/`scroll-padding`; IntersectionObserver, ResizeObserver, MutationObserver; container size queries and `cq*` units; `<picture>`, `srcset`, `sizes`, `<img loading="lazy">`; Constraint Validation API, `:user-invalid`; `<input type="range">`, `appearance: none`; `inert`; `prefers-reduced-motion`; `inputmode`; CSS grid `fr` interpolation; `matchMedia` and `MediaQueryList.change`; Pointer Events; `transitionend`/`animationend` | `popover` (all states), `popovertarget`; CSS anchor positioning; `<details name>`; `::details-content`; `interpolate-size`/`calc-size()`; `@starting-style`; `transition-behavior: allow-discrete`; `overlay`; scroll-driven animations; `scrollend`; container style and scroll-state queries; `sizes="auto"`; `<iframe loading="lazy">`; vertical form controls via `writing-mode`; `::slider-*`; `:has()`; View Transitions; Invoker Commands; `CloseWatcher`; `dialog.closedby`, `dialog.requestClose()` |

Rules that follow:

- No progressive enhancement onto a not-usable feature in the first specs: one code path per behaviour, because two paths double the test matrix and the not-usable features become usable only when the target moves with Angular. Each spec names the feature it would adopt then (for example anchor positioning for Dropdown) under Further Notes.
- `:has()` is not used in library CSS; parent state classes are bound by the directives instead (`R:platform` 16).
- CDK is used where it is the smallest correct piece, not as a framework: `MediaMatcher` (1.7), `_IdGenerator` (1.9), `Directionality` (RTL), `InteractivityChecker` (initial focus targets), `FocusTrap` only where native focus containment is unavailable (OffCanvas modal mode). CDK Overlay, Dialog, Menu, Accordion and Listbox are not used (ADR 0002, ADR 0007, 1.9); nothing in CDK is deprecated in favour of Aria, but the higher levels cover those cases (`R:cdk` Cross-cutting notes).
- Aria is used for Accordion, Tabs, and Orbit's bullet tablist. It is not used for the menus (ADR 0004), Dropdown, Reveal, OffCanvas, Tooltip, Slider (no Aria pattern exists, `R:aria` 10).

### 1.3 Naming

- Selector prefix: `nfs` for directives (`[nfsAccordion]`), `nfs-` for components (`nfs-responsive-accordion-tabs`), per AGENTS.md Workspace. Attribute-selector components keep the directive form (`[nfsAccordionContent]`).
- Class names: `Nfs` plus PascalCase of the Foundation structural CSS class the directive sits on (`.accordion-title` -> `NfsAccordionTitle`, `.dropdown-pane` -> `NfsDropdownPane`, `.off-canvas-content` -> `NfsOffCanvasContent`). When a plugin has no structural class of its own (Interchange, Magellan, SmoothScroll, Toggler, Equalizer, ResponsiveToggle, ResponsiveMenu), the plugin name is used. The `Nfs` prefix is kept, against the v20 style guide's suffix-less bare names, because the library imports Aria's bare `Tabs`, `Menu`, `Tab`, `Option` classes and Material-style names would collide (`R:di` 8 Selector conventions; naming-conventions.md "Avoid Namespace Collisions").
- Plugin name mapping: Reveal stays `NfsReveal`; Drilldown is `NfsDrilldown` (Foundation class `Drilldown`, CSS `.drilldown`; the docs page title "Drilldown Menu" is not used); OffCanvas is `NfsOffCanvas` with selector `nfsOffCanvas` and files `off-canvas/off-canvas.ts` (Foundation's own hyphenation `off-canvas`, `R:utilities` 1.1); DropdownMenu is `NfsDropdownMenu` on `ul.dropdown.menu`; Dropdown (the pane plugin) is `NfsDropdownPane` because `.dropdown` alone is Button's arrow class and `.dropdown.menu` is DropdownMenu.
- Files: v20 suffix-less kebab-case, one folder per plugin as a secondary entry point (`accordion/accordion.ts`, `accordion/accordion-title.ts`, `accordion/accordion-tokens.ts`, `accordion/accordion.spec.ts`, `accordion/accordion.stories.ts`, `accordion/_accordion.scss` for documented custom CSS). Entry point `ngx-foundation-sites/<plugin>` so a consumer's `@defer` block can split per plugin (1.11).
- Tokens: camelCase with the `Token` suffix, `nfsAccordionToken`, `nfsTooltipDefaultsToken` (AGENTS.md Design Philosophy 6; the guide's `LibHeaderToken` naming, `R:di` 1). This departs from CDK/Material `MAT_` and Aria bare `SCREAMING_SNAKE`; recorded so nobody "fixes" it.
- Outputs and methods: Material vocabulary (`R:di` 8; `R:material` 0.1): `open()`, `close()`, `toggle()`, `expandAll()`, `collapseAll()`, `show()`, `hide()`; outputs `opened`, `closed`, `selectedChange`-style `xChange` companions from `model()`, never an `on` prefix.
- Story ids: `<plugin>--<story>` in kebab case, named in each spec's Testing Decisions so play functions and Playwright open the same artifact (`R:tooling` Recommended test pyramid).

### 1.4 Inputs and outputs

- Every Foundation `data-*` option becomes `input()` under its camelCase name with `booleanAttribute` or `numberAttribute` transforms so attribute strings coerce (`R:angular` input/model/output; `R:cdk` coercion). Defaults are Foundation's unless the APG or Aria forces a change, and the spec lists each such delta (example: Accordion keeps `multiExpand=false`; Orbit gains a required rotation control).
- `model()` for the state Foundation exposes as both a method and an event: `expanded` (accordion item, accordion-menu and drilldown and dropdown-menu items, toggler in disclosure mode), `open` (Reveal, Dropdown pane, OffCanvas, Tooltip, ResponsiveToggle), `selected` (tab list value, Orbit active slide), `value` (Slider), `active` (Magellan current target, Toggler class mode), `stuck` is read-only (`computed`) because the browser owns it.
- `linkedSignal` for derived-but-writable state (Aria `TabList.selectedTab`, `R:di` 8), including the `set` write-back form when a child writes into a parent model (`R:angular` linkedSignal).
- Output naming rule: state changes are the `xChange` output the model generates; completion events are past-tense verbs emitted when the state change is committed and its enter or leave animation has finished (`opened`, `closed`, `expanded` is not reused as an event: accordion items emit `opened`/`closed` like `CdkAccordionItem`, `R:di` 8). No "start" events: Foundation's mixed timing (`open.zf.reveal` synchronous, `closed.zf.reveal` after animation, `opened.zf.offCanvas` at transition start despite its name, `R:disclosure` Events, `R:menus` 6.4) is not copied. Where a consumer must veto a close, the spec adds a predicate input (Material `closePredicate`, `R:material` 3), not a cancelable event.
- Container-level aggregate outputs carry the item instance (`{item, value}` shape from Material `MatTabChangeEvent`, `R:material` 2); item-level outputs are `void`.
- Foundation event to output mapping, applied per spec: `down/up.zf.accordion` -> item `opened`/`closed` plus container `opened`/`closed` with item payload; `change.zf.tabs` -> `selectedChange`; `collapse.zf.tabs` -> `closed`; `deeplink.zf.*` -> `deepLinked`; `on/off.zf.toggler` -> `activeChange` (class mode) or `opened`/`closed` (disclosure mode); `open/closed.zf.reveal`, `opened/closed.zf.offCanvas`, `show/hide.zf.dropdown`, `show/hide.zf.tooltip`, `show/hide.zf.dropdownMenu`, `open/hide/close/closed.zf.drilldown`, `down/up.zf.accordionMenu` -> `opened`/`closed`; `sticky.zf.stuckto/unstuckfrom` -> `stuck`/`unstuck` with the edge as payload; `update.zf.magellan` -> `activeChange`; `slidechange.zf.orbit` -> `selectedChange`, `beforeslidechange` dropped; `moved/changed.zf.slider` -> native `input`/`change` plus `valueChange`; `valid/invalid/formvalid/forminvalid/formreset.zf.abide` -> Signal Forms field state, no outputs; `replaced.zf.interchange` -> `replaced`; `preequalized/postequalized.zf.equalizer` -> `equalized`; `toggled.zf.responsiveToggle` -> `openChange`; `init.zf.*` and `destroyed.zf.*` have no counterpart (Angular lifecycle).
- Options that exist only because of jQuery or DOM strings are dropped and listed per spec under "Dropped options": `data-options`; HTML-string options (`backButton`, `wrapper`, `container`, `template`, `allowHtml`); class-name options (`linkClass`, `panelClass`, `linkActiveClass`, `panelActiveClass`, `stickyClass`, `containerClass`, `verticalClass`, `rightClass`, `tooltipClass`, `triggerClass`, `templateClasses`, `activeClass`, `disabledClass`) because the classes are the contract; timing options that CSS or the browser now owns (`slideSpeed`, `moveTime`, `fadeInDuration`, `fadeOutDuration`, `showDelay`, `hideDelay` for Reveal, `animationDuration`, `animationEasing`, `deepLinkSmudgeDelay`, `transitionTime`); `parentLink`; `resetOnClose`; `appendTo`; `forceFollow`; `touchCloseText`; `invertVertical` (dead); `checkEvery`; `dynamicHeight`; Interchange `type` and `rules` string parsing (1.4 keeps a typed `rules` input); `useMUI`; `accessible` (always on); `data-toggle-focus` (toggle on both focus and blur, `R:disclosure` Triggers).
- Motion class options stay as string inputs (`animationIn`, `animationOut`, `animate`, `animInFromRight` and friends) and feed 1.6.
- Global defaults (`Foundation.X.defaults.y = ...`) become one optional defaults token per plugin, Material shape B (`nfsRevealDefaultsToken` with an all-optional `NfsRevealDefaults` interface, `inject(token, {optional: true})` seeding input defaults; `R:di` 5). The token is provided at bootstrap, route, or element level and the nearest wins.

### 1.5 State, reactivity, DOM access

- All state is signals read from `host` bindings or templates; OnPush is the v22 default and zoneless is assumed (`R:angular` Zoneless and OnPush defaults). Anything driven by a timer, observer, or native listener writes into a signal; no `markForCheck`, no `NgZone`.
- `computed` for derived read-only state; `effect` only for side effects that are not DOM (history writes, timers) and never to propagate state between signals (`R:angular` effect guidance).
- DOM reads and writes that need layout (measure a pane, a slide, a drilldown submenu, a sticky sentinel) run in `afterRenderEffect` with explicit `earlyRead`/`write`/`read` phases, or in the callback of a `ResizeObserver`/`IntersectionObserver`/`MutationObserver` created in `afterNextRender`; never in `ngAfterViewChecked`, never at construction (`R:angular` effect and afterRenderEffect; hydration constraints in 1.11).
- Host bindings do the class and attribute work (`[class.is-active]`, `[attr.aria-expanded]`, `[attr.inert]`, `[attr.hidden]`); `Renderer2` and `ElementRef.nativeElement` writes are limited to values host bindings cannot express (inline `min-height` from a measurement, `scrollTo`, `focus()`, `showModal()`).
- `DOCUMENT` from `@angular/core`; `window` only inside render callbacks; `matchMedia` only through the Breakpoint service (1.7); `history`/`location` only after first render (1.11).
- Services are warranted only for state shared across instances: the Breakpoint service (1.7) and the Light dismiss registry (Part 3, Anchored pane). Everything else is directive-local state plus DI links (1.9). Services use `@Service()` (`R:angular` Dependency injection).
- Ids: consumer-supplied `id` wins; generated ids come from CDK `_IdGenerator` with a plugin prefix (`nfs-accordion-panel-`) (`R:di` 9, `R:aria` 1.4). Generated ids differ between server and client (`_IdGenerator` adds a per-process random infix and its counter is module-global across requests, `research/angular-rendering-modes.md` 1 and 7 rule 8), which is harmless only because every reference to a generated id (`aria-controls`, `aria-labelledby`, `aria-describedby`) is itself a host binding rewritten at hydration. Anything addressed from outside the app (hash deep links, Magellan targets, Reveal `deepLink`) requires a consumer-supplied id; the deep-linking inputs warn in dev mode when the id was generated.
- RTL: `Directionality.valueSignal` from `@angular/cdk/bidi`, never `html[dir]` reads; CSS logical properties in library CSS (`R:utilities` 10 `rtl()`).
- Keyboard: `event.key` comparisons (`'Escape'`, `'ArrowDown'`) and `hasModifierKey` from `@angular/cdk/keycodes`; no `keyCode` (`R:cdk` keycodes). Aria owns the keyboard where it is hosted; the disclosure menus and Orbit implement the APG key tables directly. Every library key handler changes state first and calls `preventDefault()` last, because `preventDefault()` throws during event replay and skips everything after it (1.11).
- Effects: `effect()` runs on the server, so an effect never writes the DOM (a write there lands in the serialised HTML behind Angular's back, `research/angular-rendering-modes.md` 1).

### 1.6 Animation mechanics (ADR 0003)

User rule: no `@angular/animations`, no JavaScript-timed animation; `animate.enter`/`animate.leave` plus native CSS. The shared mechanics:

1. Elements that stay in the DOM and change state (dialog open/closed, off-canvas open, dropdown pane open, drilldown submenu active, tooltip visible, sticky stuck): a State class bound by the directive plus a CSS `transition` or `@keyframes` in the stylesheet. Foundation's own transitions are reused where they exist (`.drilldown` `$drilldown-transition`, `.off-canvas` `$offcanvas-transition-length`, `.tabs-content` transition, `R:menus` 2.8 and 6.8). The directive waits for `transitionend`/`animationend` on its host (filtered by `event.target`) before emitting `opened`/`closed` and before any DOM step that must follow the animation (`dialog.close()` after the exit keyframes, focus moves after a drilldown slide). A fallback timer of the declared duration plus 100 ms covers stylesheets that removed the transition (Material's mechanic, `R:material` 0.2), and reduced motion resolves the wait synchronously.
2. Elements the library inserts or removes (Lazy content templates, the Tooltip tip component, Orbit slides when the scroll-snap prototype fails, deferred content): `animate.enter="<classes>"` and `animate.leave="<classes>"` as host bindings on the inserted element with a class list from the plugin's `animationIn`/`animationOut`-style inputs (`R:angular` Animations; the host-binding form is documented in `enter-and-leave.md`).
3. Auto-height (Accordion, AccordionMenu, ResponsiveAccordionTabs in accordion mode): the CSS grid trick, `grid-template-rows: 0fr -> 1fr` on the content host with a single wrapper child (`overflow: hidden`), transition on `grid-template-rows`, `@supports not (grid-template-rows: 0fr)` disables the transition (`R:material` 1 Animation; `R:platform` 5 fallbacks; `interpolate-size` is out of target). This is why `.accordion-content` is an attribute-selector component (1.1). Drilldown keeps Foundation's transform slide and the wrapper `min-height` measured with `ResizeObserver` (`R:menus` 2.2, 2.9); `animateHeight` maps to Foundation's `.animate-height` class.
4. Motion classes: the library ships `_nfs-motion.scss` with `@keyframes`-based classes under Foundation's Motion UI names prefixed `nfs-` for every default a spec needs (`nfs-fade-in`, `nfs-fade-out`, `nfs-slide-in-down`, `nfs-slide-out-up`, `nfs-slide-in-right`, `nfs-slide-out-left` and the mirror pair, `nfs-hinge-in-from-top`, `nfs-spin-out`). Consumer-supplied class names are passed through unchanged to `animate.enter`/`animate.leave` and must be keyframe animations. Motion UI's own transition classes depend on the two-frame `mui-enter` then `mui-enter-active` protocol (`R:utilities` 4.1) that `animate.enter` does not perform and `@starting-style` (out of target) would replace; whether they can be supported through the `(animate.enter)` callback form is prototype P6 (Part 4). The `motion-ui` package is never a dependency (map, Out of scope).
5. Reduced motion: `_nfs-motion.scss` sets `animation-duration: 1ms` and `transition-duration: 1ms` for every library animation under `@media (prefers-reduced-motion: reduce)` so `animationend` still fires and state changes stay instant; the Breakpoint service exposes `reducedMotion()` as a signal so Orbit autoplay and smooth scrolling switch off (`R:platform` 18). A `nfsAnimationsToken` with `{disabled: boolean}` (Material `MATERIAL_ANIMATIONS` shape, `R:di` 5) disables animations globally and is what tests provide; `TestBed` `animationsEnabled` stays false in specs.
6. `MAX_ANIMATION_TIMEOUT` is left at Angular's default (4 s); no library animation exceeds 1 s.
7. Rendering modes: `animate.enter`/`animate.leave` never run on the server, so no enter classes are in server HTML; whether a server-rendered element carrying `animate.enter` plays its enter animation at hydration is unverified (prototype P11). Rule 2 is therefore used only for elements that are never server-rendered in their animated state (the Tooltip tip, client-created lazy views, the Orbit fallback slides inserted after a user action); persistent elements use rule 1.

### 1.7 Breakpoints (ADR 0005)

- Source of truth for JavaScript: `nfsBreakpointsToken`, an `InjectionToken<NfsBreakpointMap>` with a root factory returning Foundation's default map (`small: 0, medium: 640, large: 1024, xlarge: 1200, xxlarge: 1440` in px, `R:utilities` 3.1) plus `serverBreakpoint: 'small'`. A consumer with a customised Sass `$breakpoints` provides the same values here; the library Sass also emits them as `--nfs-breakpoint-<name>` custom properties on `:root`, and a dev-mode `afterNextRender` check warns when the token and the CSS disagree. Foundation's `meta.foundation-mq` font-family handshake is not used: it needs computed style, which SSR does not have (`R:utilities` 10 MediaQuery).
- Service: `NfsMediaQuery` (`@Service()`), wrapping CDK `MediaMatcher` (SSR-safe noop stub, `R:cdk` layout) and exposing Foundation's API as signals: `current()`, `atLeast(name)`, `upTo(name)`, `only(name)`, `is('medium down')`, plus `reducedMotion()`. Queries are Foundation's `only screen and (min-width: <em>)` strings built from the token (`R:forms-media` Interchange named queries). `BreakpointObserver` and Material's `Breakpoints` constants are not used (`R:material` 11).
- Server value: `serverBreakpoint` (default `small`, Foundation's mobile-first base) so server HTML is deterministic; consumers can set it from client hints in `app.config.server.ts` via a request-scoped factory (`ssr.md` Setting providers on the server). The first client render may swap a breakpoint-gated mode; the spec for each gated plugin (ResponsiveMenu, ResponsiveToggle, ResponsiveAccordionTabs, Sticky, Equalizer, Interchange, OffCanvas reveal, Tooltip `showOn`) states what changes and how focus is preserved. Ticket 38 found no Angular-provided client-hint mechanism, so the recipe (a `useFactory` provider reading `REQUEST` headers, which is null when prerendering) belongs to the Breakpoint service spec (S1).
- CSS first: when only styling changes with the breakpoint, the spec uses Foundation's `.show-for-*`, `.hide-for-*`, `.<bp>-horizontal`, `.reveal-for-<bp>`, `.in-canvas-for-<bp>` classes and no JavaScript. Container queries are allowed inside library CSS for component-internal sizing only; breakpoint-named options keep viewport semantics because Foundation documents them that way (`R:platform` 11 Known gaps).
- Option syntax: `data-responsive-menu="drilldown medium-dropdown"` and `data-responsive-accordion-tabs="accordion medium-tabs"` keep their rule-string form as the `rules` input (the string is Foundation's documented contract); the parser is shared and typed (`{small: 'drilldown', medium: 'dropdown'}` object form also accepted).

### 1.8 Triggers

Foundation's `data-open`, `data-close`, `data-toggle` become three directives in a shared spec (Part 3): `[nfsOpen]`, `[nfsClose]`, `[nfsToggle]`. Each takes a template reference to an Openable (or an array for Foundation's space-separated multi-target form); `[nfsClose]` and `[nfsToggle]` with no value act on the nearest Openable ancestor through DI, which is Foundation's empty `data-close` bubbling rule (`R:utilities` 2.2). The Openable contract is a lightweight token (`nfsOpenableToken`) with `open()`, `close()`, `toggle()`, `open` (signal), `id`, and a `triggerRole` hint (`'disclosure' | 'dialog' | 'none'`) so the trigger sets `aria-expanded` plus `aria-controls` for disclosures, `aria-haspopup="dialog"` plus `aria-controls` for Reveal, and nothing extra for plain commands (`R:apg` Dropdown delta on `aria-haspopup`). Reveal, OffCanvas, DropdownPane, Toggler, ResponsiveToggle and Tooltip provide the token. Triggers must be native `<button type="button">` (or a link when it also navigates); the directive warns in dev mode on a non-focusable host (`R:apg` Toggler delta). Invoker Commands and `popovertarget` are out of target and not used; `<form method="dialog">` inside a Reveal is documented as a platform alternative for close buttons. `data-closable` (remove an element with an animation) is not a directive: the consumer writes `@if` with `animate.leave`. `closeme.zf.*` becomes the Light dismiss registry (Part 3).

### 1.9 DI patterns

Adopted from `R:di` 9 (the catalogue):

- Parent handle: `InjectionToken<Parent>` in `<plugin>-tokens.ts` with `import type`, parent `providers: [{provide: nfsXToken, useExisting: NfsX}]`, child `inject(nfsXToken)` required when the child cannot exist alone (accordion title inside an item), `{optional: true}` with a dev-mode `reportViolations`-style warning when the child may stand alone (menu item outside a menu root). Nested containers re-provide the token as `undefined` (`CdkAccordionItem` pattern) so grandchildren do not register upward.
- Same-element siblings: `inject(X, {self: true, optional: true})` (Abide's input directive reading `FORM_FIELD` from `@angular/forms/signals`, and `NgControl` as a courtesy).
- Projected child that must fail outside its parent: `inject(Parent, {host: true})`.
- Ordered children: parent-owned registration (`register()` in `ngOnInit`, `unregister()` on destroy) with DOM-order sorting from a `MutationObserver` started in `afterNextRender`, Aria's `SortedCollection` shape, rather than `contentChildren` queries, because it survives `@for`, `@defer`, Lazy content and projection (`R:di` 3c). `contentChildren` is used only for dev-mode validation.
- Links between non-nested elements: template references on inputs (`[nfsOpen]="reveal"`, Aria `[panel]`) or value-keyed pairing (`nfsTab value="x"` with `nfsTabsPanel value="x"`).
- Aria composition: a Foundation-classed directive hosts the Aria directive through `hostDirectives`, exposes only the Aria inputs it wants (aliased to Foundation names), adds the Foundation class and State classes in `host`, and reaches the Aria instance with `inject(AriaDirective)` (the `simple-menu.ts` shape, `R:di` 4). The wrapper's host bindings win. Risk: Aria link inputs declared `input.required` (`AccordionTrigger.panel`) cannot be set by the wrapper from code; prototype P2 settles whether Accordion composes or falls back (Part 4).
- Defaults tokens: one Shape B `nfsXDefaultsToken` per plugin (1.4). A single `provideNfs*()` function is not needed; none of Aria or CDK ships one (`R:di` 5).
- Platform guard: never `isPlatformBrowser` in templates; browser-only work in render callbacks; platform-specific services (Breakpoint server value) via `app.config.server.ts` providers (`ssr.md` Providing platform-specific implementations).
- Restore any global the directive touched (hash, `history` state, `body` classes, `inert` on content) in `DestroyRef.onDestroy`.

### 1.10 Accessibility baseline

Shared by every spec (`R:apg` Cross-cutting practices; map, Standing preferences):

- The APG pattern named in Part 2 is the contract; "a role is a promise": no role without its full keyboard table. Site navigation uses the disclosure navigation pattern, never `menu`/`menubar`/`tree` (ADR 0004).
- Native elements first: triggers are `<button type="button">`, dialogs are `<dialog>`, sliders are `<input type="range">`, links stay `<a href>`. Foundation's `<a href="#">` accordion and menu triggers become buttons in the spec markup; the hybrid disclosure form (link plus toggle button) covers menu parents that also navigate.
- Hidden content that stays in the DOM gets `inert` (Aria's choice) and Foundation's display rules; content that is truly gone uses `hidden` or `@if`; `aria-hidden` is not used for hiding. Exception: `<dialog>` and top-layer elements manage their own inertness.
- Names: `region`, `dialog`, `tabpanel`, `tablist`, `slider`, carousel `group` are named through `aria-labelledby` inputs pointing at visible text, `aria-label` as the fallback input; the spec's rendered HTML shows both. `aria-label` is never added to elements named from content (Foundation Nest's copied `aria-label` is dropped).
- Focus: one tab stop per composite (roving `tabindex`), focus persistence when content closes or re-renders (ResponsiveAccordionTabs, ResponsiveMenu mode swaps refocus the equivalent control), focus moves into dialogs and off-canvas panels and returns to the invoker on close, never focus the dialog element itself.
- Disabled: `aria-disabled` and still focusable by default (Aria `softDisabled: true`); native `disabled` on opt-in.
- Escape closes overlays and returns focus; moving focus out of an overlay closes it (WCAG 1.4.13 for hover and focus content).
- Reduced motion honoured (1.6); auto-rotating content (Orbit) stops on focus and hover and has a visible stop control before the rotating content.
- Gate: every story runs axe through `@storybook/addon-a11y` with `parameters.a11y.test = 'error'` and `runOnly` widened to WCAG 2.2 AA; a story may opt out only to demonstrate a documented anti-pattern (`R:tooling` Accessibility checks in CI).

### 1.11 Rendering modes (ADR 0008)

User rule (map, Standing preferences): every directive and component supports `@defer` including hydrate triggers, server-side rendering, prerendering, full and incremental hydration, and event replay. Facts come from `research/angular-rendering-modes.md` (cited `R:rendering` below); its eleven library rules (section 7) are adopted as written and are not repeated here, only the decisions they force.

Facts that shape the design (`R:rendering` 0, 2, 4):

- For SSR consumers a plain `provideClientHydration()` turns on incremental hydration and therefore event replay; the library must assume both are on. `RenderMode.Client` routes skip hydration, so one app exercises CSR, SSR plus hydration, and prerender plus hydration.
- Hydration matches nodes by type and tag name only. A class or ARIA value that differs between server and client is not an error but a visible flash until the first client pass; a structural difference (extra or missing node) is.
- `ngSkipHydration` is valid only on component hosts (NG0504 elsewhere), so every directive must be hydration-clean by construction; the library never uses it and never uses Shadow DOM encapsulation (which silently skips hydration and replay).
- Event replay covers only listeners declared in templates or `host` metadata on elements, for the listed native types (`click`, `keydown`, `focusin`, `focusout`, `pointerdown`/`up`/`move`, `mouseover`/`mouseout`, `input`, `change`, `submit`, `toggle`, and others). Not replayed: `mouseenter`, `mouseleave`, `pointerenter`, `pointerleave`, `scroll`, `resize`, `animation*`, `transition*`, custom events, outputs, listeners added in code, and `document:`/`window:`/`body:` host listeners. `preventDefault()` throws during replay and skips the rest of the handler; Aria's keyboard manager calls it after its handler.

Decisions:

1. Server output is the first paint. Every state visible at first paint is a host binding on signal state (Foundation classes, State classes, ARIA, `inert`, `hidden`, `--nfs-*` style bindings). No template branches on the platform. Examples: a closed Reveal is `<dialog class="reveal">` without `open`; a hidden pane is `.dropdown-pane` without `.is-open`; a collapsed accordion panel carries `inert` and Foundation's `display: none`.
2. Open-at-first-paint content renders on the server. Foundation has no CSS rule that shows open `.accordion-content` (its JavaScript wrote inline `display`), so `nfsAccordionContent` binds the shown state itself (documented custom CSS keyed on the item's `.is-active`), and panel content is projected, not placed in Aria's `ng-template` content directives: Aria's `DeferredContent` creates views in `afterRenderEffect`, so an open Aria panel or selected Aria tab panel is empty in server HTML. Lazy content stays available as an opt-in `ng-template` input for consumers who accept client-only panel content, and the spec says so (`R:rendering` 5).
3. Nothing before hydration outside templates: no node creation, moves, `innerHTML`, or `Renderer2` writes at construction; no `window`, `matchMedia`, `getBoundingClientRect`, `focus()`, `scrollIntoView()`, observers, `history`, or `location` outside `afterNextRender`/`afterRenderEffect`. These render callbacks are the library's only platform check; `isPlatformBrowser` and `ngServerMode` are not used. Structure Foundation injected is template-owned or consumer-written (1.1). The Tooltip tip is created on first show, which is always a client event.
4. Timers (Orbit autoplay, hover-intent delays, animation fallback timers) start only inside render callbacks or handlers, never during server render, and on the client outside the Angular zone so a zone-based consumer still reaches stability and replays queued clicks promptly (`R:rendering` 1 Stability).
5. Event replay readiness: primary activation is a `click` or `keydown` listener in `host` metadata of the element the user interacts with. State a replayed handler needs exists at construction or in the first `afterNextRender` (both run before replay). Handlers change state first and call `preventDefault()` last. Hover and focus opening (Dropdown `hover`, DropdownMenu hover, Tooltip) uses non-replayed `pointerenter`/`pointerleave`, and replayed `focusin` handlers re-check live focus before opening. Document-level handlers (Light dismiss, outside click, global Escape) do not replay, which is correct: nothing is open before hydration. Replayed swipes and `pointermove` drags are stale and ignored. How a handler recognises a replayed event without importing an internal constant is OPEN FOR HUMAN (Part 4).
6. Hydration boundaries: a composite widget's container and items, and a Trigger and its Openable, belong inside one hydration boundary. Aria and this library register children when they are constructed, so a parent whose items sit in a dehydrated block has no items. Every spec documents that a consumer `@defer` wraps the whole widget, never part of it.
7. `@defer`: library templates contain no `@defer` (the library has no heavy dependencies to split and cannot choose hydrate triggers for consumers). Each plugin is a standalone secondary entry point so a consumer can defer per plugin. Inside a dehydrated block a directive is its server HTML: Foundation CSS and native elements must carry the closed state, and an interaction on an element with a replayable listener hydrates the block and replays the event. Inside `hydrate never` a widget works only as far as its server HTML and native elements do; each spec states that residue (Sticky, Slider, SmoothScroll, Button keep working; everything else is inert).
8. Breakpoint-gated behaviour renders `serverBreakpoint` (1.7) because CDK `MediaMatcher` answers `false` to every query on the server; the Breakpoint service defines its own server answer. A client on another breakpoint re-renders or re-classes at hydration, and the spec states which (class change for ResponsiveMenu, `@if` branch rebuild for ResponsiveAccordionTabs).
9. Deep links (Accordion, Tabs, Reveal, Magellan) apply after hydration because the server never sees the fragment, and they require consumer-supplied ids (1.5). A consumer who needs server-correct initial state binds it from route data.
10. `animate.enter` has no hydration guard in 22.2 source; whether a server-rendered element with `animate.enter` replays its enter animation at hydration is prototype P11. Until then, persistent elements (Reveal, OffCanvas, dropdown panes, Toggler targets) animate through State classes only (1.6 rule 1), which cannot replay at hydration because the State class value is the same on both platforms.
11. Prerendering is SSR at build time with `REQUEST` null; nothing in the library reads request tokens.

### 1.13 Sass and theming

In scope for every spec: the Foundation Sass mixins and partials the directive relies on (`foundation-accordion`, `foundation-reveal`, `foundation-range-input` and so on) and the library's documented custom CSS in `_nfs-<plugin>.scss` (reason per rule, AGENTS.md Styling Guidelines). Foundation Sass is a consumer-side dependency compiled from the consumer's settings; Sass boolean variables stay compile-time configuration, never inputs (foundation-api-design SKILL.md Input Names).

Out of scope for the specs: runtime theming through CSS custom properties as a public contract. A directive may write a `--nfs-*` custom property when it has to pass a measured value to CSS (drilldown wrapper height, slider fill percentage); that is an implementation channel documented in the spec, not a theming API. How the new repo packages `_nfs-*.scss` next to Foundation, and whether `foundation-sites` is a peer dependency, is a repo-setup ticket (Part 4), not a spec.

### 1.14 Spec shape

A `/to-spec` spec keeps the template's top-level sections in order: Problem Statement, Solution, User Stories, Implementation Decisions, Testing Decisions, Out of Scope, Further Notes. The foundation-api-design material goes in as subsections:

Implementation Decisions:
1. Foundation contract: features, options, events inventory (from the research file), and the dropped options list.
2. CSS class to directive mapping (one row per structural class; state classes as host bindings).
3. Hierarchy and DI shape (tokens, host directives, parent discovery, defaults token).
4. API per directive or component: inputs with Foundation defaults and deltas, models, outputs, methods, `exportAs`.
5. Implementation level and primitives, with the fallback.
6. ARIA and keyboard tables (APG pattern, roles, states, keys, focus rules).
7. Rendered HTML: consumer markup and the resulting DOM, closed and open, server and hydrated.
8. Animation: State classes, keyframes, completion, reduced motion.
9. Rendering modes: server output, pre-hydration rules, event replay readiness, behaviour inside `@defer` and hydrate blocks.
10. Design decisions table.

Testing Decisions: the four layers from 1.12 by name (story play function, browser-level test with the stack per ticket 41, node-level Vitest including the SSR smoke, Playwright e2e), each with its story ids and cases.

Further Notes: Material comparison table, usage examples, platform features to adopt when the browser target moves, and the "behaviour that only jQuery makes easy" that was dropped.

## Part 3. Shared utilities that earn their own spec

Four, each a directive or service spec written with the same shape as a plugin spec and consumed by the plugin specs listed:

1. **Breakpoint service** (`NfsMediaQuery`, `nfsBreakpointsToken`, the rule-string parser). Consumers: ResponsiveMenu, ResponsiveToggle, ResponsiveAccordionTabs, Interchange, Equalizer, Sticky, OffCanvas, Tooltip, Orbit (reduced motion), Reveal (none), plus `reducedMotion()` for every animated spec. Decided in 1.7 and ADR 0005.
2. **Triggers** (`nfsOpen`, `nfsClose`, `nfsToggle`, `nfsOpenableToken`). Consumers: Reveal, OffCanvas, DropdownPane, Toggler, ResponsiveToggle, Tooltip (programmatic). Decided in 1.8.
3. **Anchored pane** (positioner service porting Foundation's Positionable and Box formulas onto `getBoundingClientRect` in `afterRenderEffect`, with the `position`/`alignment`/`vOffset`/`hOffset`/`allowOverlap`/`allowBottomOverlap` option set and the 12-candidate search, plus the Light dismiss registry that closes siblings of the same kind and handles click-outside and Escape). Consumers: DropdownPane, Tooltip; DropdownMenu uses only the collision check. Decided in ADR 0002; prototype P3.
4. **Nested menu** (`nfsMenuItem`, `nfsSubmenu`, `nfsSubmenuToggle`, `nfsMenuModeToken`, the `is-<mode>-submenu*` and `submenu`/`is-submenu-item` class emission that replaces Nest's runtime Feather, and the disclosure keyboard table). Consumers: AccordionMenu, Drilldown, DropdownMenu, ResponsiveMenu. Decided in ADR 0004; prototype P9.

Explicitly no spec of their own:

- Motion: the mechanics live in 1.6 and each spec names its classes; `_nfs-motion.scss` is a stylesheet, listed in the repo-setup ticket.
- Keyboard: Aria where hosted, `event.key` elsewhere; `findFocusable`/`trapFocus` are `InteractivityChecker`/`FocusTrap` or native `<dialog>`.
- Box: folded into Anchored pane.
- Touch: Pointer Events and scroll snap; no `tap`/`swipe` synthesis.
- Timer: Orbit-local `setTimeout` bookkeeping.
- ImageLoader: `ResizeObserver` fires again when images load.
- Plugin lifecycle, `reflow`, `reInit`, `data-options`: Angular lifecycle; nothing to port.
- Id generation: CDK `_IdGenerator` (1.5).
