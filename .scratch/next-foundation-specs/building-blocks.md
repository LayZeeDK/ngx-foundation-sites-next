## Part 1. Cross-cutting decisions

### 1.1 Directive or component

Rule (ADR 0001, [ADR 0039](adr/0039-directives-manage-every-foundation-class.md)): a plugin, a CSS-only component, a layout system, or a utility family becomes attribute directives on the elements the consumer writes, and those directives set every Foundation class: one directive per Structural class, which binds it even when that is all the directive does, a typed input for every Variant class, and a host binding for every State class (a State class on an element that carries no library directive, such as `html` (the Reveal's Scroll lock), `body`, or the links and list items of a Magellan navigation, is written by the directive that owns the state with `Renderer2` from a render callback, only for state with no first-paint value, [ADR 0039](adr/0039-directives-manage-every-foundation-class.md), dated note); the directives of a layout system or utility family set its Utility classes. The consumer writes no Foundation or library class, and an element Foundation styles only by tag gets no directive. A component is allowed only where Foundation's JavaScript builds structure the consumer never writes and that structure cannot be expressed as a single consumer-written element. Three cases qualify:

1. `ResponsiveAccordionTabs` renders one of two markup trees from the same content and must swap heading-plus-button semantics for tab semantics (`R:apg` ResponsiveAccordionTabs; `R:disclosure` ResponsiveAccordionTabs "Behaviour that only jQuery makes easy"). It is the one element-selector component: `nfs-responsive-accordion-tabs`.
2. Content wrappers: `.accordion-content` becomes an attribute-selector component (`[nfsAccordionContent]`) whose template is a single wrapper around `<ng-content>`, because the grid-row height animation (1.6 rule 3) needs that wrapper (Material does the same, `R:material` 1 Animation). `.tabs-panel` gets `[nfsTabsPanel]`, a directive: resolved by the [Prototype: `@angular/aria` Accordion and Tabs under Foundation markup](issues/43-prototype-aria-accordion-tabs.md), Aria's tab panel works without a template child, and Tabs has no height animation, Table B Tabs, and panel content is projected, 1.11 decision 2. Each binds its Foundation class on the host element the consumer wrote (ADR 0039).
3. Elements Foundation generates that the consumer should not author: the Tooltip tip (`.tooltip`, created by the plugin and never written by hand, `R:positioned` Tooltip 2). The Tooltip *directive* sits on the trigger and creates an internal `NfsTooltipTip` component on first show, then keeps it; in its first client render callback it also creates a hidden internal `NfsTooltipDescription` beside the host ([Resolve the assistive-technology checks](issues/77-evidence-assistive-technology-checks.md)). The Tooltip exception in ADR 0001 covers both: created by the plugin, never authored by the consumer; the description element is a single plain element, kept a component because a consumer-written one would repeat the tooltip text beside every trigger and no platform feature replaces it (ADR 0001's dated bullet; [Spec: Tooltip](issues/27-spec-tooltip.md), D1). Everything else Foundation generates (Reveal overlay, off-canvas overlay, drilldown wrapper and back buttons, sticky container, accordion-menu toggle button, parent-link clones) is either replaced by a platform feature (`::backdrop` for the Reveal overlay), authored by the consumer as one plain element with a directive on it (off-canvas overlay, drilldown back button, sticky container, submenu toggle), or dropped (parent-link clones, `wrapper`/`backButton`/`container`/`template` HTML-string options).

Why this and not the "container = component" table of this repository's early API-design sketch (from its Spec Kit attempt): that table predates the user's directive-over-component preference and Aria's all-directive shape (`R:aria` 1.4, `R:material` 1 "Directive or component"). Part 2 applies one directive or component per Structural class, which binds that class ([ADR 0039](adr/0039-directives-manage-every-foundation-class.md)), row by row; Variant classes are typed inputs, and State classes (`.is-active`, `.is-open`, `.is-stuck`) are host class bindings, never directives.

Consequence: every directive works on server-rendered markup with no DOM creation before hydration (1.11), and because host bindings render on the server, the server HTML carries every Foundation class. The consumer keeps the element structure of Foundation's docs markup and writes directive attributes where the docs write classes (ADR 0039); the other deltas (`<a href="#">` becomes `<button>`, `<div class="reveal">` becomes `<dialog nfsReveal>`, `href="#id"` on a routed page under `<base href>` is built from the current path) are listed per spec. The class rule governs the consumer's templates and input values; a spec's recipe for consumer CSS (a `scroll-margin-top`, a sticky header's `scroll-padding-top`) selects elements, attributes, or the consumer's own classes, never a Foundation or library class, so every example is free of those names however the rule is read for stylesheets ([Spec: Accordion](issues/15-spec-accordion.md), D27).

### 1.2 Implementation level and the browser target

Order per plugin: native platform feature, then `@angular/aria`, then `@angular/cdk`, then custom Angular. A spec stops at the first level that covers the behaviour with the browser target applied, and states the fallback if a prototype fails that level.

Browser target (user decision): Baseline widely available on 2026-05-07, Chrome/Edge/Firefox 119 and Safari 17 (map, Notes). Applied from `R:platform` Feature summary:

| Usable without fallback | Not usable (needs fallback or is out) |
| --- | --- |
| `<dialog>`, `showModal()`, top layer, `::backdrop`, `:modal`; `<details>`/`<summary>` and `toggle`; `position: sticky`; scroll snap, `scrollIntoView()` with options, `scroll-behavior`, `scroll-margin`/`scroll-padding`; IntersectionObserver, ResizeObserver, MutationObserver; container size queries and `cq*` units; `<picture>`, `srcset`, `sizes`, `<img loading="lazy">`; Constraint Validation API, `:user-invalid`; `<input type="range">`, `appearance: none`; `inert`; `prefers-reduced-motion`; `inputmode`; CSS grid `fr` interpolation; `matchMedia` and `MediaQueryList.change`; Pointer Events; `transitionend`/`animationend` | `popover` (all states), `popovertarget`; CSS anchor positioning; `<details name>`; `::details-content`; `interpolate-size`/`calc-size()`; `@starting-style`; `transition-behavior: allow-discrete`; `overlay`; scroll-driven animations; `scrollend`; container style and scroll-state queries; `sizes="auto"`; `<iframe loading="lazy">`; vertical form controls via `writing-mode`; `::slider-*`; `:has()`; View Transitions; Invoker Commands; `CloseWatcher`; `dialog.closedby`, `dialog.requestClose()` |

Rules that follow:

- No progressive enhancement onto a not-usable feature in the first specs: one code path per behaviour, because two paths double the test matrix and the not-usable features become usable only when the target moves with Angular. Each spec names the feature it would adopt then (for example anchor positioning for Dropdown) under Further Notes. The rule holds where the fallback would be the in-target technique and only newer browsers would gain: [Decide: Slider vertical orientation](issues/73-decide-slider-vertical-orientation.md) applied it to vertical range inputs laid out with `writing-mode` behind a feature query, as ADR 0002 applied it to `popover` and anchor positioning and the Accordion spec to CSS alternative text.
- `:has()` is not used in library CSS; parent state classes are bound by the directives instead (`R:platform` 16).
- CDK is used where it is the smallest correct piece, not as a framework: `MediaMatcher` (1.7), `_IdGenerator` (1.9), `Directionality` (RTL), `InteractivityChecker` (initial focus targets), `FocusTrap` only where native focus containment is unavailable (OffCanvas `trapFocus`, modal or not; Dropdown `trapFocus` with `role="dialog"`). CDK Overlay, Dialog, Menu, Accordion and Listbox are not used (ADR 0002, ADR 0007, 1.9); every named fallback was retired once its prototype resolved the risk the map flagged: the [Spec: Accordion](issues/15-spec-accordion.md) retired the CDK accordion state fallback in Table B Accordion, the anchored pane prototype retired ADR 0002's CDK Overlay fallback, and the Reveal dialog prototype retired ADR 0007's CDK Dialog fallback; nothing in CDK is deprecated in favour of Aria, but the higher levels cover those cases (`R:cdk` Cross-cutting notes).
- Aria is used for Accordion, Tabs, and Orbit's bullet tablist and slides. It is not used for the menus (ADR 0004), Dropdown, Reveal, OffCanvas, Tooltip, Slider (no Aria pattern exists, `R:aria` 10).
- Images in specs (the repository's AGENTS.md rule): every static `<img>` in a spec's examples, stories, and fixtures uses Angular's `NgOptimizedImage` (`ngSrc` with `width` and `height`, and a configured image loader wherever it should generate `srcset`), beside any library directive on the same `<img>`. A plain `<img>` remains only where `NgOptimizedImage` cannot be used: the `<img>` of an art-directed `<picture>`, which Angular 22.2 does not support and whose aspect-ratio check and `priority` preload would misread, and a `data:` or `blob:` URL, which it rejects ([Spec: Interchange](issues/35-spec-interchange.md), design decision 18).

### 1.3 Naming

- Selector prefix: `nfs` for directives (`[nfsAccordion]`), `nfs-` for components (`nfs-responsive-accordion-tabs`), per AGENTS.md Workspace. Attribute-selector components keep the directive form (`[nfsAccordionContent]`).
- Class names: `Nfs` plus PascalCase of the Foundation Structural class the directive binds (`.accordion-title` -> `NfsAccordionTitle`, `.dropdown-pane` -> `NfsDropdownPane`, `.off-canvas-content` -> `NfsOffCanvasContent`). When a plugin has no structural class of its own (Interchange, Magellan, SmoothScroll, Toggler, Equalizer, ResponsiveToggle, ResponsiveMenu), the plugin name is used. The `Nfs` prefix is kept, against the v20 style guide's suffix-less bare names, because the library imports Aria's bare `Tabs`, `Menu`, `Tab`, `Option` classes and Material-style names would collide (`R:di` 8 Selector conventions; naming-conventions.md "Avoid Namespace Collisions"; ADR 0009). A CSS-only component's directives follow the same rule (`.button-group` -> `NfsButtonGroup`); the specs of the layout systems and utility families name theirs ([ADR 0039](adr/0039-directives-manage-every-foundation-class.md)); a layout system's directives are named after the classes that name elements of its layout (`.grid-x` -> `NfsGridX`, `.cell` -> `NfsCell`, [Spec: XY Grid](issues/99-spec-xy-grid.md)); the two legacy grids bind the same classes on the same markup, so the Float Grid's and the Flex Grid's directives share the names `NfsRow` (`[nfsRow]`) and `NfsColumn` (`[nfsColumn]`), each in its grid's entry point, while their type aliases carry the grid's name (`NfsFloatGridColumnSize`, `NfsFlexGridColumnSize`), because their families differ ([Spec: Float Grid](issues/100-spec-float-grid.md), D1; [Spec: Flex Grid](issues/101-spec-flex-grid.md), D1, D7). An element Foundation styles by tag that gets a directive only for its Variant classes is named after Foundation's mixin or docs term for it: the form `label` is `NfsFormLabel` (`label[nfsFormLabel]`, from `form-label`), because `NfsLabel` is the Label component's ([Spec: Forms](issues/98-spec-forms.md)). A Structural class that Foundation writes without its component's prefix but styles only under the component's root class takes the component's name: `.pagination .ellipsis` is `NfsPaginationEllipsis` (`li[nfsPaginationEllipsis]`), because a bare `NfsEllipsis` would read as a text-truncation utility ([Spec: Pagination](issues/87-spec-pagination.md)).
- Utility families (2026-09-28, [Spec: Prototyping Utilities](issues/102-spec-prototyping-utilities.md)): a family of Utility classes that stand alone gets one directive class per Foundation export mixin, `Nfs` + the PascalCase of the mixin without `foundation-` (`NfsPrototypeSpacing`, `NfsFloatClasses`, `NfsTextAlignment`), or, where the mixin qualifies a class by element, a directive whose selector names those elements: one per element where the qualified classes differ (`ul[nfsListStyleType]`, `ol[nfsListStyleType]`), one for both where one rule qualifies both (`NfsNoBullet`, `ul[nfsNoBullet], ol[nfsNoBullet]`, [Spec: Typography Helpers](issues/106-spec-typography-helpers.md), D3). Its inputs are Utility attributes (1.4) named `nfs` + the class template's stem (`nfsDisplay`, `nfsMarginTop`, `nfsOverflowX`), the CSS property where templates share or shorten a stem (`nfsTextTransform`, `nfsTextAlign`, `nfsListStyleType`), or, for a class without a value, the camelCase of the class (`nfsBordered`, `nfsClearfix`). Value aliases end in `Name`, `Count`, or the dimension (`NfsPrototypeDisplayName`, `NfsPrototypeSpacerCount`, `NfsPrototypeSeparatorAlign`) and attribute aliases in `Input`, or `Value` for a transformed read type, so no alias collides with a directive class. A family with roles (the Flexbox Utilities' flex parent and flex child) names each role's directive after its class, as above, and a family whose templates express one effect under `<words>-for-<bp>` names (the Visibility Classes) names its directive after the docs page and its inputs with Foundation's words (1.4), and binds each class of the family that has another contract through a directive named after that class (`NfsShowForSr` for `.show-for-sr`, `NfsShowOnFocus` for `.show-on-focus`, [Spec: Visibility Classes](issues/104-spec-visibility-classes.md), D1); in every shape an un-prefixed input shares no name with another directive's input on the same element, or the spec reports the case.
- Variant types ([ADR 0040](adr/0040-variant-input-types.md)):
  - A Variant registry is `Nfs` + the PascalCase of its Sass setting + `Overrides` (`NfsButtonPaletteOverrides` for `$button-palette`, `NfsFoundationPaletteOverrides`, `NfsButtonSizesOverrides`, `NfsBreakpointClassesOverrides`, `NfsGridColumnsOverrides`). There is one per setting, and all are declared in the primary entry point `ngx-foundation-sites`.
  - A directive family's alias is `Nfs` + component + dimension (`NfsButtonColor`, `NfsCalloutSize`, `NfsResponsiveEmbedRatio`, `NfsCellSize`), built with `NfsOverridableStringUnion<defaults, registry>`, or `NfsOverridableCount<default, registry>` for a count.
  - `NfsClassBreakpoint`, `NfsClassBreakpointQuery<M>`, and `NfsClassBreakpointRules<V>` mirror `$breakpoint-classes`. `NfsBreakpointName` stays the type of behaviour Options (Tooltip `showOn`, Sticky `stickyOn`).
- Plugin name mapping: Reveal stays `NfsReveal`; Drilldown is `NfsDrilldown` (Foundation class `Drilldown`, CSS `.drilldown`; the docs page title "Drilldown Menu" is not used for the class; its entry point and Story ids use `drilldown-menu`, the Drilldown Menu spec's D2); OffCanvas is `NfsOffCanvas` with the selectors `nfsOffCanvas` (binding `.off-canvas`) and `nfsOffCanvasAbsolute` (binding Foundation's alternative class `.off-canvas-absolute`), one directive class for Foundation's two Structural classes of the panel ([Spec: Off-canvas](issues/25-spec-off-canvas.md), D25) and files `off-canvas/off-canvas.ts` (Foundation's own hyphenation `off-canvas`, `R:utilities` 1.1); DropdownMenu is `NfsDropdownMenu` on `ul.dropdown.menu`; Dropdown (the pane plugin) is `NfsDropdownPane` because `.dropdown` alone is Button's arrow class and `.dropdown.menu` is DropdownMenu.
- Files: v20 suffix-less kebab-case, one folder per plugin as a secondary entry point (`accordion/accordion.ts`, `accordion/accordion-title.ts`, `accordion/accordion-tokens.ts`, `accordion/accordion.spec.ts`, `accordion/accordion.stories.ts`, `accordion/_accordion.scss` for documented custom CSS). Entry point `ngx-foundation-sites/<plugin>` so a consumer's `@defer` block can split per plugin (1.11).
- Tokens: camelCase with the `Token` suffix, `nfsAccordionToken`, `nfsTooltipDefaultsToken` (AGENTS.md Design Philosophy 6; the guide's `LibHeaderToken` naming, `R:di` 1). This departs from CDK/Material `MAT_` and Aria bare `SCREAMING_SNAKE`; ADR 0009 records the prefix and the token naming so nobody "fixes" them.
- Outputs and methods: Material vocabulary (`R:di` 8; `R:material` 0.1): `open()`, `close()`, `toggle()` for every Openable (not `show()`/`hide()`); containers use one pair, `expandAll()`/`collapseAll()`, the names of the Aria `AccordionGroup` the Accordion hosts (`src/aria/accordion/accordion-group.ts:133, 138`), not CDK and Material's `openAll()`/`closeAll()` (`src/cdk/accordion/accordion.ts:51, 58`), which is the alternative not taken. A boolean state signal whose verb would collide with a method or an output is named `isX`: every Openable's state is the `isOpen` model (change output `isOpenChange`) beside the `open()`/`close()`/`toggle()` methods and the `opened`/`closed` outputs, as Sticky's `isStuck` sits beside its `stuck` output (`show()`/`hide()` as the Openable verbs would collide with `HTMLDialogElement.show()` on Reveal, and Material's `opened` state name is taken here by the completion output); `expanded` and `active` do not collide and keep their names. Outputs `opened`, `closed`, `selectedChange`-style `xChange` companions from `model()`, never an `on` prefix.
- Story ids: `<plugin>--<story>` in kebab case, named in each spec's Testing Decisions so play functions and Playwright open the same artifact (`R:tooling` Recommended test pyramid). `<plugin>` is the entry point folder name, pinned by `meta.id`; conventions in [storybook-conventions.md](storybook-conventions.md).
- `exportAs` (2026-09-28, [Decide: the directive and component architecture guide](issues/141-decide-directive-component-architecture-guide.md)): where a template needs the instance (state, methods, a Trigger target), it is the directive's camelCase name (`nfsReveal`, `nfsAccordionContent`), or its family's where two classes share one attribute (both Toggler classes export `nfsToggler`, ADR 0016), as Aria names its own (`exportAs: 'ngAccordionGroup'`); a directive with no state or method to read has none. The consumer's own inputs are not state to read, so a directive whose public members are only inputs and outputs has no `exportAs` (2026-09-29, [Consistency review: the class-rule wave](issues/133-consistency-review-class-rule-wave.md)).

### 1.4 Inputs and outputs

- Every Foundation `data-*` option becomes `input()` under its camelCase name with `booleanAttribute` or `numberAttribute` transforms so attribute strings coerce (`R:angular` input/model/output; `R:cdk` coercion). Defaults are Foundation's unless the APG or Aria forces a change, and the spec lists each such delta (example: Accordion keeps `multiExpand=false`; Orbit gains a required rotation control).
- Variant inputs ([ADR 0040](adr/0040-variant-input-types.md)): every Variant class family is one input of the directive that binds its Structural class, and its type is closed. Unlike Options, a Variant input never uses `booleanAttribute` or `numberAttribute`, whose `unknown` parameter accepts any template value.
  - Names, in this order:
    1. A Foundation `data-*` Option that already names the family keeps its name (Off-canvas `revealOn` and `inCanvasOn`, Slider `vertical`; Responsive Toggle `hideFor` takes its name the same way but stays an Option with a Defaults token slot, because it also selects the Breakpoint service query and its Foundation default `medium` sets a class, 1.7).
    2. Otherwise, the input name of the hosted `@angular/aria` directive for the same concept (`orientation`, as Tabs has it, for `.horizontal`, `.vertical`, and their responsive forms).
    3. Otherwise, mutually exclusive names from one Sass setting or loop form one enum input named for the dimension Foundation's docs and Sass use: `color` for a palette; `size` for a size map and for Reveal, Switch, and grid cell sizes; `fill` for `solid`, `hollow`, and `clear`; `ratio` for `$responsive-embed-ratios`; `offset`, `up`, and `order` for the grid and flex families.
    4. Otherwise, a single on or off class is a boolean named with the camelCase of its class (`expanded`, `dropdown`, `arrowOnly`, `noGaps`).

    A responsive form is never its own input: remove the breakpoint and any `only` or `down` from Foundation's class template, and what remains names the input (`.medium-only-expanded` is `expanded="medium only"`, `.medium-6` is `[size]="{medium: 6}"`, `.medium-horizontal` is `[orientation]="{medium: 'horizontal'}"`). A `<words>-for-<bp>` class keeps Foundation's words (`stackedFor="medium"`, `showFor="large only"`). The input's JSDoc names the Foundation class template and the Sass setting (AGENTS.md Design Philosophy 5).
  - Types:
    - A Closed Variant family is a literal union, or a boolean through `nfsVariantBoolean`, whose parameter is `NfsVariantBoolean`: `boolean | '' | 'true' | 'false' | null | undefined`.
    - An Open Variant family is its alias over the setting's Variant registry (1.3), with no `(string & {})` member.
    - A count is `NfsOverridableCount`, through a transform whose parameter adds the static-attribute strings and the family's keywords.
    - An on or off responsive family takes `true` or an `NfsClassBreakpointQuery<M>` whose `M` lists only the modifiers whose classes Foundation generates for it.
    - A valued responsive family takes a bare value, which means the Zero breakpoint, or `NfsClassBreakpointRules<V>`.
    - A class-name string is never a value (ADR 0039).
  - Authoring: every Variant input declares explicit type arguments that name exported aliases, and the library's build asserts that each emitted write type in the typings names its alias. Declaration emit can print an inferred or conditional type resolved, which would freeze Foundation's defaults where no consumer declaration reaches them. An `@angular/aria` input that a wrapper exposes through `hostDirectives` as a Variant input (Tabs `orientation`) keeps Aria's declared type: the library does not declare it, so the alias rule and the typings assertion apply only to the inputs the library declares ([Spec: Tabs](issues/16-spec-tabs.md)). The assertion is the Variant typings check of the [Spec: Variant declaration tooling](issues/136-spec-variant-declaration-tooling.md), which also compiles probe programs generated from the Variant manifest, in which a declared name must reach every listed input and misspelt, removed, and out-of-range values must fail. Each Open Variant family row of a spec's class mapping (1.14 item 2) names a registry of that spec's settings table and becomes one `uses` entry of the manifest.
  - Defaults and binding: every Variant input defaults to `undefined` (`false` for a boolean), which sets no class, so the consumer's Sass default is the look; A Variant family without which Foundation's CSS gives the element no look, because Foundation's docs require one of its classes and no Sass setting names a default, is a required input instead, so the no-class state cannot arise: the Off-canvas `position` ([Spec: Off-canvas](issues/25-spec-off-canvas.md), D6). `'default'`, where Foundation's map has that key, also sets none. An explicit value always sets its class. The directive maps each value to the one class with its meaning, including Foundation's Zero-breakpoint gaps (`expanded="small down"` sets `.small-only-expanded`; a Menu rule for the Zero breakpoint sets `.vertical`), and binds nothing for a value that is not one class token. A directive that fills a Zero-breakpoint gap reads the Zero breakpoint as `nfsBreakpointForWidth(inject(nfsBreakpointsToken).map, 0)`, the same on server and client, without injecting `NfsMediaQuery`. A directive whose Variant inputs read a Variant property reports them through `nfsVariantCheck(directive)` of `ngx-foundation-sites/media-query`: in its own render callback, created only when the handle is not `null`, it calls `include(mixin, settings)` on every run, bound value or not (or, where the property is read only for a value that may stay unbound and its own mixin holds nothing it needs, only while such a value is bound: the Off-canvas `revealOn`, the Top Bar `stackedFor`, the grids' counts), naming only properties its mixin never leaves empty on Foundation's defaults and never a flag-gated one, then `value(input, value, needs)` for each rendered value, with `needs` from the same mapping that sets its classes; the spec names the call as `nfsVariantCheck('<directive>')`, and its missing-property browser-level case sits in a test file of its own, because reads and reports are once per realm ([Spec: Breakpoint service (shared utility)](issues/53-spec-breakpoint-service.md), Runtime checks).
  - The consumer's names reach these types only through its Variant declaration file (1.13), never through a provider, a subclass, or a consumer directive.
- Utility attributes (2026-09-28, [Spec: Prototyping Utilities](issues/102-spec-prototyping-utilities.md)): the inputs of a utility family's directive are named after their own attribute selectors, `nfs`-prefixed, so any of them creates the directive, an element gets one instance per family, and no utility captures another directive's input or a native attribute (`position`, `size`, `color`, `width`, `height`). They are typed and default as Variant inputs are; the responsive form is the same attribute: a bare value from the Zero breakpoint or a Breakpoint rules object for a valued attribute, `true` or a Breakpoint query with only the modifiers Foundation generates for a boolean. Where two templates of one family set the same property on one side (`.margin-2` and `.margin-top-1`; `.overflow-scroll` and `.overflow-x-hidden`), the directive resolves them: at each Class breakpoint the most specific attribute wins for each side, and no two bound classes set one side, because Foundation resolves them by source order (measured in three engines). Across families Foundation's cascade decides, and each spec names the pairs.
- Inputs named like HTML attributes (2026-09-28, [Decide: inputs named like HTML presentational attributes](issues/139-decide-inputs-named-like-presentational-attributes.md)): a static input attribute stays on the element (Angular sets the input and renders the attribute, which HTML lowercases), so an input whose lowercased name is an HTML attribute (in the WHATWG index or its obsolete features, `role`, or `aria-*`) also renders that attribute. The naming order above still picks the name. The directive that declares the input owns what the static attribute renders, so a static attribute and a binding of the same value give the same page, and the spec's input table states one kind for each such input, from what the attribute does on each host the spec allows, in Chromium, Firefox, and WebKit with Foundation's CSS:
  1. `output`: the attribute is what the input means there, a native or ARIA attribute or the Foundation attribute selector of the intended look. It is bound from the input, `null` when off, which also replaces a static value (`type` and `disabled` on the Button's `button`, `disabled` on the Accordion's `ul`).
  2. `removed`: the browser reads it from the element's current attributes, as a presentational hint or through a Foundation attribute selector. The declaring directive binds `'[attr.<name>]': 'null'`, as Angular Material's `MatHint` does for its `align` (the Menu's `align`, the Slider container's `disabled`, the Slider Handle's `readonly`). The binding keeps the attribute out of the server HTML and the first paint; hydration and client rendering carry it only until the first update pass, which also restores the bound classes, and no rendering update drew it (1.11).
  3. `insertion`: the browser acts on it when the element is parsed or inserted (`autofocus`). Every such input binds `'[attr.autofocus]': 'null'`, which keeps it out of the server HTML, and hydration's rewrite onto a node already in the document does nothing. In client rendering Angular sets static attributes before it inserts the element, and the browser takes the element as an autofocus candidate however soon the binding removes the attribute (measured in three engines). So where the host can take focus when it is inserted (the Tabs strip, which Aria's roving focus gives `tabindex="-1"`; a Reveal's `dialog` open at its first render), the spec documents the bound form and the Defaults token, and the directive reports a static attribute in development through `HostAttributeToken`, as the Dropdown pane's check 6 does.
  4. `inert`: the attribute does nothing on those hosts (`size`, `color`, `value`, or `selected` on a `div`): no binding.

  A `removed` or `insertion` binding carries a source comment naming the effect it prevents, and the spec's SSR smoke writes the static form and asserts that the attribute is absent. The directive owns the attribute, so a consumer's own `[attr.<name>]` on the host is not supported (the host binding wins the first pass, and a later change of the consumer's value is written; measured). `research/presentational-attribute-inputs.md` classes the inputs of the specs published by 2026-09-28 (72 inputs, row 64 as corrected there); a later spec states the kind in its input table. Utility attributes keep the `nfs` prefix (the bullet above), so none of them raises the question.
- `model()` for the state Foundation exposes as both a method and an event: `expanded` (accordion item, accordion-menu and drilldown and dropdown-menu items), `isOpen` (Reveal, Dropdown pane, OffCanvas, Tooltip, ResponsiveToggle, Toggler in visibility mode, matching the Openable contract of 1.8; named per the `isX` rule in 1.3), `selected` (tab list value, Orbit active slide), `value` (Slider), `active` (Magellan current target, Toggler class mode, whose `NfsClassToggler` also exposes a read-only `isOpen` mirror for the Openable contract). Sticky's `isStuck` and `edge` are read-only signals (`computed`) because the browser owns them; its outputs are `stuck`/`unstuck`.
- Initial state is bound, never read from a class ([ADR 0039](adr/0039-directives-manage-every-foundation-class.md)): an item, panel, or pane that is open, active, or in a variant at first paint is written with the input or model that owns it (`[expanded]="true"` on an accordion title), not with a Foundation class in the markup, and no directive reads a static Foundation class to seed state or a Variant. A Foundation class copied from Foundation's markup that a directive binds dynamically is stripped on server and client, because Angular's styling resolution consults static classes only when every binding for the class is `undefined`; each such directive reads its host's static `class` through `HostAttributeToken` in development builds only and warns once, naming the input to bind ([Spec: Accordion](issues/15-spec-accordion.md), dev check 7). A State class written with `Renderer2` on elements no library directive hosts (1.1) follows the same rule by its own means: Magellan's marker write removes a copied `is-active` from every tracked link and list item outside the Current section, and its development check reads the class before that write ([Spec: Magellan](issues/30-spec-magellan.md), D18). Structural classes written redundantly merge with the directive's static `host` class and are not reported. So does a plugin root's class that its directive binds `true` whenever the root stands alone and that a Responsive Menu binds per Menu mode (`accordion-menu`, `drilldown`, `dropdown`): a copy is stripped only in the modes that are not live and is not reported ([Spec: Responsive Menu](issues/23-spec-responsive-menu.md), D22). A Foundation class that no directive binds but that Foundation's CSS or JavaScript reads on that element is reported the same way, naming what replaces it (the Tooltip's legacy position classes; the Slider Handle's `slider-handle`, whose Foundation rules still reach the input, [Spec: Slider](issues/32-spec-slider.md), development check 5). A directive whose State classes come only from a measurement, with no input or model that could set them (Sticky), strips a copied State class the same way and does not report it, because the copy expresses no state the consumer could have bound ([Spec: Sticky](issues/28-spec-sticky.md), D16). A component whose host binds no class reads the host's static `class` the same way and reports the Foundation classes Foundation's markup put on the plugin's element, because there they are not stripped but style the host itself ([Spec: Responsive Accordion Tabs](issues/19-spec-responsive-accordion-tabs.md), dev check 7: a copied `tabs` draws a border around the whole widget). A directive may still read the consumer's own classes (the Toggler's Class mode). The specs that read a static Foundation class today apply this in their re-runs: the Nested menu's `is-active` seed (removed by the [Re-run: Nested menu (shared utility) spec under the class rule](issues/132-rerun-nested-menu-class-rule.md), which binds the item's `[expanded]` and reports a copied `is-active`; the menus built on it follow), the Toggler's `is-hidden` (dropped by the [Re-run: Toggler spec under the class rule](issues/109-rerun-toggler-class-rule.md), which reports a copied one instead of reading it; its `hidden` attribute seed stays, because `hidden` is not a class), the Slider's `vertical` and `disabled` (removed by the [Re-run: Slider spec under the class rule](issues/124-rerun-slider-class-rule.md), which binds both from their inputs and reports a copied one), the Tooltip's legacy position classes (dropped by the [Re-run: Tooltip spec under the class rule](issues/119-rerun-tooltip-class-rule.md), which resolves `position: 'auto'` to `top` and reports a copied one instead of reading it), the Off-canvas position classes (stripped by the panel's class record and reported by development check 1 of the [Re-run: Off-canvas spec under the class rule](issues/117-rerun-off-canvas-class-rule.md)), and the Button's `.submit` marker (dropped by the [Re-run: Button spec under the class rule](issues/128-rerun-button-class-rule.md), which reports a copied one instead of reading it).
- `linkedSignal` for derived-but-writable state (the private `_selectedTabPattern` behind Aria `TabList`'s `selectedTab` model, `src/aria/tabs/tab-list.ts:109, 112`; `R:di` 8), including the `set` write-back form when a child writes into a parent model (`R:angular` linkedSignal).
- Output naming rule: state changes are the `xChange` output the model generates; completion events are past-tense verbs emitted when the state change is committed and its enter or leave animation has finished (`opened`, `closed`, `expanded` is not reused as an event: accordion items emit `opened`/`closed` like `CdkAccordionItem`, `R:di` 8). No "start" events: Foundation's mixed timing (`open.zf.reveal` synchronous, `closed.zf.reveal` after animation, `opened.zf.offCanvas` at transition start despite its name, `R:disclosure` Events, `R:menus` 6.4) is not copied. Where a consumer must veto a close, the spec adds a predicate input (Material `closePredicate`, `R:material` 3), not a cancelable event.
- Container-level aggregate outputs carry the item instance (`{item, value}` shape from Material `MatTabChangeEvent`, `R:material` 2); item-level outputs are `void`.
- Foundation event to output mapping, applied per spec: `down/up.zf.accordion` -> item `opened`/`closed` plus container `opened`/`closed` with item payload; `change.zf.tabs` -> `selectedChange` (value) plus `selectionChange` (`{value, tab}`); `collapse.zf.tabs` -> `closed`; `deeplink.zf.*` -> `deepLinked` (Tabs: `{value, tab}` payload); `on/off.zf.toggler` -> `activeChange` (class mode) or `opened`/`closed` (visibility mode); `open/closed.zf.reveal`, `openedEnd/closed.zf.offCanvas`, `show/hide.zf.dropdown`, `show/hide.zf.tooltip`, `show/hide.zf.dropdownMenu`, `open/hide/close/closed.zf.drilldown`, `down/up.zf.accordionMenu` -> `opened`/`closed` (OffCanvas: `opened`/`close.zf.offCanvas` become `isOpenChange`; Drilldown: aggregate outputs with the `NfsMenuItem`, one `closed` per level; `scrollme.zf.drilldown` dropped); `sticky.zf.stuckto/unstuckfrom` -> `stuck`/`unstuck` with the edge as payload; `update.zf.magellan` -> `activeChange`; `slidechange.zf.orbit` -> `selectedChange`, `beforeslidechange` dropped; `moved/changed.zf.slider` -> native `input`/`change` plus `valueChange`; `valid/invalid/formvalid/forminvalid/formreset.zf.abide` -> Signal Forms field state, no outputs; `replaced.zf.interchange` -> `replaced`; `preequalized/postequalized.zf.equalizer` -> `equalized`; `toggled.zf.responsiveToggle` -> `opened`/`closed` (Foundation fires it after the animation), plus `isOpenChange` from the model; `init.zf.*` and `destroyed.zf.*` have no counterpart (Angular lifecycle).
- Options that exist only because of jQuery or DOM strings are dropped and listed per spec under "Dropped options": `data-options`; HTML-string options (`backButton`, `wrapper`, `container`, `template`, `allowHtml`); class-name options (`linkClass`, `panelClass`, `linkActiveClass`, `panelActiveClass`, `stickyClass`, `containerClass`, `verticalClass`, `rightClass`, `tooltipClass`, `triggerClass`, `activeClass`, `disabledClass`) because the classes are the contract (Tooltip keeps `templateClasses` for the consumer's own classes only: the consumer does not author the tip, so it is the only per-tooltip class hook; the tip leaves out a class it binds itself or a library `nfs-` class and reports it in development, [Spec: Tooltip](issues/27-spec-tooltip.md), D7); timing options that CSS or the browser now owns (`slideSpeed`, `moveTime`, `fadeInDuration`, `fadeOutDuration`, `showDelay`, `hideDelay` for Reveal, `animationDuration`, `animationEasing` (Drilldown's are its `scrollTop` scroll timing), `deepLinkSmudgeDelay`, `transitionTime`); `parentLink`, `autoApplyClass`, `backButtonPosition` (the markup is the switch); `resetOnClose`; `appendTo`; `forceFollow`; `touchCloseText`; `invertVertical` (dead); `checkEvery`; `dynamicHeight`; Interchange `type` (the host element decides the mode), the `"[path, query]"` string-array form of the programmatic `rules` option, and `replace(path)` (the `data-interchange` rule string stays as the `nfsInterchange` value beside a typed tuple form); `useMUI`; `hoverPane` (Dropdown: the pane is always in the Hover region, WCAG 1.4.13); `accessible` (always on); `data-toggle-focus` (toggle on both focus and blur, `R:disclosure` Triggers); Slider `changedDelay`, `binding`, `draggable` (`doubleSided`, `initialStart`, `initialEnd` become derived state and handle models, not dropped); Sticky `anchor`, `topAnchor`, `btmAnchor` (the platform mechanism cannot honour them; the Sticky spec gives a recipe); `slideClass`, `boxOfBullets`, `nextClass`, `prevClass` (class-name options, with `containerClass`); - Motion class options (`animationIn`, `animationOut`, `animate`) take Motion names or the consumer's own keyframe classes in the dot form (1.6 rule 4), never a library class name ([ADR 0039](adr/0039-directives-manage-every-foundation-class.md)), and feed 1.6; they are Options, not Variant inputs, so their Defaults tokens hold them. Orbit's `animInFromRight`, `animOutToRight`, `animInFromLeft`, and `animOutToLeft` are dropped: scroll snap moves the slides ([Spec: Orbit](issues/33-spec-orbit.md)).
- Global defaults (`Foundation.X.defaults.y = ...`) become one optional defaults token per plugin, Material shape B (`nfsRevealDefaultsToken` with an all-optional `NfsRevealDefaults` interface, `inject(token, {optional: true})` seeding input defaults; `R:di` 5). The token is provided at bootstrap, route, or element level and the nearest wins. For Aria-hosted plugins the token covers only options the library owns, because a host-directive wrapper cannot change an Aria input's default (the Accordion and Tabs prototype). A Defaults token never holds a Variant input's default ([ADR 0040](adr/0040-variant-input-types.md)).

### 1.5 State, reactivity, DOM access

- All state is signals read from `host` bindings or templates; OnPush is the v22 default and zoneless is assumed (`R:angular` Zoneless and OnPush defaults). Anything driven by a timer, observer, or native listener writes into a signal; no `markForCheck`; `NgZone` is used only for `runOutsideAngular` around timers started in render callbacks or handlers (1.11 decision 4), which is harmless in zoneless apps.
- `computed` for derived read-only state; `effect` only for side effects that are not DOM, never `history` or timers (1.11 decisions 3 and 4), and never to propagate state between signals (`R:angular` effect guidance), with two exceptions. The rendered-state signal of the bullet below records that a render side effect has happened (a `computed` cannot express it) and is read only by render callbacks, never by templates or `computed`s. A reverse-link registration of a reference input with its target (a Trigger with each target that implements `registerTrigger`, the Responsive Toggle bar with its menu, the Off-canvas panel with its content and the overlay with its panel, the Abide Form error with its referenced field) runs in an `effect` whose cleanup unregisters, because the reference can change at runtime; it writes only the target's registry signal and no DOM, so it is safe on the server, and it is Aria's own shape (`MenuTrigger` sets `menu.parent` from an `effect`, `src/aria/menu/menu-trigger.ts:91`). Confirmed by the [Consistency review and bundle index](issues/36-consistency-review.md) (audit 0004, unrecorded departure 6); the Abide Form error added 2026-09-26 from audit 0005 M4 ([Spec: Abide](issues/31-spec-abide.md)).
- DOM reads and writes that need layout (measure a pane, a slide, a drilldown submenu, a sticky sentinel) run in `afterRenderEffect` with explicit `earlyRead`/`write`/`read` phases, or in the callback of a `ResizeObserver`/`IntersectionObserver`/`MutationObserver` created in `afterNextRender`; never in `ngAfterViewChecked`, never at construction (`R:angular` effect and afterRenderEffect; hydration constraints in 1.11).
- Render callbacks that report or act on a breakpoint-driven render (a Completion output such as Interchange's `replaced`, a focus move after a mode swap, a measurement of the new mode) depend on rendered state, never directly on `NfsMediaQuery` reads or state derived from them. Rendered state is state that changes only when change detection has rendered the swap: a signal written by the swap `effect()` (Interchange outlet), a signal written by an `effect()` beside the host binding that applies it (Interchange background mode), or a signal view query of the new branch's elements (a template `@if` swap, as ResponsiveAccordionTabs does). The callback acts only when rendered and requested state agree. Reason: the Breakpoint service writes `current` in an `earlyRead` callback (ADR 0014); a later-phase render callback that reads it runs in the same batch of render hooks, before the change-detection pass that renders the swap. This was measured in the [Prototype: Interchange template outlet under hydration](issues/61-prototype-interchange-outlet-hydration.md) and fixed in the [Re-run: Interchange spec, the `replaced` timing and the outlet's focus rule](issues/67-rerun-interchange-replaced-timing.md) in three engines. The same holds for any state written inside a render callback, not only breakpoints. "Focus was inside the removed content" is recorded while the old nodes still exist, in one of three places: in the change-detection code that removes them (Interchange's swap effect); in the render callback that itself commits the swap, when the displayed mode changes only there (ResponsiveAccordionTabs' `earlyRead`, and the Nested menu root's swap callback for ResponsiveMenu); or continuously from `focusin`/`focusout` host listeners on a host that survives the swap. A render callback that runs after change detection has already removed the nodes is too late, because the browser has already moved focus to `<body>`. Library render callbacks use `afterRenderEffect` phases after `earlyRead` for anything that must see live breakpoint values, unless the callback itself commits the swap.
- Host bindings do the class and attribute work (`[class.is-active]`, `[attr.aria-expanded]`, `[attr.inert]`, `[attr.hidden]`); `Renderer2` and `ElementRef.nativeElement` writes are limited to what host bindings cannot express: imperative calls (`scrollTo`, `focus()`, `showModal()`); a State class on an element no library directive hosts, which the directive owns, strips when copied, and removes on destroy ([ADR 0039](adr/0039-directives-manage-every-foundation-class.md), as the user confirmed for the Magellan current-section marker, the Off-canvas class on `body`, and the Reveal Scroll lock on `html`); and a value that must change in the same task as a native event (the Slider's `aria-valuetext` fallback). Every such write runs in a render callback or a handler after hydration (1.11 rule 3), so it never carries first-paint state and never reaches server or prerendered HTML.
- `DOCUMENT` from `@angular/core`; `window` only inside render callbacks; `matchMedia` only through the Breakpoint service (1.7); `history`/`location` only after first render (1.11).
- Services are warranted only for state shared across instances: the Breakpoint service (1.7) and the Light dismiss registry (Part 3, Anchored pane). A plugin-internal service is allowed for the same reason (Reveal's `NfsRevealStack`: open order, Scroll lock count, the modal Escape listener; the Off-canvas Scroll lock count in `NfsOffCanvasScrollLock`), internal to its entry point and not public API (added 2026-09-26 from audit 0005, unrecorded departure 5). Everything else is directive-local state plus DI links (1.9). Services use `@Service()` (`R:angular` Dependency injection).
- Ids: consumer-supplied `id` wins; generated ids come from CDK `_IdGenerator` with a plugin prefix (`nfs-accordion-panel-`) (`R:di` 9, `R:aria` 1.4). Generated ids of Aria-hosted elements keep Aria's own prefixes (`ng-accordion-trigger-`, `ng-accordion-panel-`); the `nfs-<plugin>-` prefix applies only to ids the library itself generates. Generated ids differ between server and client (`_IdGenerator`, called with `randomize: true`, adds a per-process random infix, and its counter is module-global across requests, `research/angular-rendering-modes.md` 1 and 7 rule 8), which is harmless only because every reference to a generated id (`aria-controls`, `aria-labelledby`, `aria-describedby`) is itself a host binding rewritten at hydration. Anything addressed from outside the app (hash deep links, Magellan targets, Reveal `deepLink`) requires a consumer-supplied id; the deep-linking inputs warn in dev mode when the id was generated.
- RTL: `Directionality.valueSignal` from `@angular/cdk/bidi`, never `html[dir]` reads; CSS logical properties in library CSS (`R:utilities` 10 `rtl()`). Exceptions, each a read of the rendered layout, which follows CSS direction while `Directionality` reports only the `dir` of the document or of an element carrying CDK's `Dir` directive: the Slider reads the host's computed `direction` in client event handlers, because its native inputs and fill follow CSS direction; and the development geometry checks of the Float Classes (check 2) and the Float Grid (D9) read the parent's or the row's computed `direction`, because float placement follows it (2026-09-29, [Audit: the specs against the architecture guide](issues/142-audit-specs-against-architecture-guide.md)).
- Keyboard: `event.key` comparisons (`'Escape'`, `'ArrowDown'`) and `hasModifierKey` from `@angular/cdk/keycodes`; no `keyCode` (`R:cdk` keycodes). Aria owns the keyboard where it is hosted; the disclosure menus and Orbit implement the APG key tables directly. Every library key handler changes state first and calls `preventDefault()` last, because `preventDefault()` throws during event replay and skips everything after it (1.11).
- Effects: `effect()` runs on the server, so an effect never writes the DOM (a write there lands in the serialised HTML behind Angular's back, `research/angular-rendering-modes.md` 1).

### 1.6 Animation mechanics (ADR 0003)

User rule: no `@angular/animations`, no JavaScript-timed animation; `animate.enter`/`animate.leave` plus native CSS. The shared mechanics:

1. Elements that stay in the DOM and change state (dialog open/closed, off-canvas open, dropdown pane open, drilldown submenu active, tooltip visible, sticky stuck): a State class bound by the directive plus a CSS `transition` or `@keyframes` in the stylesheet. Foundation's own transitions are reused where they exist (`.drilldown` `$drilldown-transition`, `.off-canvas` `$offcanvas-transition-length`, `.tabs-content` transition, `R:menus` 2.8 and 6.8). The directive waits for `transitionend`/`animationend` on its host (filtered by `event.target`) before emitting `opened`/`closed` and before any DOM step that must follow the animation (`dialog.close()` after the exit keyframes, focus moves after a drilldown slide). A fallback timer of the measured duration plus 100 ms, the duration read from the host's computed `animation-*` or `transition-*` once the class is bound (Angular's own method for `animate.leave`; a measured zero completes at once), covers stylesheets that removed or changed the transition (Material's mechanic, `R:material` 0.2), and reduced motion resolves the wait synchronously (this refines the Motion UI prototype's design-time rule: a dropped stylesheet measures zero and completes at once; 2026-09-28, [Decide: the directive and component architecture guide](issues/141-decide-directive-component-architecture-guide.md): library-owned animations are measured too, as the Reveal and Accordion specs already do, so a consumer Sass override of a library duration is honoured).
2. Elements the library inserts or removes (Lazy content): `animate.enter="<classes>"` and `animate.leave="<classes>"` as host bindings on the inserted element with a class list from the plugin's `animationIn`/`animationOut`-style inputs (`R:angular` Animations; the host-binding form is documented in `enter-and-leave.md`). Orbit does not use this mechanism: its scroll-snap design, confirmed by the [Prototype: Orbit on CSS scroll snap](issues/46-prototype-orbit-scroll-snap.md), needed no inserted-slide fallback. An element the consumer inserts or removes itself (a callout inside `@if`) carries no library Motion class: its `animate.enter` and `animate.leave` take only the consumer's own keyframe classes, and a library Motion there goes through a Toggler's typed Motion input, with removal in its `closed` output ([Spec: Triggers (shared utility)](issues/54-spec-triggers.md), D17; [ADR 0039](adr/0039-directives-manage-every-foundation-class.md)).
3. Auto-height (Accordion, AccordionMenu, ResponsiveAccordionTabs in accordion mode): the CSS grid trick, `grid-template-rows: 0fr -> 1fr` on the content host with a single wrapper child (`overflow: hidden`), transition on `grid-template-rows`; the inner element clips only while collapsed or animating, so focus rings and content inside an open panel are never cut off (`R:material` 1 Animation; `R:platform` 5 fallbacks; `interpolate-size` is out of target; every engine in the Browser target interpolates `grid-template-rows`, so no `@supports` guard is needed). This is why `.accordion-content` is an attribute-selector component (1.1). Foundation's `foundation-accordion-menu` Sass has no height rule to reuse (its JavaScript animated with jQuery `slideDown`/`slideUp`), and AccordionMenu has no wrapper (a grid on the multi-child `ul.menu.nested` would size only its first row), so its documented custom rule, the smallest one that replaces `slideDown`, puts the grid on the parent `li` (`nfsMenuItem`, rows `auto 0fr` to `auto 1fr`) with the submenu `ul` as the clipped row (`min-height: 0; overflow: hidden`), keyed on `data-nfs-expanded` on the `li`, the clip released by `data-nfs-shown` once the submenu has opened; the [Prototype: Nested menu directive family with breakpoint mode switching](issues/50-prototype-nested-menu.md) confirmed it in three engines, the Hybrid form included. Drilldown keeps Foundation's transform slide and the wrapper `min-height` measured with `ResizeObserver` (`R:menus` 2.2, 2.9); `animateHeight` maps to Foundation's `.animate-height` class.
4. Motion classes: the library's `nfs-motion` mixin emits `@keyframes`-based classes under Foundation's Motion UI names prefixed `nfs-` for every default a spec needs (`nfs-fade-in`, `nfs-fade-out`, `nfs-slide-in-down`, `nfs-slide-out-up`, `nfs-slide-in-right`, `nfs-slide-out-left` and the mirror pair, `nfs-hinge-in-from-top`, `nfs-spin-in`, `nfs-spin-out`). For Reveal it also emits the `nfs-reveal-backdrop-in`/`nfs-reveal-backdrop-out` keyframes and the two `::backdrop` rules keyed on `.reveal.is-opening` and `.reveal.is-closing`, both added to its reduced-motion override ([Spec: Reveal](issues/18-spec-reveal.md)). A Motion input's value is a Motion name or the consumer's own keyframe classes, never a library class name ([ADR 0039](adr/0039-directives-manage-every-foundation-class.md), class names passed as input values). The primary entry point `ngx-foundation-sites` declares `NfsMotionInName` and `NfsMotionOutName`, the entering and leaving names of the set above written without the `nfs-` prefix (`'fade-in'`, `'spin-out'`); `NfsMotionClassList`, `` `.${string}` ``, the consumer's own keyframe classes, each written with a leading dot as Foundation's `data-toggler=".class"` writes a class; `NfsMotionIn` and `NfsMotionOut`, a name of that direction, the dot form, or `''`; and the pure function `nfsMotionClasses`, which maps a value to the classes to bind: `nfs-<name>` for a name, the dot form's classes without their dots, and none for `''` or anything else. A misspelt name, a name of the other direction, Motion UI's `fast`/`slow` modifiers, and `'nfs-fade-in'` fail to compile (measured with `ngc` 22.2.0 strict templates by the [Re-run: Reveal spec under the class rule](issues/110-rerun-reveal-class-rule.md)). The classes go to a State class binding (rule 1) or to `animate.enter`/`animate.leave` (rule 2) and must be keyframe animations; an input that takes an entering and a leaving value in one string (the Toggler's and the Dropdown pane's `animate`, `"<in> <out>"`, also shared by Responsive Toggle) is typed `NfsMotionPair`, declared beside them with its mapping `nfsMotionPairClasses`: an entering value alone (a Motion name or the dot form) or `''`, a leaving name alone, whose name tells its direction (the counterpart of Foundation's `data-closable="slide-out-right"`), or `` `${NfsMotionInName | NfsMotionClassList} ${NfsMotionOutName | NfsMotionClassList}` ``, split at whitespace into one token per direction, each mapped by `nfsMotionClasses`, so a pair half holds one class (a compound form such as `.a.b` is not supported); a value that does not split so, which the type admits only through a value that starts with a dot (`'.a .b .c'`, `'.a fade-in'`; measured with `tsc` 6.0.3 by the [Consistency review: the class-rule wave](issues/133-consistency-review-class-rule-wave.md)), maps to no class in either direction and is reported in development ([Spec: Toggler](issues/17-spec-toggler.md), D18; [Re-run: Dropdown spec under the class rule](issues/118-rerun-dropdown-class-rule.md)). Motion UI's own transition classes depend on the two-frame `mui-enter` then `mui-enter-active` protocol (`R:utilities` 4.1) that `animate.enter` does not perform, and they are not supported: `animate.enter` with transitions needs `@starting-style` (`enter-and-leave.md:28`), which is out of target; the Motion names map to the library's keyframe classes instead, and the consumer's own classes in the dot form must be keyframe animations. The [Prototype: `animate.enter` and `animate.leave` with Motion UI transition classes](issues/47-prototype-motion-ui-animate-enter.md) confirms the keyframe path in the three engines. The `motion-ui` package is never a dependency (map, Out of scope).
5. Reduced motion: the `nfs-motion` mixin sets `animation-duration: 1ms` and `transition-duration: 1ms` for every library animation under `@media (prefers-reduced-motion: reduce)` so `animationend` still fires and state changes stay instant; the Breakpoint service exposes `reducedMotion()` as a signal so Orbit autoplay and smooth scrolling switch off (`R:platform` 18). A consumer's own keyframe Motion class carries its own reduced-motion rule. A directive may in addition bind no Motion class while `reducedMotion()` is true, neither the library's class mapped from a Motion name nor the consumer's own class in the dot form, and complete the change in the same tick, which also covers a consumer class without that rule (Responsive Toggle, Dropdown); Reveal and Toggler rely on the `nfs-motion` override and the consumer's rule. The Breakpoint service spec's consuming-directive rule 3 names this exception (confirmed by the [Consistency review and bundle index](issues/36-consistency-review.md), audit 0004 unrecorded departure 8). A `nfsAnimationsToken` with `{disabled: boolean}` (Material `MATERIAL_ANIMATIONS` shape, `R:di` 5) disables animations globally and is what tests provide; `TestBed` `animationsEnabled` stays false in specs. Stories do not provide it globally ([storybook-conventions.md](storybook-conventions.md) section 4).
6. `MAX_ANIMATION_TIMEOUT` is left at Angular's default (4 s); no library animation exceeds 1 s.
7. Rendering modes: `animate.enter`/`animate.leave` never run on the server, so no enter classes are in server HTML; a server-rendered element carrying `animate.enter` plays its enter animation at hydration in every rendering mode ([Prototype: `animate.enter` at hydration](issues/52-prototype-animate-enter-hydration.md)). Rule 2 is therefore used only for elements that are never server-rendered in their animated state (client-created Lazy content views); persistent elements, the kept Tooltip tip included, use rule 1.

### 1.7 Breakpoints (ADR 0005)

- Source of truth for JavaScript: `nfsBreakpointsToken`, an `InjectionToken<NfsBreakpoints>` (`{map, serverBreakpoint?}`, map in px) with a root factory returning Foundation's default map (`small: 0, medium: 640, large: 1024, xlarge: 1200, xxlarge: 1440` in px, `R:utilities` 3.1); `serverBreakpoint` defaults to the Zero breakpoint (`small`). Provided at application level only. A consumer with a customised Sass `$breakpoints` provides the same values here; the consumer's `@include nfs-breakpoint-properties;` emits the `--nfs-breakpoint-<name>` px custom properties on `:root` from their own `$breakpoints`, and the `strictBreakpointSync` Runtime check reports, in the browser after the first render, when the token and the CSS disagree or when a Class breakpoint in `--nfs-breakpoint-classes` is missing from the token. The emission belongs to [Sass packaging for the new library](issues/57-sass-packaging.md); the token shape and the drift check belong to the [Spec: Breakpoint service (shared utility)](issues/53-spec-breakpoint-service.md), which waits on it. Foundation's `meta.foundation-mq` font-family handshake is not used: it needs computed style, which SSR does not have (`R:utilities` 10 MediaQuery).
- Service: `NfsMediaQuery` (`@Service()`), wrapping CDK `MediaMatcher` (SSR-safe noop stub, `R:cdk` layout) and exposing `current` and `reducedMotion` as signals, the read-only `serverBreakpoint` (the breakpoint it started from), and `atLeast`, `upTo`, `only`, `is`, `resolve(rules, breakpoint?)` (Breakpoint rules, at `current` by default or at a given breakpoint such as `serverBreakpoint`, [ADR 0032](adr/0032-responsive-accordion-tabs-instance-first-render.md)), and `matches` (Named queries) as reactive reads of them, plus `get`; it reports the Server breakpoint on the client until its first render callback and receives a per-request Server breakpoint through `TransferState` (ADR 0014). This refines this bullet's earlier "as signals" wording: only `current` and `reducedMotion` are signals, the rest are reactive reads, correct in a reactive context and a snapshot elsewhere (Breakpoint service spec decision 14). Queries are Foundation's `only screen and (min-width: <em>)` strings built from the token (`R:forms-media` Interchange named queries). `BreakpointObserver` and Material's `Breakpoints` constants are not used (`R:material` 11). The entry point also holds the Runtime checks ([ADR 0040](adr/0040-variant-input-types.md)): `provideNfsRuntimeChecks`, `provideNfsProductionRuntimeChecks`, and `nfsVariantCheck(directive)`, through which every directive with a Variant property reports ([Spec: Breakpoint service (shared utility)](issues/53-spec-breakpoint-service.md), Runtime checks).
- Server value: `serverBreakpoint` (default `small`, Foundation's mobile-first base) so server HTML is deterministic; consumers can set it from client hints in `app.config.server.ts` via a request-scoped factory (`ssr.md` Setting providers on the server). The first client render may swap a breakpoint-gated mode; the spec for each gated plugin (ResponsiveMenu, ResponsiveToggle, ResponsiveAccordionTabs, Sticky, Equalizer, Interchange, OffCanvas reveal, Tooltip `showOn`) states what changes and how focus is preserved. A first-render swap moves focus like any other swap, because server-rendered controls can hold focus before hydration: the swapping directive reads the live `document.activeElement` in an `earlyRead` callback before the old nodes are removed or re-classed ([Spec: Responsive Accordion Tabs](issues/19-spec-responsive-accordion-tabs.md)). The [Angular 22.2 @defer, SSR, prerendering, hydration, and event replay for DOM-touching directives](issues/38-angular-rendering-modes.md) ticket found no Angular-provided client-hint mechanism, so the recipe (a `useFactory` provider reading `REQUEST` headers, which is null when prerendering) belongs to the [Spec: Breakpoint service (shared utility)](issues/53-spec-breakpoint-service.md). The recipe is consumer code: a `useFactory` provider in the server configuration mapping `Sec-CH-Viewport-Width` with `nfsBreakpointForWidth`; the Breakpoint service spec documents it.
- CSS first: when only styling changes with the breakpoint, the spec uses Foundation's `.show-for-*`, `.hide-for-*`, `.<bp>-horizontal`, `.reveal-for-<bp>`, `.in-canvas-for-<bp>` classes, set by the directive that owns them through a Variant input (1.4) or a host binding (ADR 0039), and no breakpoint logic in JavaScript. Content the consumer shows or hides carries `nfsVisibility` with `showFor` or `hideFor` ([Spec: Visibility Classes](issues/104-spec-visibility-classes.md)); a Plugin directive that owns a Visibility class for its own behaviour (the Responsive Toggle's bar and menu) binds it itself, and `nfsVisibility` never shares its element. A responsive Variant input takes a Breakpoint query for an on or off class (`showFor="large only"`, `expanded="medium down"`) or a Breakpoint rules object for a valued family (`[orientation]="{small: 'vertical', medium: 'horizontal'}"`). It never takes a rule string, whose tokens would be Foundation class names. Its breakpoint names are Class breakpoints (`NfsClassBreakpoint`), closed over `$breakpoint-classes` and extended by the consumer's Variant declaration file, so a misspelt breakpoint, modifier, or rules key fails to compile. `nfs-breakpoint-properties` also lists them as `--nfs-breakpoint-classes`. An Option that sets a class only for Class breakpoints (`revealOn`, `inCanvasOn`) is typed `NfsClassBreakpoint`; an Option whose spec emits the classes for every breakpoint keeps `NfsBreakpointName` (Responsive Toggle `hideFor`). Container queries are allowed inside library CSS for component-internal sizing only; breakpoint-named options keep viewport semantics because Foundation documents them that way (`R:platform` 11 Known gaps).
- Option syntax: `data-responsive-menu="drilldown medium-dropdown"` and `data-responsive-accordion-tabs="accordion medium-tabs"` keep their rule-string form as the `rules` input (the string is Foundation's documented contract); the parser is shared and typed (`{small: 'drilldown', medium: 'dropdown'}` object form also accepted). Rules resolve by Breakpoint map order (the largest rule breakpoint at or below the current one), not by written order; a bare mode applies from the Zero breakpoint; tokens split at the last hyphen (`parseNfsBreakpointRules`).

### 1.8 Triggers

Foundation's `data-open`, `data-close`, `data-toggle` become three directives in a shared spec (Part 3): `[nfsOpen]`, `[nfsClose]`, `[nfsToggle]`. Each takes a template reference to an Openable (or an array for Foundation's space-separated multi-target form); `[nfsClose]` and `[nfsToggle]` with no value act on the nearest Openable ancestor through DI, which is Foundation's empty `data-close` bubbling rule (`R:utilities` 2.2). Only the bare attribute selects the Nearest Openable (`inject(nfsOpenableToken, {optional: true, skipSelf: true})`); a bound `null` means no target. `nfsToggle` with several targets moves them together. The Openable contract is an interface, `NfsOpenable`: `isOpen`, `id` (the controlled element's id), and `triggerRole` (`'disclosure' | 'dialog' | 'modal-dialog' | 'toggle-button' | 'none'`) as signals, `open(trigger?)`, `close(result?)`, `toggle(trigger?)`, and an optional `registerTrigger(trigger)`, behind the lightweight `nfsOpenableToken`; the Trigger renders `aria-expanded` plus `aria-controls` for disclosures, adds `aria-haspopup="dialog"` for dialogs, renders `aria-haspopup="dialog"` plus `aria-controls` without `aria-expanded` for a modal Reveal or an Off-canvas panel in Modal mode (`modal-dialog`), renders `aria-pressed` on `nfsToggle` for toggle buttons, and nothing for plain commands; `nfsClose` renders no ARIA. A modal Reveal's Trigger renders no `aria-expanded`, because `showModal()` makes it inert while open; `role="dialog"` Dropdown panes keep it, and Off-canvas Modal mode reports `modal-dialog`, because its Modal inert set makes every Trigger outside the panel inert while open (Part 4, Decided item 4; [Resolve the assistive-technology checks](issues/77-evidence-assistive-technology-checks.md)), apart from the edge cases the modal-opener decision accepts (a Trigger inside an exception, an `nfsToggle` inside its own panel, an element added after the set was taken, a panel open by default before hydration, `autoFocus: false`). Reveal, OffCanvas, DropdownPane, Toggler, ResponsiveToggle and Tooltip provide the token. A Trigger binds no class, and no Openable writes one on its Triggers: the classes on a Trigger's host come from the directive beside it (`nfsButton`, `nfsCloseButton`, `nfsMenuIcon`), placed beside rather than hosted ([Spec: Triggers (shared utility)](issues/54-spec-triggers.md), D16, D18). Triggers must be native `<button type="button">` (or a link when it also navigates); the directive warns in dev mode on a non-focusable host (`R:apg` Toggler delta). Triggers do not bind `type`; a `<button>` Trigger gets `type="button"` from the consumer, from `nfsButton`, from `nfsCloseButton` ([Spec: Close Button](issues/83-spec-close-button.md)), or from `nfsMenuIcon` ([Spec: Top Bar](issues/86-spec-top-bar.md)) (confirmed by the Triggers spec, which warns in dev mode on a typeless `<button>` Trigger inside a form). Invoker Commands and `popovertarget` are out of target and not used; `<form method="dialog">` inside a Reveal is documented as a platform alternative for close buttons: it closes natively, and the Reveal re-syncs through the `close` event, reporting `returnValue`, without the exit animation or `closePredicate` ([Spec: Reveal](issues/18-spec-reveal.md)). `data-closable` is not a directive: to hide in place as Foundation's `fadeOut()` did, the element is a Toggler in visibility mode with a bare `nfsClose` on the `nfsCloseButton` inside, animated by the Toggler's typed Motion input; to remove it, the consumer writes `@if` and a handler, and its `animate.leave` takes only the consumer's own keyframe class; a removal that should play a library Motion hides through the Toggler and is removed in its `closed` output, so no library class name appears in consumer code ([Spec: Triggers (shared utility)](issues/54-spec-triggers.md), D17; [ADR 0039](adr/0039-directives-manage-every-foundation-class.md)). `closeme.zf.*` becomes the Light dismiss registry (Part 3).

### 1.9 DI patterns

Adopted from `R:di` 9 (the catalogue):

- Parent handle: `InjectionToken<Parent>` in `<plugin>-tokens.ts` with `import type`, parent `providers: [{provide: nfsXToken, useExisting: NfsX}]`, child `inject(nfsXToken)` required when the child cannot exist alone (accordion title inside an item), `{optional: true}` with a dev-mode `reportViolations`-style warning when the child may stand alone (menu item outside a menu root). Nested containers re-provide the token as `undefined` (`CdkAccordionItem` pattern) so grandchildren do not register upward (Equalizer needs no `undefined` provider: a nested container providing its own token already shadows the outer one).
- Composition, never subclassing (map, Standing preferences; [ADR 0040](adr/0040-variant-input-types.md)): library directives are not extension points. An Angular subclass inherits host bindings, inputs, outputs, host directives, and lifecycle hooks, but not `providers`, its selector, or `exportAs`, and a directive injected by class matches its exact type only, so a consumer subclass of a token-providing directive would leave its children silently without a parent. No spec asks a consumer to subclass or to wrap a library directive in order to type an input.
- Hosting a class directive (2026-09-27, [Spec: Menu](issues/85-spec-menu.md)): a directive whose element is always another component's Structural class hosts that component's directive through `hostDirectives` and exposes its Variant inputs under their own names, so the class and its Variants have one owner: the Accordion Menu, Drilldown, and Dropdown Menu roots and `NfsSubmenu` host `NfsMenu`. Since Angular 22.0 a directive reached several times through host directives on one element is created once with the exposed input maps merged (one input exposed under two names is an error), and a template match of the same directive discards its host-directive matches, so a consumer who also writes it gets no NG0309; a host's own class bindings override its host directive's. All three were measured with Angular 22.2.0 in the Menu ticket. A behaviour that may sit on any element (Smooth Scroll, Magellan) is written beside the class directive instead. A helper that a factory provider creates on the hosting element reads the hosted directive the same way, because Angular runs a node provider's factory at the node that declares it: the Nested menu root reads the Menu's `align()` for the dropdown Base side (measured with Angular 22.2.0 in the [Re-run: Nested menu (shared utility) spec under the class rule](issues/132-rerun-nested-menu-class-rule.md)). The Flexbox Utilities' `NfsFlexAlign` and `NfsFlexChild` are written beside the directive of a Flex parent or Flex child (the Button Group, the grids, the Media Object) or hosted by it under the same input names; no spec declares inputs of its own for their classes, and `NfsFlexContainer` hosts `NfsFlexAlign` ([Spec: Flexbox Utilities](issues/103-spec-flexbox-utilities.md), D8). Two library directives written on one element must not declare an input of the same name with different types: Angular sets a template binding on every directive that declares the input, so `<div nfsCell nfsCallout size="small">` fails to compile against the cell's column count. Where two families share an input name (`size` on cells, columns, callouts, buttons, close buttons, and dropdown panes; `collapse` on rows and reveals; `expanded` on rows, buttons, button groups, and menus; `color` on buttons, button groups, callouts, badges, labels, and progress bars; `position` on off-canvas panels, dropdown panes, and tooltips; `alignment` on dropdown menus, dropdown panes, tooltips, and media object sections; `offset` and `up` on cells, columns, grids, and rows), the elements nest, as Foundation's markup does ([Spec: XY Grid](issues/99-spec-xy-grid.md), D15).
- Ancestry that projection can hide (2026-09-28, [Re-run: Dropdown Menu spec under the class rule](issues/113-rerun-dropdown-menu-class-rule.md)): a directive that must know at first paint that it sits inside another library element injects that element's lightweight token optionally at construction, which is right on the server for everything declared inside it. Where content projection from another template can hide the provider (DI follows the declaration site), it may walk the DOM once in its first render callback, only when the token is absent, and reports that case in development builds, because the state it fixes changes at hydration: the Nested menu root and `nfsTopBarRightToken`. A check that only reports placement reads the DOM alone (the Top Bar's section check, its D13).
- Forgotten imports (2026-09-28, [ADR 0046](adr/0046-forgotten-imports-caught-by-checks.md), [Spec: forgotten-import checks (shared utility)](issues/150-spec-forgotten-import-checks.md)): entry points export their directive classes and no import arrays. Every library directive and component with an attribute selector calls `nfsDirectiveCheck('<Class>', family?)` from `ngx-foundation-sites/media-query` once, from its constructor, inside an inline `if (typeof ngDevMode === 'undefined' || ngDevMode)` block (a hoisted guard kept the checks in production bundles); the call records its host for the `strictDirectiveImports` Runtime check and runs its In-family checks. A part whose parent injection is optional passes the directives that provide or host its parent and whether the injection found one, and a part with children passes the child directives it probes; each family spec lists these per part by that spec's rule. A required parent injection needs no parent check, because NG0201 is the report, and every parent token's description names, in development builds only, the directive that provides it, its entry point, and the same-template rule (`typeof ngDevMode === 'undefined' || ngDevMode ? "nfsAccordionToken (provided by NfsAccordion from 'ngx-foundation-sites/accordion' on an ancestor element declared in the same template)" : ''`). Under the opt-in `strictParents` flag, a part in that spec's table throws at construction in development builds when its optional parent injection found nothing; a part that a component projects into its parent from another template renders there through a template outlet with the parent element's injector (`viewChild(Parent, {read: Injector})` and `ngTemplateOutletInjector`, measured with Angular 22.2.0), which the required injections need already.
- Same-element siblings: `inject(X, {self: true, optional: true})` (Abide's input directive reading `FORM_FIELD` from `@angular/forms/signals`, and `NgControl` as a courtesy).
- Projected child that must fail outside its parent: `inject(Parent, {host: true})`.
- Ordered children: parent-owned registration (`register()` in `ngOnInit`, `unregister()` on destroy) with DOM-order sorting from a `MutationObserver` started in `afterNextRender`, Aria's `SortedCollection` shape, rather than `contentChildren` queries, because it survives `@for`, `@defer`, Lazy content and projection (`R:di` 3c). `contentChildren` is used only for dev-mode validation. A family whose readers need order only at event time or in a render callback (the Nested menu) sorts there with `compareDocumentPosition` and keeps no `MutationObserver`. This `ngOnInit` rule is for children found through DI; a child linked by a reference input registers from an `effect` with cleanup instead (the reverse-link exception in 1.5), because the reference can change after `ngOnInit`.
- Links between non-nested elements: template references on inputs (`[nfsOpen]="reveal"`, Aria `[panel]`) or value-keyed pairing (`nfsTab value="x"` with `nfsTabsPanel value="x"`).
- Aria composition: a Foundation-classed directive hosts the Aria directive through `hostDirectives`, exposes only the Aria inputs it wants (aliased to Foundation names), adds the Foundation class and State classes in `host`, and reaches the Aria instance with `inject(AriaDirective)` (the `simple-menu.ts` shape, `R:di` 4). The wrapper's host binding on an attribute the Aria directive also binds is applied after Aria's in each pass, but each binding writes only when its own value changes, so the override holds only when Aria's value never changes after the wrapper's last write or equals the wrapper's whenever it changes (the Tabs and Orbit bullet `tabindex` before and after Aria's first active item), or changes in every pass in which Aria's does, which a binding computed from the same public Aria signal guarantees (the Orbit slide's `inert`, derived from `TabPanel.visible()`). A plain override that must differ from an Aria value that can still change loses; derive it from Aria's signal instead ([adr/0037-orbit-slide-hosts-tab-panel.md](adr/0037-orbit-slide-hosts-tab-panel.md), superseding ADR 0034). Risk: Aria link inputs declared `input.required` (`AccordionTrigger.panel`) cannot be set by the wrapper from code; resolved by the [Prototype: `@angular/aria` Accordion and Tabs under Foundation markup](issues/43-prototype-aria-accordion-tabs.md): Accordion composes, with `#c="nfsAccordionContent"` and `[panel]="c.panel"` as the binding form. An Aria input whose default differs from Foundation's is not exposed; the wrapper declares its own input and enforces it through Aria's models, methods, and event interception ([Spec: Accordion](issues/15-spec-accordion.md); [ADR 0028](adr/0028-accordion-expansion-policy.md)). Aria-hosting containers carry the Replay guard, a `keydown` listener that stops propagation of the keys Aria handles so a replayed key is not handled again by an outer widget.
- Defaults tokens: one Shape B `nfsXDefaultsToken` per plugin (1.4). A single `provideNfs*()` function is not needed; none of Aria or CDK ships one (`R:di` 5). The runtime checks are configured by two provider functions of `ngx-foundation-sites/media-query`, `provideNfsRuntimeChecks` (development overrides) and `provideNfsProductionRuntimeChecks` (production opt-in), not by an umbrella `provideNfs()` ([ADR 0040](adr/0040-variant-input-types.md)).
- Platform guard: never `isPlatformBrowser` in templates; browser-only work in render callbacks; platform-specific services (Breakpoint server value) via `app.config.server.ts` providers (`ssr.md` Providing platform-specific implementations).
- Lazy services: `injectAsync` (`@angular/core`, stable since 22.0, with `prefetch: onIdle`) is the pattern for a service or component needed only after a client interaction; each spec that owns such a piece decides eager or `injectAsync` in its decision log. The Anchored pane spec decided eager loading because placement must land in the render pass that shows the pane.
- Restore any global the directive touched (hash, `history` state, `body` classes, the Off-canvas Modal inert set) in `DestroyRef.onDestroy`, except a deep-link hash, which is the user's state and outlives the directive that wrote it (Accordion does not clear it on destroy; Magellan does not restore the URL on destroy either, since rewriting history during route teardown would corrupt the Router's navigation).

### 1.10 Accessibility baseline

Shared by every spec (`R:apg` Cross-cutting practices; map, Standing preferences):

- WCAG 2.2 AA is a requirement for every directive and component (map, Standing preferences; [ADR 0022](adr/0022-wcag-2-2-aa-enforcement.md)). Each spec carries a criteria subsection naming the 2.2 AA criteria its plugin touches and how each is met; where a Foundation default fails one (1.4.3 text contrast, 1.4.11 non-text contrast, 2.5.8 target size, 2.4.11 focus not obscured, 1.4.12 text spacing, 1.4.10 reflow, and 2.4.7 focus visible are the ones found so far), the spec states the Sass settings the consumer must set or the smallest custom rule the `nfs-<plugin>` mixin adds, with the reason. Every axe run names the WCAG 2.2 AA tags, and the story gate is the enforcing check; where axe has no rule, the mixin checks at compile time with the exact WCAG relative-luminance formula, computed by one library-internal Sass helper with `math.pow` that composites a translucent colour over `$body-background` first; a translucent colour painted over an image rather than the page (the Orbit's caption and arrow bands) is composited over `#fff` and over `#000`, the lightest and darkest colours an image can hold, before the helper compares it ([Spec: Orbit](issues/33-spec-orbit.md), D17); never with Foundation's `color-luminance()`, which raises to the power 2.4 through Foundation's approximate `pow()` and `nth-root()` and overstates some ratios (measured by the [Spec: Top Bar](issues/86-spec-top-bar.md) ticket: it passes 26 failing pairs of a 16-step colour grid against `#fefefe` and `#0a0a0a`, such as `#1177dd` on `#0a0a0a` at 4.51:1, where the exact ratio is 4.44:1), and never with Foundation's `color-contrast()`, which rounds to one decimal and would pass a failing pair (Foundation's alert button fill measures 4.498:1 against its label, and `color-contrast()` rounds that to 4.5, over the 4.5:1 threshold; [Spec: Button](issues/37-spec-button.md), WCAG 2.2 AA revision). A text colour Foundation picks with `color-pick-contrast()` is checked as Foundation emits it: that function compares ratios from the approximate `color-luminance()`, rounded to one decimal, keeps the first candidate on a tie, and ignores a translucent colour's alpha, so it can pick the failing candidate while the other passes (measured by the [Spec: Badge](issues/93-spec-badge.md) ticket: on `#e10f69` it picks `$black` at 4.22:1 where `$white` reaches 4.65:1); each spec that relies on the pick decides whether its mixin corrects it, as `nfs-badge` and `nfs-label` do, or only checks it, as `nfs-button` does for buttons and button groups, whose error then names the other candidate's ratio. A spec quotes a ratio as that exact formula gives it on the colours as painted (8 bits per channel) or as the helper computes it (unrounded channels), writes a failing ratio with enough decimals to stay below its threshold (4.498:1, never 4.50:1), and quotes axe's figures as axe's.
- The APG pattern named in Part 2 is the contract; "a role is a promise": no role without its full keyboard table. Site navigation uses the disclosure navigation pattern, never `menu`/`menubar`/`tree` (ADR 0004).
- Native elements first: triggers are `<button type="button">`, dialogs are `<dialog>`, sliders are `<input type="range">`, links stay `<a href>`. Foundation's `<a href="#">` accordion and menu triggers become buttons in the spec markup; the hybrid disclosure form (link plus toggle button) covers menu parents that also navigate.
- Hidden content that stays in the DOM gets `inert` (Aria's choice) and Foundation's display rules; content that is truly gone uses `hidden` or `@if`; `aria-hidden` is not used for hiding. Exceptions: `<dialog>` and top-layer elements manage their own inertness, and the closed off-canvas panel relies on Foundation's `.off-canvas.is-closed { visibility: hidden }`, because an `inert` there would also disable a panel that `.reveal-for-<bp>` shows at larger breakpoints (1.11 decision 8). A hidden Drilldown ancestor level, which still holds the open level, uses Foundation's `invisible`, never `inert`, because `inert` cannot be undone inside a subtree and the open level's `visible` overrides `visibility: hidden` ([Spec: Nested menu (shared utility)](issues/56-spec-nested-menu.md), D9, measured in [Prototype: Nested menu directive family with breakpoint mode switching](issues/50-prototype-nested-menu.md); recorded 2026-09-29 by [Audit: the specs against the architecture guide](issues/142-audit-specs-against-architecture-guide.md)). The Tooltip tip is `aria-hidden="true"` at all times, not to hide it but because its hidden description element carries the same text ([Spec: Tooltip](issues/27-spec-tooltip.md), D4). Where the library hides a Foundation-classed element with `hidden` and a Foundation rule sets `display` on that element, it also binds Foundation's `.is-hidden`, because normalize's `[hidden] { display: none }` loses to later Foundation component `display` rules (`.menu`, `.thumbnail`). An element whose Foundation rule sets no `display` uses `hidden` alone: the Tooltip tip, whose `tooltip` mixin sets none ([Spec: Tooltip](issues/27-spec-tooltip.md); confirmed by the [Consistency review and bundle index](issues/36-consistency-review.md), audit 0004 unrecorded departure 7). The `hidden` attribute a consumer writes does not hide an element whose Foundation class sets `display` either: measured in three engines, `.flex-container` and `.grid-x` keep `display: flex` over normalize's `[hidden]`, which comes first at equal specificity; the specs hide such an element with `@if`, a Toggler in Visibility mode (which binds `.is-hidden`), or `nfsVisibility` with a bare `hideFor` (Foundation's `.hide`), measured for `.thumbnail`, `.float-center`, `.flex-container`, `.grid-x`, `.grid-y`, `.cell-block-container`, and the Flex Grid's `.row` by the [Spec: Thumbnail](issues/97-spec-thumbnail.md), [Spec: Float Classes](issues/105-spec-float-classes.md), [Spec: Flexbox Utilities](issues/103-spec-flexbox-utilities.md), [Spec: XY Grid](issues/99-spec-xy-grid.md), and [Spec: Flex Grid](issues/101-spec-flex-grid.md).
- Names: `region`, `dialog`, `tabpanel`, `tablist`, `slider`, carousel `group` are named through `aria-labelledby` pointing at visible text, with `aria-label` as the fallback; the spec's rendered HTML shows both. `aria-label` is never added to elements named from content (Foundation Nest's copied `aria-label` is dropped). On an element the consumer writes, the name is the consumer's own `aria-labelledby` or `aria-label` attribute, checked in development, and the directive declares no name input ([Spec: Progress Bar](issues/95-spec-progress-bar.md), D12; [Spec: Table](issues/92-spec-table.md), D4); a name input exists where the consumer cannot reach the named element (Responsive Accordion Tabs' `label` and `labelledBy`). A development check that reads a name or text from content (the host's, a referenced element's, a `label`'s, a `legend`'s, a `caption`'s) reads it as accessible-name computation does: text outside `aria-hidden="true"` subtrees, visually hidden text included, and an embedded image's text alternative, the non-blank `alt` of an `img` or the non-blank `aria-label` of an element with `role="img"`, so it never reports a name or text that assistive technology has (the [Spec: Thumbnail](issues/97-spec-thumbnail.md)'s check 2; Chromium and Firefox name a group from an image-only `legend`'s `alt`, measured by the [Re-run: Switch spec, out-of-scope survivors](issues/147-rerun-switch-out-of-scope-survivors.md); 2026-09-29, [Consistency review: the class-rule wave](issues/133-consistency-review-class-rule-wave.md)).

The consumer names a `region` with `aria-labelledby`, at the table's caption or a heading, or with `aria-label`, and a development check reports an unnamed Scroll region. Chromium focuses a scroller without one only in releases after the Browser target's Chrome 119, and Safari does not. The Prototyping Utilities' overflow directives, which may sit on any element, an Aria-hosted one with its own `tabindex` included, bind none and warn instead ([Spec: Prototyping Utilities](issues/102-spec-prototyping-utilities.md), D13).
- Table ([Spec: Table](issues/92-spec-table.md)): Foundation's stacked table hides its `thead` and `tfoot` below `$table-stack-breakpoint` (measured through Windows UI Automation in Chromium and Firefox: two rows and no column headers, which axe does not report), so `nfs-table` stops the compile unless `$show-header-for-stacked: true` and keeps the footer with one rule (`table.stack tfoot { display: table-footer-group; }` in Foundation's stack media query). It also stops the compile when text or a link is under 4.5:1 on any table background: Foundation's links reach only 3.97:1 to 4.45:1 on seven of the eight, so the consumer sets the Callout's `$anchor-color`.
- Visibility Classes ([Spec: Visibility Classes](issues/104-spec-visibility-classes.md)): content hidden by `nfsVisibility` is hidden from assistive technology too, so `showFor` and `hideFor` hide only a presentation another element also carries (1.4.10 at 320 CSS px; 1.3.4 for the orientation conditions), a requirement every story asserts. Print-only content (`showFor="print"`) is hidden on every screen too, so it only adds to the screen page and never holds the caption, label, or legend of something shown there (measured: a print-only `caption` leaves its table unnamed in Chromium's tree, and axe reports nothing; [Re-run: Visibility Classes spec for the print classes](issues/143-rerun-visibility-classes-print.md)). Visually hidden text (`nfsShowForSr`) never holds a tab stop, which it reports in development (measured in three engines: a focused `.show-for-sr` element is a 1 by 1 px box, 2.4.7, and axe reports nothing), follows a control's visible text (2.5.3), and never replaces a form field's visible label (3.3.2). `nfsShowOnFocus` sits on the focused element itself, which it reports in development (measured: on a wrapper it paints nothing while its link has focus). The skip link is `nfsShowOnFocus` beside `nfsSmoothScroll` with the live current-path `href` and a `main` with `tabindex="-1"` (2.4.1, 2.4.3).
- Elements that can cover content (Sticky): WCAG 2.4.11 is met by required consumer `scroll-padding`, checked by a development warning and an e2e case; 1.4.3 needs an opaque background on a stuck element that overlaps content, which a Title Bar or a Callout paints and a Top Bar paints only while `$topbar-background` is opaque, so a transparent Top Bar, which Foundation's Sass allows, is not stuck over content ([Spec: Sticky](issues/28-spec-sticky.md)).
- axe cannot enforce every WCAG 2.2 AA criterion: it reports `target-size` only as incomplete for roving-tabindex items whose neighbours are outside the tab order, marks text contrast over images and of one-character text incomplete (`shortTextContent`: every one of Foundation's badge examples, measured by the [Spec: Badge](issues/93-spec-badge.md) ticket), has no 1.4.11 rule, does not see text or a focus outline that an ancestor's `overflow: hidden` cuts off ([Spec: Card](issues/90-spec-card.md), [Spec: Responsive Embed](issues/96-spec-responsive-embed.md)), and does not see a focus ring an engine draws across a picture instead of around it ([Spec: Thumbnail](issues/97-spec-thumbnail.md)); specs enforce those through Library mixin floors, compile-time contrast checks with the exact unrounded ratio, and e2e geometry.
- Where a Foundation default marks state by colour alone against a neighbour rather than a background (a selected tab, an active bullet), axe's contrast rule cannot see the pair; the spec names the required Sass settings and a play function asserts the contrast ratio between the two states directly (Tabs: `$tab-background-active: $primary-color; $tab-active-color: $white;`, checked for 3:1 between selected and unselected tab backgrounds; on a `primary` bar the `nfs-tabs` rule gives the selected tab the panel's colours, and its compile-time checks cover the plain strip's pairs and the pair against the bar).
- Gate: every story runs axe through `@storybook/addon-a11y` with `parameters.a11y.test = 'error'` and `runOnly` set to the tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`, `best-practice`; only the Anti-pattern story exception in the [Storybook conventions](storybook-conventions.md) may switch off the rules it demonstrates (`R:tooling` Accessibility checks in CI).
- Target size (WCAG 2.2 success criterion 2.5.8) is met by size, not by the spacing exception, wherever a Foundation control is smaller than 24 by 24 CSS px and a spec owns it: the Library mixin grows the control's box to 24 by 24 CSS px without resizing what Foundation draws, because axe's `target-size` rule measures only the element's box. Where the box is transparent and the drawing is a glyph inside it (`.close-button`, `.button`), a `min-width: 24px; min-height: 24px` floor. Where the drawing is laid out on the box (the `.menu-icon` hamburger, whose bars fill its 20 by 16 px padding box), a transparent border on a content box (`box-sizing: content-box; border: solid transparent; border-width: 4px 2px`), which leaves the padding box, and so the drawing, unchanged; `nfs-menu-icon` applies it to every `.menu-icon`, so the Responsive Toggle's and Off-canvas's title bars get it from that include ([Spec: Top Bar](issues/86-spec-top-bar.md)). Where the target is an inline text link in a floated row (a breadcrumb step), the link becomes `inline-block` with the `min-width` and `min-height` floor and every item of the row gets one line of at least 24 px, so the rows stay aligned and 24 px apart; line height alone is not used, because a user's line-height override shrinks the links again (measured in three engines, [Spec: Breadcrumbs](issues/88-spec-breadcrumbs.md)). A transparent hit-area pseudo-element is not used: measured in three engines, it takes pointer hits outside the box, but axe reports a close button over a link as incomplete ([Spec: Close Button](issues/83-spec-close-button.md)) and fails two adjacent menu icons ([Spec: Top Bar](issues/86-spec-top-bar.md)), both of which it passes with the floor and the border.
- Strings and direction (2026-09-28, [Decide: the directive and component architecture guide](issues/141-decide-directive-component-architecture-guide.md)): the library renders no human-readable string of its own; every label, role description, and formatted value comes from consumer markup or a consumer function (the Slider's `displayWith`, Orbit's labels, the names the Close Button, Top Bar, and Progress Bar require), and a directive declares no name input for an element the consumer writes (the Names bullet above). Direction comes from `Directionality.valueSignal` (1.5, with its exceptions for reads of the rendered layout), and library CSS uses logical properties, never `:dir()`, which is outside the Browser target (web-features 3.40.0: widely available only from 2026-06-07).

### 1.11 Rendering modes (ADR 0008)

User rule (map, Standing preferences): every directive and component supports `@defer` including hydrate triggers, server-side rendering, prerendering, full and incremental hydration, and event replay. Facts come from `research/angular-rendering-modes.md` (cited `R:rendering` below); its eleven library rules (section 7) are adopted as written and are not repeated here, only the decisions they force.

Facts that shape the design (`R:rendering` 0, 2, 4):

- For SSR consumers a plain `provideClientHydration()` turns on incremental hydration and therefore event replay; the library must assume both are on. `RenderMode.Client` routes skip hydration, so one app exercises CSR, SSR plus hydration, and prerender plus hydration.
- Hydration matches nodes by type and tag name only. A class or ARIA value that differs between server and client is not an error but a visible flash until the first client pass; a structural difference (extra or missing node) is.
- Hydration writes a located element's attributes again: Angular's element instruction applies its static attributes to the server-rendered node before directives are created, and its property bindings write on the first client pass, with no hydration skip (read in 22.2). Writing `src` again, even the same value, reloads a frame and resets a media element, so every server-rendered `iframe` and `video`, static or bound, is requested once from the server HTML and again at hydration, and a video the user started before hydration returns to its start (measured with Angular 22.2 in three engines by [Spec: Responsive Embed](issues/96-spec-responsive-embed.md), with a clean hydration). An embed that never changes goes inside `@defer (hydrate never)` (requested once); one that changes, or sits below the fold, is created on the client with `@defer (on viewport)` and a placeholder (requested once, on the client). Every spec whose markup server-renders a frame or a media element documents this.
- A static attribute that a directive binds to `null` (`'[attr.align]': 'null'`, 1.4) is absent from the server HTML. Hydration's creation pass writes it back onto the server node, in the same batch in which it resets the `class` attribute to the element's static classes, and the first update pass removes it and restores the bound classes; client rendering inserts the element with its static attributes and without its bound classes until that pass. No rendering update drew either window (measured with Angular 22.2, zoneless, in development and production builds, in Chromium, Firefox, and WebKit, for full and incremental hydration and client-rendered `@defer`, by [Decide: inputs named like HTML presentational attributes](issues/139-decide-inputs-named-like-presentational-attributes.md)), so a null binding adds no risk the class bindings do not already carry. An attribute the browser acts on at insertion (`autofocus`) acts in client rendering before that pass, so a null binding cannot stop it there (1.4).
- `ngSkipHydration` is valid only on component hosts (NG0504 elsewhere), so every directive must be hydration-clean by construction; the library never uses it and never uses Shadow DOM encapsulation (which silently skips hydration and replay).
- Event replay covers only listeners declared in templates or `host` metadata on elements, for the listed native types (`click`, `keydown`, `focusin`, `focusout`, `pointerdown`/`up`/`move`, `mouseover`/`mouseout`, `input`, `change`, `submit`, `toggle`, and others). Not replayed: `mouseenter`, `mouseleave`, `pointerenter`, `pointerleave`, `scroll`, `resize`, `animation*`, `transition*`, custom events, outputs, listeners added in code, and `document:`/`window:`/`body:` host listeners. `preventDefault()` throws during replay and skips the rest of the handler; Aria's keyboard manager calls it after its handler.

Decisions:

1. Server output is the first paint. Every state visible at first paint is a host binding on signal state (Foundation classes, State classes, ARIA, `inert`, `hidden`, `--nfs-*` style bindings). No template branches on the platform. Examples: a closed Reveal is `<dialog class="reveal">` without `open`; a hidden pane is `.dropdown-pane` without `.is-open`; a collapsed accordion panel carries `inert` and the collapsed `0fr` row of `nfs-accordion` (Foundation's `display: none` only when that mixin is missing).
2. Open-at-first-paint content renders on the server. Foundation has no CSS rule that shows open `.accordion-content` (its JavaScript wrote inline `display`), so `nfsAccordionContent` binds the shown state itself (documented custom CSS keyed on the item's `.is-active`), and panel content is projected, not placed in Aria's `ng-template` content directives: Aria's `DeferredContent` creates views in `afterRenderEffect`, so an open Aria panel or selected Aria tab panel is empty in server HTML. Lazy content stays available as an opt-in `ng-template` input for consumers who accept client-only panel content, and the spec says so (`R:rendering` 5). The Accordion's opt-in renders an open lazy panel on the server through its own template and keeps it through the close transition (Accordion D12); the Tabs opt-in is Aria's `TabContent`, client-only (Tabs D19).
3. Nothing before hydration outside templates: no node creation, moves, `innerHTML`, or `Renderer2` writes at construction; no `window`, `matchMedia`, `getBoundingClientRect`, `focus()`, `scrollIntoView()`, observers, `history`, or `location` outside `afterNextRender`/`afterRenderEffect`. These render callbacks are the library's only platform check; `isPlatformBrowser` and `ngServerMode` are not used. Structure Foundation injected is template-owned or consumer-written (1.1). The Tooltip tip is created on first show, which is always a client event.
4. Timers (Orbit autoplay, hover-intent delays, animation fallback timers) start only inside render callbacks or handlers, never during server render, and on the client outside the Angular zone so a zone-based consumer still reaches stability and replays queued clicks promptly (`R:rendering` 1 Stability).
5. Event replay readiness: primary activation is a `click` or `keydown` listener in `host` metadata of the element the user interacts with. State a replayed handler needs exists at construction or in the first `afterNextRender` (both run before replay). Handlers change state first and call `preventDefault()` last. Hover and focus opening (Dropdown `hover`, DropdownMenu hover, Tooltip) uses non-replayed `pointerenter`/`pointerleave`, and replayed `focusin` handlers re-check live focus before opening. Document-level handlers (Light dismiss, outside click, global Escape) do not replay, which is correct: nothing is open before hydration. The exceptions, a Dropdown pane and a non-modal Reveal open at first paint, cannot be dismissed that way until hydration. Replayed swipes and `pointermove` drags are stale and ignored. A directive on `<a>` elements whose navigation must stay native declares no host `click` listener (SmoothScroll is the recorded exception: its purpose is to replace the native jump; see [ADR 0017](adr/0017-smooth-scroll-click-handling.md), and its container placement keeps `jsaction` off the links): Angular's dispatcher calls `preventDefault()` on anchor clicks carrying `jsaction` inside dehydrated blocks. A link that is itself a root node of a `hydrate on interaction` block is cancelled the same way, because the trigger annotates root nodes with `click`; specs tell consumers to wrap such links. How a handler recognises a replayed event without importing an internal constant is decided under the triage rule: it does not need to; every handler changes state first and calls `preventDefault()` last, accepting the error Angular logs on replay (Part 4, Decided item 3).
6. Hydration boundaries: a composite widget's container and items, and a Trigger and its Openable, belong inside one hydration boundary. Aria and this library register children when they are constructed, so a parent whose items sit in a dehydrated block has no items. Every spec documents that a consumer `@defer` wraps the whole widget, never part of it. Magellan's sections are the exception: they are observed from the DOM, not registered, so they may sit in any hydration boundary ([ADR 0029](adr/0029-magellan-targets-from-links.md)).
7. `@defer`: library templates contain no `@defer` (the library has no heavy dependencies to split and cannot choose hydrate triggers for consumers). Each plugin is a standalone secondary entry point so a consumer can defer per plugin. Inside a dehydrated block a directive is its server HTML: Foundation CSS and native elements must carry the closed state, and an interaction on an element with a replayable listener hydrates the block and replays the event. Inside `hydrate never` a widget works only as far as its server HTML and native elements do; each spec states that residue (Sticky, Slider, SmoothScroll, Button keep working; native links such as Magellan's, `<picture>` for Interchange, natural heights for Equalizer keep working too; Orbit keeps native scroll-snap scrolling with every slide reachable and usable; Abide forms do not go in `hydrate never` (Signal Forms never runs and the `ready`-bound submit stays disabled), a JavaScript-free form is a plain `method="post"` form whose native constraint attributes validate; everything else works only as far as its server HTML and native elements do).
8. Breakpoint-gated behaviour renders `serverBreakpoint` (1.7) because CDK `MediaMatcher` answers `false` to every query on the server; the Breakpoint service defines its own server answer. A client on another breakpoint re-renders or re-classes at hydration, and the spec states which (a class change committed in the Nested menu root's swap callback for ResponsiveMenu, an `@if` branch swap in the component's first render callback for ResponsiveAccordionTabs; both start every instance from the Server breakpoint's mode, so their blocks hydrate as sent). A breakpoint-gated hidden or inert state is expressed in CSS keyed on the Breakpoint map, never as a server-bound `hidden` or `inert`, whenever Foundation's CSS shows the element at a larger breakpoint (ResponsiveToggle's menu, OffCanvas `revealOn`/`inCanvasOn`). The CSS is Foundation's own first (`.hide-for-<bp>`, `.show-for-<bp>`, `.reveal-for-<bp>`, `.in-canvas-for-<bp>`); a custom rule, built with Foundation's `breakpoint()`, `show-for()`, or `hide-for()` mixins, is added only for what those classes cannot express, with its reason documented. Outputs and focus moves that follow such a re-render obey the rendered-state rule of 1.5.
9. Deep links (Accordion, Tabs, Reveal, Magellan) apply after hydration because the server never sees the fragment, and they require consumer-supplied ids (1.5). A consumer who needs server-correct initial state binds it from route data.
10. `animate.enter` has no hydration guard in 22.2 source and plays at hydration ([Prototype: `animate.enter` at hydration](issues/52-prototype-animate-enter-hydration.md)), so persistent elements (Reveal, OffCanvas, dropdown panes, Toggler targets, the ResponsiveToggle menu, the kept Tooltip tip) animate through State classes only (1.6 rule 1), which cannot replay at hydration because the State class value is the same on both platforms.
11. Prerendering is SSR at build time with `REQUEST` null; nothing in the library reads request tokens.

### 1.13 Sass and theming

In scope for every spec: the Foundation Sass mixins and partials the directive relies on (`foundation-accordion`, `foundation-reveal`, `foundation-range-input` and so on) and the library's documented custom CSS in the plugin's `nfs-<plugin>` Library mixin (reason per rule, AGENTS.md Styling Guidelines). Foundation Sass is a consumer-side dependency compiled from the consumer's settings; Sass boolean variables stay compile-time configuration, never inputs (AGENTS.md Design Philosophy 5).

Out of scope for the specs: runtime theming through CSS custom properties as a public contract. A directive may write a `--nfs-*` custom property when it has to pass a measured value to CSS (slider fill percentage); the drilldown wrapper's height is an inline style bound from a measurement, Foundation's own mechanism; that is an implementation channel documented in the spec, not a theming API. How the library's Sass ships next to the consumer's Foundation, and that `foundation-sites` is a required peer dependency at `^6.9.0`, is decided in [Sass packaging for the new library](issues/57-sass-packaging.md) and `adr/0012-sass-packaging.md`.

Variant properties, the Variant declaration file, and the runtime checks ([ADR 0040](adr/0040-variant-input-types.md)).
- Variant properties: each Library mixin of an entry point with an Open Variant family writes on `:root` one `--nfs-<setting>` property per Sass setting its classes loop over, listing the names that generate a class, space-separated, or the count (`--nfs-button-palette: primary secondary success warning alert;`, `--nfs-grid-columns: 12;`). Each property has one writer: an entry point whose Open Variant families loop over another entry point's settings reads that entry point's properties and writes none (Button Group reads `nfs-button`'s `--nfs-button-palette` and `--nfs-button-sizes`), because an empty property reads like a missing one, so a second writer would keep a property present while the first include is missing and hide it from `strictVariantProperties` ([Spec: Button Group](issues/82-spec-button-group.md), D11). A setting that no entry point owns is the exception: `nfs-callout` and `nfs-progress-bar` both loop over `$foundation-palette`, and an application may include either alone, so both write `--nfs-foundation-palette` with the same value. The legacy grids' shared settings are the second case: the Float Grid's and the Flex Grid's Library mixins both write `--nfs-grid-column-count` and `--nfs-block-grid-max`, because `$grid-column-count` and `$block-grid-max` belong to neither grid alone and an application compiles one of them ([Spec: Flex Grid](issues/101-spec-flex-grid.md), D12). Neither legacy grid's mixin writes a property of its own that it never leaves empty (the Float Grid's `--nfs-grid-column-gutter` is empty under a static `$grid-column-gutter`), so each reports its own missing mixin only while the other's is missing too, as the Progress Bar does ([Spec: Float Grid](issues/100-spec-float-grid.md), D12). A directive then decides its own mixin's absence from a property only that mixin writes where one exists (the Callout's `--nfs-callout-sizes`); `nfs-progress-bar` has none, so a missing `nfs-progress-bar` is reported only while `nfs-callout` is missing too ([Spec: Progress Bar](issues/95-spec-progress-bar.md), D14). A family that a Sass flag gates gets a Variant property of its own, written as the empty list (whitespace only) while the flag is off and read only by the runtime checks; two families that one flag gates in opposite directions share one property listing whichever of their names the compile generates, which is never empty while its mixin is included and may therefore be named in `include()`: `nfs-media-object` writes `--nfs-media-object-section` as `main-section` under `$global-flexbox: true` and `middle bottom` under `false` ([Spec: Media Object](issues/91-spec-media-object.md), D6); a flag that only chooses which of two opposite classes exists, where the absent class's look is already the default, needs none (the Table's `striped` and `unstriped` under `$table-is-striped`, [Spec: Table](issues/92-spec-table.md), D5). `nfs-breakpoint-properties` also writes `--nfs-breakpoint-classes`. An entry point with an Open Variant family therefore always has a Library mixin that writes its properties, its own or, for families over another entry point's settings, that entry point's (ADR 0012, dated note).
- The Variant declaration file: the library's tooling reads the Variant properties from a compile of the project's global stylesheet, writes the consumer's `src/nfs-variants.d.ts`, the file that augments the Variant registries, and compares it with the Sass by meaning. It is kept in step by an Nx task sync generator registered on each covered project's own targets, with `nx sync:check` as a required CI step, or on the Angular CLI by the Architect builder behind each project's `nfs-variants` target, whose `check` configuration runs in CI. A shared library whose own programs use names Foundation's defaults lack gets a file of its own. The [Spec: Variant declaration tooling](issues/136-spec-variant-declaration-tooling.md) fixes the commands, options, file format, Variant property format, and messages.
- The runtime checks: `strictVariantNames`, `strictVariantProperties`, and `strictBreakpointSync` read the same properties in the browser after the first render. They are on by default in development builds, where a consumer can opt one out, and off in production unless the consumer opts one in. Each property is read and each report made once per realm; library directives report through `nfsVariantCheck`, and a production bundle without `provideNfsProductionRuntimeChecks` carries none of the checker's code (measured under the application builder, [Re-run: Breakpoint service (shared utility) spec under the class rule](issues/129-rerun-breakpoint-service-class-rule.md)).

Like the Breakpoint properties, the Variant properties are a verification channel, not theming.

Every plugin spec's Further Notes carries a "Sass" subsection with this content (Button and the shared utilities included), per [Sass packaging for the new library](issues/57-sass-packaging.md):

> Sass. The consumer compiles Foundation's Sass from its own settings; the library imports no Foundation code and copies no Foundation rule. This plugin relies on Foundation's export mixins `<list, for example foundation-accordion>`. Its documented custom CSS is the `nfs-<plugin>` mixin of the library's Sass (`@import 'ngx-foundation-sites';` after Foundation), included after `<the Foundation export mixin>`. The subsection lists: (1) every rule the mixin emits, with its selector and the reason Foundation's CSS cannot provide it (AGENTS.md Styling Guidelines); where it adjusts a Foundation rule, only the declarations that differ; (2) the Foundation settings, mixins, and functions each rule reuses (`$reveal-overlay-background`, `breakpoint()`), read from the consumer's compile and never copied as literal values or parameter defaults; a mixin parameter exists only for a value Foundation has no setting for, and the spec names it; (3) any `--nfs-<plugin>-*` property the directive writes and the mixin reads (an implementation channel, not theming, `building-blocks.md` 1.13); (4) the Motion classes from `nfs-motion` it uses by default, and the `prefers-reduced-motion` override its mixin emits for each transition or animation it adds or awaits; (5) what visibly breaks when the include is missing; (6) the Variant properties its mixin writes, one per Sass setting its Variant classes loop over. A plugin with no custom CSS says "No library CSS; there is no `nfs-<plugin>` mixin" and still lists (4) when it uses Motion classes. No directive or component declares `styles` or `styleUrl`. Breakpoint-gated behaviour reads `nfsBreakpointsToken`, whose CSS mirror is `nfs-breakpoint-properties`, never a per-plugin copy of the Breakpoint map; a per-plugin media rule built with Foundation's `breakpoint()` is allowed under 1.11 decision 8.

Tabs has an `nfs-tabs` Library mixin with two Variant rules, a 24 by 24 px minimum for `simple` titles and the selected tab's colours on a `primary` bar, and compile-time contrast checks of every strip's text and selected look and of the `primary` bar's pairs, so every application with a tab strip includes it; its nav bar is a consumer recipe of Foundation's `tabs-container` and `tabs-title` mixins with no library rule ([Spec: Tabs](issues/16-spec-tabs.md)). The [Spec: Responsive Accordion Tabs](issues/19-spec-responsive-accordion-tabs.md) includes it for its tabs mode.

### 1.14 Spec shape

A `/to-spec` spec keeps the template's top-level sections in order: Problem Statement, Solution, User Stories, Implementation Decisions, Testing Decisions, Out of Scope, Further Notes. The foundation-api-design material goes in as subsections:

Implementation Decisions:
1. Foundation contract: features, options, events inventory (from the research file), and the dropped options list.
2. CSS class to directive mapping: one row per Structural class with the directive that binds it; one row per Variant class family with its Variant input, its type alias, the Sass setting and Variant registry it follows (or "closed"), its value shape (name, boolean, query, rules object, count), the class each value sets (with the Zero-breakpoint gaps), and the Variant property the runtime check reads; State classes as host bindings; no class left for the consumer to write (ADR 0039).
3. Hierarchy and DI shape (tokens, host directives, parent discovery, defaults token).
4. API per directive or component: inputs with Foundation defaults and deltas, models, outputs, methods, `exportAs`.
5. Material comparison table.
6. Implementation level and primitives, with the fallback.
7. ARIA and keyboard tables (APG pattern, roles, states, keys, focus rules).
8. Rendered HTML: consumer markup and the resulting DOM, closed and open, server and hydrated.
9. Animation: State classes, keyframes, completion, reduced motion.
10. Rendering modes: server output, pre-hydration rules, event replay readiness, behaviour inside `@defer` and hydrate blocks.

Testing Decisions: the four layers from 1.12 by name (story play function, browser-level test (Vitest browser mode, `nx test`), node-level Vitest including the SSR smoke, Playwright e2e), each with its story ids and cases.

Further Notes: usage examples, the design decisions table, platform features to adopt when the browser target moves, and the "behaviour that only jQuery makes easy" that was dropped.

## Part 3. Shared utilities that earn their own spec

Six, each written with the same shape as a plugin spec and consumed by the specs listed:

1. **Breakpoint service** (`NfsMediaQuery`, `nfsBreakpointsToken`, the rule-string parser). Consumers: ResponsiveMenu, ResponsiveToggle, ResponsiveAccordionTabs, Interchange, Equalizer, Sticky, OffCanvas, Tooltip, Orbit (reduced motion), plus `reducedMotion()` for JavaScript-driven motion (Orbit autoplay; SmoothScroll, and Magellan through the composed `NfsSmoothScroll`, which Magellan does not inject itself; the Accordion, Tabs, and Responsive Accordion Tabs deep-link scrolls; the Drilldown `scrollTop` scroll) and for the directives that bind no Motion class under reduced motion (Responsive Toggle, the Dropdown pane; 1.6 rule 5), as the Breakpoint service spec's consumer table lists them (corrected 2026-09-26 from audit 0005 L6).
